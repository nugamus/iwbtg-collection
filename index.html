Terms in this register
Placed instances
Every object instance placed in a room in the census. This is the denominator for built-in and script shares.
Built-in coverage
The share of placed instances whose behavior a documented engine built-in covers. This is a composition share, not a completion score.
Script-object instances
Placed instances whose behavior comes from a game-specific package script instead of a built-in. The script share is a share of all placed instances, not a progress score.
Recorded traces
Input and state recordings captured from the original. A count of evidence, not proof that behavior is tick-accurate.
Objects exercised
Distinct object names that appear in those traces. Exercised does not mean tick-accurate.
Custom object types
Distinct custom object types placed in the game, counted by the census from shortlist.md.
Client / kid
Placed client objects and kid instances that are neither covered by a built-in nor counted as script objects.
Trace cases passing
Committed trace cases whose status in crates/tools/fidelity-baseline.txt is OK, over the cases recorded in crates/tools/cases/<game>/. A case is one recorded scenario; a passing case is evidence, not proof that every object in it is tick-accurate.
Mapped objects
Objects resolved to a built-in behavior spec over objects in the converted package, from progress/exporter.json and the docs/games front-matter. The snapshot is generated in the research environment; its date is shown beside the bars.
Scripted objects
Objects the converted package writes as scripts over objects in the package. Mapped and scripted objects partition the package total.
Passing-trace coverage
The share of individual objects proven tick-accurate by a passing trace. Not measured yet; it needs the trace runner (#1365). This is different from the per-game trace cases passing bar.
Not measured yet
A value the repo cannot supply honestly. The page names the missing input and, where one exists, the follow-up issue; it never prints zero or an estimate.
Tick-accurate
The rebuilt object reproduces the original's behavior on every simulation tick, proven by a passing trace.
Port
Each game's port issue in the games repository, with the progress of its Done when checklist.
Phase gate
A milestone with entry and exit conditions. Delivery measures closed issues against the phase total and remaining size points, not a date.
Size points
A planning weight from issue labels: S=1, M=3, L=8. An unlabelled issue counts 0 points. This is not time or a deadline.
Process labels
agent-ready can start without a blocker; in-progress is claimed; needs-user waits on a decision; triage is unsorted; blocked cannot proceed; revisit is deferred.
