# The simulation: Collision

Part of [the simulation](../sim.md).

## Collision

Spec: `research/specs/engines/gm8/runner/collision.md` (claims `COL-NNN`; index `research/specs/INDEX.md`).

- **Masks.** Each sprite frame has a `Mask`: a bounding box in sprite space and an optional bitset (rows as `u64` words) for precise masks. `crates/format` builds masks from PNG alpha at load, using the sprite's `collision` mode (`precise`, `rect`, `none`) and `alpha_tolerance`. The sim receives finished bitmasks; image data never reaches it.
- **Bounding box in the room.** Computed exactly as GM8 does: position, origin, scale and bbox offsets, then banker's rounding. The kid's box in all 20 games is the rectangle [12, 11, 22, 31] with origin (17, 23) (`research/shortlist.md`).
- **What `bbox_*` reads** (`collide::bbox::bbox_read`, the trace probe's `bbox_*` columns). -100000 with no sprite and no mask, else the reported box (`reported_edges`), which also covers empty masks (COL-072, `research/specs/engines/gm8/runner/collision.md`, research#224): a sprite with no frames (as sprite or mask) reads a 1x1 mask at origin 0; maskNothing (2x2, bounds 1,0,1,0) reads its box normalized; any other inverted manual rectangle (sprite520, temp) reads its raw per-axis edges, left > right, at angle 0 and positive scale (the measured rows; no rule tells it from maskNothing, UNKNOWN); every other empty mask (rotated or mirrored inverted rectangle, fully transparent precise mask, no collision shape) is UNKNOWN (no box, an empty probe cell). `mask_sprite` gives GML `mask_index` for a mask: the first sprite in table order that owns it (the probe's `mask_index` column).
- **One box under `standard`** (decision 0005, D2; `CollideRules::reported_box`). The measured `bbox_*` rule above is the gm8 default (`ReportedBox::Measured`). On `standard` (`ReportedBox::Collider`) the reported box is the one authoritative collider's box, exactly as `instance_box` places it: the mirrored second box and every empty-mask special case disappear, and an instance with no collider has no reported box (`None`, so the probe cell is empty and a non-precise query skips it). Render bounds are separate presentation data (D2a `render_bounds`, absent = frame); the collision box is never the render box. No package selects `standard` until #1160, so every gm8 pin is unchanged.
- **Empty masks in collisions** (COL-073, `research/specs/engines/gm8/runner/collision.md` "Collisions with these boxes", research#230, #926). These masks have a reported box but no collision box (`instance_box` is `None`): place tests (`place_meeting`, `instance_place`, `place_free`) and collision events never see them, from either side. Non-precise `collision_point`, `collision_rectangle` and `collision_line` hit the reported box (an inverted box contains no point, so it is never hit); with `prec` on, and in `instance_position`, an instance without a collision mask is skipped instead of falling back to its box (`query.rs` `shape_hits`). `distance_to_object` measures the reported box, inverted edges included: per axis `other.left - self.right` if positive, else `self.left - other.right` if positive, else 0 (`axis_gap`; the two can both be positive only for an inverted box). The grid buckets an inverted box by its min and max edges. `tests/empty_mask.rs` checks every collision and bbox column of empty-mask-collide.csv (k0-k15).
- **Precise test.** Integer pixels in the intersection of two boxes, mapped back through each instance's scale. Rotated precise masks are rejected by the validator in format v0 unless the engine spec defines the rule (**OPEN**; the pixel mapping is COL-058, `research/specs/engines/gm8/runner/collision.md`).
- **Broadphase.** One uniform grid per room, 64 px cells (sparse, so instances outside the room need no separate list), each cell holding instance ids. It starts unbuilt on room entry and after a savestate restore (queries then test every instance) and is built at the first turn of the next collision phase that has one (`World::ensure_grid`). An instance one of whose boxes cannot be computed goes in the overflow set every query tests, so its error surfaces where brute force raises it. A flush re-buckets a moved instance only when its cell range changed. Position and image setters live on `Motion` and `Image`, which cannot reach the grid, so `World::get_mut` (the only way to change an instance) marks the instance as moved; every query also tests all moved instances, and `World::flush_grid` re-buckets them between handlers or phases. A stale bucket costs a test, never a missed instance (`collide/grid.rs`).
- **Order never depends on the grid.** Query results are sorted by (rank, id) before use.
- **Collision phase pairs through the grid** (#781, `collide/pairs.rs`). Under the one pair order (R12) with the engine's overlap test (`Hooks::broadphase`), an outer instance's inner list is not a scan of every instance: its candidates are the grid cells under its collision box plus the moved and overflow sets, filtered by rank and classes and sorted by (rank, id). Membership and order use each instance's rank, classes, handlers and alive-and-active as of the turn start (`Members`, updated from the moved set before each turn's flush); after each overlapping pair the grid is asked again from the outer instance's current box, continuing after the last inner instance reached, so handlers that move either side or a third instance change nothing. Two shortcuts keep that walk cheap without changing its pairs (#1139): a turn is skipped when no kind at or above its rank can meet it (a static check over the kinds that have a rank, `collide::pairs::Reach`), and the grid is asked again only when a handler marked something moved (or spawned, which marks too). A death's 800 stuck `blood` drops all share one grid cell and their turns can meet no kind at all; with both shortcuts the plateau at 897 instances costs about 1 ms per tick instead of about 20 ms, and `blood::stick` skips a write of the values a resting drop already has so that it does not mark the grid moved. Same pairs, same order, same errors as the scan; `tests/pairs.rs` compares both on generated worlds (handler log and state hash per tick) and times them (`-- --ignored`: 5,000 instances, about 69 ms per tick scanning, 12 ms gathering). This is the only pair order (decision 0005); only a non-engine overlap test (`broadphase: false`) scans instead of gathering.
- **Queries.** `place_meeting`, `place_free`, `collision_point`, `collision_rect`, `collision_line`, `instance_place` and `move_contact_solid` follow GM8 semantics (1 px steps, step limits) per the engine spec (`research/specs/engines/gm8/runner/collision.md`: COL-028..COL-035, COL-086). A query names its targets with `collide::Target`: a class, one kind, a kind with the kinds the loader derived from it (`KindTree`, `GameDef::kind_covers`, what a script's kind name means), one instance or all. Scripts call the same functions (`script/collide.rs`, #777), so a script and a built-in see the same masks, 1 px rules, first instance (R21) and destroyed-this-step instances (R22, never seen).
- **Bounce** (`collide/bounce.rs`, C14, #835). `move_bounce_solid` and `move_bounce_all` (the Bounce action; `place_free` or `place_empty` as "blocked") change only `hspeed` and `vspeed`: the tick's motion then moves by the new speed, so a bounce never moves to contact. The two rules are pure functions over a "blocked here" closure (`plain_bounce`, `precise_direction`), which `tests/bounce.rs` checks row by row against the recorder tables. A precise bounce writes the new `direction` through `Motion::set_direction` (speed kept), so `hspeed` and `vspeed` come from the one polar-to-cartesian conversion with its integer snap (research#193, #855; [numbers](numbers.md), Motion coupling). `tests/bounce.rs` checks those bits on every precise row and the `h0`/`v0` of every probe, except one ulp at directions 45 and 220 (the M6 libm gap).
- **Scale.** 1,288 water tiles in one room (Fairy tale) and 28,900 instances over 116 rooms (qoqoqo) are well within this design. A benchmark covers both.
- **OPEN:** spike masks (precise triangle or bounding box) per engine (COL-059).

## Collision reference

The live text of plan section 3.4's types and rules not already covered above (this page is the authority; the [sim core plan](../../plans/sim-core.md) keeps the same text as history).

**Masks** (built by `crates/format`, consumed here):

```rust
// def/sprite.rs
pub struct SpriteDef { pub frames: u16, pub size: (u32, u32), pub origin: (i32, i32), pub masks: MaskSet }
pub enum MaskSet { Shared(MaskId), PerFrame(Vec<MaskId>) }   // "separate collision masks" (Confirmed)
pub struct Mask { pub bbox: IRect /* sprite space, inclusive */, pub shape: MaskShape }
pub enum MaskShape { Rect, Bits(BitMask) /* rows of u64 words, bbox-relative */, Empty }
```

- Pixel in mask: alpha compared to tolerance, `>` by default (C5, UNKNOWN; one const in `format::masks`). Only pixels inside the bbox count; a manual bbox is shared by all frames (Confirmed). Disk and diamond are rasterized into `Bits` inside the bbox (Inferred). `left > right` boxes (sprBow) give `Empty` (Inferred).
- Which frame's mask: `floor(image_index) mod frames` at the time of the check (Inferred, C6). Where the animation update sits (R7) changes which frame a cherry uses during Collision.

**Placement and bbox** (all in `collide/bbox.rs`, the only place that rounds):

```rust
pub fn place_origin(v: Real, rules: &CollideRules) -> i64;               // banker's round (Inferred), C2
pub fn instance_box(def: &GameDef, inst: &Instance, at: (Real, Real), rules: &CollideRules) -> Result<Option<PlacedMask<'_>>, SimError>;
pub struct PlacedMask<'a> { pub bbox: IRect /* room space, inclusive, i64 */, pub mask: &'a Mask, pub xf: Xform }
```

- Unit scale, angle 0: `bbox_left = round(x) + (mask.left - origin.x)` and so on (Inferred). The kid gives `round(x)-5 .. round(x)+5`, `round(y)-12 .. round(y)+8`.
- Scale, mirror and rotation: `collide::xform::map_box` and `map_pixel` (C3, C4 UNKNOWN). Default: offsets relative to the origin are mirrored `d -> -d` and rotated by multiples of 90 degrees exactly; fractional scale (mini spikes 0.5) scales offsets and floors; other angles return `SimError::Unsupported` in engine_rev 0, so a package that needs them waits for MASK-ROTATE traces or routes the object to a script. Kaenbyou and eat-the-lemon need the 90/180/270 case for every engine spike (`kaenbyou/famb-spike-mask-*` recorded).
- Place tests round the tested coordinate (`round(y + 1)`), not `round(y) + 1` (Inferred "Standing heights"; C2 switch `PlaceRound::TestedCoord | RoundThenAdd`).

**Overlap**: inclusive boxes, then a pixel test over the intersection when either shape is `Bits` (Inferred). `collide/overlap.rs`.

**Queries** (`collide/query.rs`), each excluding `me`, skipping inactive instances, skipping dead ones unless `TickRules::dead_in_queries` (R22), and returning `World::first_of` order (R21):

```rust
pub enum Target { Class(ClassMask), Kind(KindId), Inst(InstId), Any }
pub fn place_free(ctx: &Ctx, me: InstId, x: Real, y: Real) -> Result<bool, SimError>;   // solids only (Confirmed)
pub fn place_empty(ctx: &Ctx, me: InstId, x: Real, y: Real) -> Result<bool, SimError>;
pub fn place_meeting(ctx: &Ctx, me: InstId, x: Real, y: Real, t: Target) -> Result<bool, SimError>;
pub fn instance_place(ctx: &Ctx, me: InstId, x: Real, y: Real, t: Target) -> Result<Option<InstId>, SimError>;
pub fn instance_position(ctx: &Ctx, x: Real, y: Real, t: Target) -> Result<Option<InstId>, SimError>;
pub fn collision_point(ctx: &Ctx, x: Real, y: Real, t: Target, prec: bool, notme: Option<InstId>) -> Result<Option<InstId>, SimError>;
pub fn collision_rectangle(ctx: &Ctx, x1: Real, y1: Real, x2: Real, y2: Real, t: Target, prec: bool, notme: Option<InstId>) -> Result<Option<InstId>, SimError>;
pub fn collision_line(ctx: &Ctx, x1: Real, y1: Real, x2: Real, y2: Real, t: Target, prec: bool, notme: Option<InstId>) -> Result<Option<InstId>, SimError>;
pub fn distance_to_object(ctx: &Ctx, me: InstId, t: Target) -> Result<Option<Real>, SimError>;          // C13
pub fn move_contact_solid(ctx: &mut Ctx, me: InstId, dir: Real, maxdist: Real) -> Result<(), SimError>;   // C10, C11
pub fn resolve_contact_move(ctx: &mut Ctx, me: InstId, dir: Real, maxdist: Real) -> Result<ContactMove, SimError>; // D3 seam
pub fn move_outside_solid(ctx: &mut Ctx, me: InstId, dir: Real, maxdist: Real) -> Result<(), SimError>;
pub fn move_bounce_solid(ctx: &mut Ctx, me: InstId, precise: bool) -> Result<(), SimError>; // C14 (collide::bounce, #835)
pub fn solid_resolve(ctx: &mut Ctx, a: InstId, b: InstId, run: impl FnOnce(&mut Ctx) -> Flow) -> Result<Flow, SimError>;
```

- `move_contact_solid` (Inferred): unit step `(dcos d, -dsin d)`; repeat up to `maxdist` times (no limit when negative): if one step further hits a solid, stop, else step. Fractional `maxdist` and `maxdist == 0` are C11 (`collide::contact::mcs_step_limit`). Start already overlapping: the manual says do not move, OpenGMK docs say the start is not checked (C10, `CollideRules::mcs_start = ManualNoMove` default; `little-runner/t-col-07-*` recorded). Non-axis directions (kaenbyou playerSlope) use the same loop; their sub-pixel result is UNKNOWN. A negative `maxdist` loop is bounded by the room size plus the mask size (Design), then `SimError::Unsupported`.
- **Contact resolver seam** (`resolve_contact_move`, D3 #1183). The same position loop as `move_contact_solid`, behind a result type: the resolved position, why it stopped (`Contact`, `Limit`, `OverlappingStart`) and, for a contact, the axis-aligned face opposite the step. No production caller uses it yet; it is the seam the movement actions move onto for D3/D4. It shares the loop with `move_contact_solid`, so positions and errors are identical; `tests/query.rs` asserts that on contact, limit, zero/negative `maxdist` and non-solid cases.
- `distance_to_object`: Confirmed (recorder): `distance_to_object` = sqrt(dx*dx + dy*dy) where dx and dy are the edge gaps of the rounded reported bboxes (dx = other.left - self.right if > 0, else self.left - other.right if > 0, else 0); touching boxes give 1 because the edges are inclusive (`traces/deride-kotaro-from-aslant/trick-vine-kick-and-djump-d.csv` rows 108-110 give sqrt(5), sqrt(26), sqrt(65); `traces/showdown/a3-t16-c.csv` row 13; `bug-right-vine-miss-f.csv`). The switches stay, with these defaults. `kid/B.md` and `kid/A3.md` note that diagonal or sub-pixel positions give fractional distances, which integer boxes cannot. So C13 has two switches: `DistBoxes::RoundedInclusive | Unrounded` (boxes from C1 rounding, or from unrounded `x + offset`) and `DistOffset::None | PlusOne`. The x and y gaps are combined as `sqrt(dx*dx + dy*dy)` (Confirmed; alternative `Max`). Defaults: the reported boxes (`DistBoxes::Reported`, each edge rounded; a left-facing kid's mirrored box x-7 is the box used), `PlusOne` and `Euclid`. Evidence also in T-COL-10 and the recorded `deride-kotaro-from-aslant/bug-right-vine-miss-*`, `animus/a-vine-right-*`, `kaenbyou/famb-vines-*`. `None` when no instance exists (A3 U4: what GM returns is UNKNOWN; callers treat `None` as a large value).
- `collision_rectangle/line` corner inclusivity and fractional corners: C12, one function each.
- **Broadphase** (Design): uniform 64 px grid per room. All cell math in `i64` with `i64::try_from` and checked arithmetic; a value that does not fit is `SimError`, never an `as usize` cast (wasm32 has a 32-bit `usize`). Static instances are bucketed at room start, moving ones re-bucketed when their box changes, out-of-room instances go in an overflow list. Results are re-sorted by `first_of` order before use, so the grid never changes outcomes. A grid-equals-brute-force test runs on every CI target including wasm32. Rooms up to 16800 x 8512 and 12,805 instances per game fit.
