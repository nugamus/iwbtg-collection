# The simulation: Collision

Part of [the simulation](../sim.md).

## Collision

- **Masks.** Each sprite frame has a `Mask`: a bounding box in sprite space and an optional bitset (rows as `u64` words) for precise masks. `crates/format` builds masks from PNG alpha at load, using the sprite's `collision` mode (`precise`, `rect`, `none`) and `alpha_tolerance`. The sim receives finished bitmasks; image data never reaches it.
- **Bounding box in the room.** Computed exactly as GM8 does: position, origin, scale and bbox offsets, then banker's rounding. The kid's box in all 20 games is the rectangle [12, 11, 22, 31] with origin (17, 23) (`research/shortlist.md`).
- **What `bbox_*` reads** (`collide::bbox::bbox_read`, the trace probe's `bbox_*` columns). -100000 with no sprite and no mask, else the reported box (`reported_edges`), which also covers empty masks (CLONE_SPEC collision, research#224): a sprite with no frames (as sprite or mask) reads a 1x1 mask at origin 0; maskNothing (2x2, bounds 1,0,1,0) reads its box normalized; any other inverted manual rectangle (sprite520, temp) reads its raw per-axis edges, left > right, at angle 0 and positive scale (the measured rows; no rule tells it from maskNothing, UNKNOWN); every other empty mask (rotated or mirrored inverted rectangle, fully transparent precise mask, no collision shape) is UNKNOWN (no box, an empty probe cell). `mask_sprite` gives GML `mask_index` for a mask: the first sprite in table order that owns it (the probe's `mask_index` column).
- **Empty masks in collisions** (CLONE_SPEC collision, "Collisions with these boxes", research#230, #926). These masks have a reported box but no collision box (`instance_box` is `None`): place tests (`place_meeting`, `instance_place`, `place_free`) and collision events never see them, from either side. Non-precise `collision_point`, `collision_rectangle` and `collision_line` hit the reported box (an inverted box contains no point, so it is never hit); with `prec` on, and in `instance_position`, an instance without a collision mask is skipped instead of falling back to its box (`query.rs` `shape_hits`). `distance_to_object` measures the reported box, inverted edges included: per axis `other.left - self.right` if positive, else `self.left - other.right` if positive, else 0 (`axis_gap`; the two can both be positive only for an inverted box). The grid buckets an inverted box by its min and max edges. `tests/wp3_empty_mask.rs` checks every collision and bbox column of empty-mask-collide.csv (k0-k15).
- **Precise test.** Integer pixels in the intersection of two boxes, mapped back through each instance's scale. Rotated precise masks are rejected by the validator in format v0 unless a CLONE_SPEC defines the rule (**OPEN**).
- **Broadphase.** One uniform grid per room, 64 px cells, each cell holding instance ids, built at room entry. Anything outside the room bounds goes in a separate list. Position and image setters live on `Motion` and `Image`, which cannot reach the grid, so `World::get_mut` (the only way to change an instance) marks the instance as moved; every query also tests all moved instances, and `World::flush_grid` re-buckets them between handlers or phases. A stale bucket costs a test, never a missed instance (`collide/grid.rs`).
- **Order never depends on the grid.** Query results are sorted by (rank, id) before use.
- **Queries.** `place_meeting`, `place_free`, `collision_point`, `collision_rect`, `collision_line`, `instance_place` and `move_contact_solid` follow GM8 semantics (1 px steps, step limits) per the CLONE_SPEC.
- **Bounce** (`collide/bounce.rs`, C14, #835). `move_bounce_solid` and `move_bounce_all` (the Bounce action; `place_free` or `place_empty` as "blocked") change only `hspeed` and `vspeed`: the tick's motion then moves by the new speed, so a bounce never moves to contact. The two rules are pure functions over a "blocked here" closure (`plain_bounce`, `precise_direction`), which `tests/bounce.rs` checks row by row against the recorder tables. A precise bounce writes the new `direction` through `Motion::set_direction` (speed kept), so `hspeed` and `vspeed` come from the one polar-to-cartesian conversion with its integer snap (research#193, #855; [numbers](numbers.md), Motion coupling). `tests/bounce.rs` checks those bits on every precise row and the `h0`/`v0` of every probe, except one ulp at directions 45 and 220 (the M6 libm gap).
- **Scale.** 1,288 water tiles in one room (Fairy tale) and 28,900 instances over 116 rooms (qoqoqo) are well within this design. A benchmark covers both.
- **OPEN:** spike masks (precise triangle or bounding box) per engine.
