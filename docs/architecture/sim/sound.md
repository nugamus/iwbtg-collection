# The simulation: Sound model

Part of [the simulation](../sim.md).

## Sound model

Spec: `research/specs/engines/gm8/runner/sound.md` (claims `SND-NNN`; index `research/specs/INDEX.md`). This is the live text of section 7 of [the sim core plan](../../plans/sim-core.md), which stays only as history; this page is the authority.

Audio output is the client's job, but whether a sound **is playing** is sim state. 15 of the 20 games call `sound_isplaying` (SND-083, Confirmed), and its result can change game state, not only audio: machinary's playMusic2 sets an instance flag from it, and Step-based music objects call `sound_stop_all` when it returns false (Inferred). The DLL getters matter too: the GMFMODSimple getters give the start value, and so the lifetime, of the fader objects in go-the-spook-house and keep-celebrating-for-xia, and the SuperSound volume getter gives the start of kaenbyou's and eat-the-lemon's death fade. So `sim::sound` keeps a model:

- Playing copies start at the call's tick and end after the sound's `length_ticks` (song length times tick rate, from the package). A sound whose package gives no length (`length_ticks` 0, unknown; CR9) plays until it is stopped (`sound_stop`, `sound_stop_all`, or the end of the run), the same rule as the DLL adapters (#1173; feel contract `sound/unknown_length_plays_until_stopped`). At most one MULTIMEDIA copy. `sound_isplaying` latency and the second MULTIMEDIA start are UNKNOWN switches in `SoundRules` (S1-S3); game_restart keeps sounds (Inferred, S4).
- The run has one named sound model, `SoundRules::model`: `event` for the `standard` ruleset (no DLL adapters: the built-in copies and the event stream only), and a gm8 value naming the adapter a port uses (`supersound` or `gmfmod`, or `stub` for the recorder's `--stub-dlls`). A format-0 package has no profile field yet, so the compatibility default (`gm8`) models both adapters, exactly as before the profiles. `SimOptions::dll_mode = Stub` is the build-level `--stub-dlls` override: it forces `stub` for a trace regardless of the profile. The built-in copy model and the client event stream run in every model.
- SuperSound (kaenbyou, eat-the-lemon) and GMFMODSimple (go-the-spook-house, xia) are adapters whose getters return the last value set (S5).
- The `mute` action flips the game's music flag through the world built-in; music objects then call `stop_all`, which is sim state.
- Built-in copies play the ticks `start .. start + length_ticks` (looping, or length 0: until stopped). One helper, `sound::active`, decides this for built-in copies, SuperSound sounds and FMOD instances. `sound::is_playing` computes that itself; tick row 16 (`sound::tick`) only drops ended copies, SuperSound sounds and FMOD instances. S1 (latency) delays only a start; S2 and S3 govern a second MULTIMEDIA start; S4 (`keep_on_restart`) is read by `game_restart`. The built-in model runs in every sound model, including `stub`: the recorder stubs only the DLLs.
- DLL adapters (`sound::{supersound, gmfmod, cleanmem}`) are called by the script host with the arguments of the GML `external_call`. SuperSound returns strings (`"1"`, `"0"`, `"-1"` for is-playing); FMOD returns numbers (0 is an error); an adapter the run's model does not provide (or a `stub` model) returns `""` or 0 and changes nothing. The `death_sound` built-in stands in for kaenbyou's SuperSound death code, so it follows the same rule: when the run does not model SuperSound its start volume is 0, the absent getter's answer (audio-supersound-deathfade-a). The DLLs do not know a sound length, so the host passes `length_ticks` at load (0 = unknown, plays until stopped). OPEN: where the package supplies those lengths (follow-up).
- The state is hashed. The client receives one `SoundOutput` event stream. Every event carries the sim tick of its call; `Play` and `Load` also carry the sound's `length_ticks`, so the client mixer owns latency, fades and output without reading the package's sound table. A fade is a schedule of `Volume` events at their ticks (the sim keeps the per-tick death-fade schedule for trace/probe exactness; the client may interpolate). Nothing is read back from audio.
