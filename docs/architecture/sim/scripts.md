# The simulation: Scripts and the script API

Part of [the simulation](../sim.md).

## Scripts

Scripts are Rhai under the IWS profile ([0001](../../decisions/0001-script-language.md)). The sim talks to them only through the `ScriptHost` trait, so the sim core never names Rhai types. This is the live text of section 11 of [the sim core plan](../../plans/sim-core.md), which stays only as history; this page is the authority.

- **Rhai profile and pin.** Features `std`, `only_i64`, `no_time`, `no_module`, `no_custom_syntax`, `no_closure`, `compact_str` and `internals` on `=1.27.0` (pinned by #90; 1.27.0 was 14 days old on 2026-11-04). The root `Cargo.toml` carries the pin. `Engine::new_raw()` starts with only our packages; `eval`, `**` and `**=` are disabled.
- **Both operands always evaluated** (Confirmed for `&&`, `||`, `^^`). Rhai short-circuits `&&`/`||`, so the validator rejects any call that can draw from the RNG or change state inside a right operand and suggests Rhai's non-short-circuit `&`/`|` on bools, or evaluating first into a variable.
- **Conditions and repeats on reals.** Ported `if` and `repeat` code calls `gm_bool(x)` and `gm_repeat_count(x)` (rounded, Confirmed), which read `NumRules`. Comparisons of reals go through `gm_eq`..`gm_ge`, as 0001 requires. A single `=` inside a GML expression is a comparison (Inferred); Rhai treats it as a parse error, so porters write `gm_eq`.
- A scripted object's events run in the same pipeline slots as built-in events, in the same (rank, id) order.
- During a script call the world is lent to the Rhai host: `on_event` swaps a placeholder into `ctx.w` and parks the live world in the host (`RefCell<Option<World>>`). Each API function borrows it briefly; a function that needs a whole `Ctx` (spawn, destroy, kill) takes the world out, builds a `Ctx` and puts it back, so a spawned instance's Create can run its own script. The world is restored also on errors. Single thread, no `unsafe`, no `sync` feature.
- Built-ins call scripts only through defined events: `collide`, `trigger`, `animation_end`, timeline moments, and the `call` trigger action.
- The budget counter, caps and error handling are in [0001](../../decisions/0001-script-language.md#step-budget).
- **The engine (WP9.1, `script/host.rs`, `script/api.rs`, `script/budget.rs`).** `script::host::Iws::new(NumRules)` builds the IWS engine: `Engine::new_raw()` with the core, arithmetic, logic, string, array and map packages only, `eval`, `**` and `**=` disabled, the 0001 limits, strict variables, the simple optimizer and fast operators off. The numeric API is `num` under the run's `NumRules` (`gm_eq`..`gm_ge`, `gm_bool`, `gm_repeat`, `div`, `mod`, rounding, libm transcendentals, `random`, `irandom`, `random_range`, `irandom_range`, `choose`, `tick`, `room_tick`); `/` on two integers is a FLOAT. **Rhai's built-in float comparisons (1.26.1 and 1.27.0) use a relative epsilon**, which is neither IEEE nor GM8's rule, so the engine overrides `== != < <= > >=` with exact IEEE (a test pins `0.1 + 0.2 == 0.3` false and `gm_eq` true). The RNG and the tick counters are lent per tick (`begin_tick`, `end_tick`), so the scripts' draws are the sim's draws. The tick budget (`budget.rs`: 1,000,000 units, 200,000 per call) counts one unit per Rhai operation and ends a runaway call with a deterministic error.
- **The host (WP9.2, `script/host.rs`, `script/inst.rs`).** `ScriptRuntime::new(def, rules)` compiles every script (a compile error is a load-time `SimError::Script` with the file and position) and keeps the functions each defines. `script::on_event` (called by `events::dispatch` after the base built-in) maps the event to a function (`create`, `begin_step`, `step`, `end_step`, `late`, `alarm(n)`, `user(n)`, `collide(other)`, `trigger(name)` for a trigger kind's kid collision, `outside_room`, `intersect_boundary`, `animation_end`, `room_start`, `room_end`, `game_start`, `destroy`, `end_of_path`, and `moment_<name>()` for a timeline moment) and calls it with `this` bound to the instance; a function the script does not define is skipped. For `trigger(name)` the name is the trigger instance's room-file name (`PlacedInstance::name`, the field documented "for triggers and scripts"); an unnamed trigger has no name to pass and keeps the ordinary `collide` mapping, and a trigger kind that defines both gets `trigger` for that kid collision. `ScriptRuntime::event_set(id)` gives the events a script handles (the loader merges it into the kind's `EventSet`; collision classes stay the kind's business). The instance API is `Inst` handles (ids are never reused, so a stale handle is a script error, and `exists(h)` tells) with the built-in fields as properties, the package's custom variables through the same syntax (`this.hp`, mapped by `GameDef::var_names`; an unknown name is an error, and an unset one follows the run's `ScriptRules::init`), `set_alarm(n, steps)`, `get_alarm(n)`, `instance_create`, `destroy`, `exists`, `instances(kind)` (event order), `kid()`, `emit(name)` and `kill_kid()`. Scripts nest at most 8 deep. A script call may create at most 256 instances and all scripts 4,096 per tick (`budget::MAX_SPAWNS_PER_CALL`, `MAX_SPAWNS_PER_TICK`; a Create a spawn runs counts toward the spawning call); exceeding either halts the sim with a script error that names the cap, file, line and tick. No more than 50,000 instances are live at once (`world::store::MAX_LIVE_INSTANCES`, checked in `World::insert` for every spawn, script or built-in): the 50,001st halts the sim with `instance cap exceeded`. The tick loop calls `ScriptRuntime::begin_tick` at row 0 to reset the budget. An error becomes `SimError::Script` with `file: message (line, position) [kind, instance, event, tick]` and halts the sim.
- **Prepared scripts (#1021, #1093).** `script::PreparedScripts` compiles the package's scripts once (`PreparedScripts::new(&GameDef, &RunnerRules)`): the `AST`s and the kind-name map, shared behind `Rc` (the ASTs are not `Send` under the sim's no-`sync` Rhai profile). `ScriptRuntime::new_run(Arc<GameDef>, &RunnerRules, &PreparedScripts)` builds a fresh `Iws` and per-run `Shared` state (RNG, budget, log, parked world, nesting depth) for every run and reuses only the prepared data; `Host` holds `Arc<GameDef>`, so a run does not deep-clone the definition. `Sim::prepare`, `Sim::new_prepared` and `Sim::new_or_halted_prepared` are the retry path; `ScriptRuntime::new` and `Sim::new`/`new_or_halted` stay prepare-plus-run. A prepared artifact is refused for another package, and a prepared run hashes the same as an unprepared one. The client caching the artifact across `restart_run` is #1093B.
- **Array values (#984, #997; `script/array.rs`).** A custom variable or a global can hold an array (`Value::Array`, at most 10,000 elements, copied on assignment: the GML 8 rule). It survives events, hashing and `World`'s postcard encoding. A script writes one with a Rhai array literal (`this.pattern = [1.0, 2.0]`, `global.flags = [0.0, 0.0]`) and reads it as a `VarArray`, a copy of the stored elements with the GM index rules: `this.pattern[3]`, `global.flags[i]`. An index is a whole number from 0 (an INT or a whole FLOAT) below 10,000; a fractional or negative index is an `Unsupported` script error, because what GM8 does with one is OPEN (research `creation-code.md`, "Global arrays"; trace request NUM-ARRAY-IDX), and 10,000 or more is the array cap error. Writing past the end grows the array ("At the moment you use an index the array is generated"), the skipped elements unset; reading an element past the end or never set follows the run's `ScriptRules::init` (0 under `gm8` with uninitialized reads as 0, else a script error), as an unset variable does. Writing an element through a variable (`this.pattern[3] = 9.0`) changes the copy and Rhai writes it back through the variable's setter; `let a = this.pattern; a[0] = 1.0;` changes only `a`. A script reads the whole array through the bare name, so ported GML that reads a bare name meaning element 0 writes `[0]`; a bare write under `gm8` still writes element 0 (#1133, contract `script/global-array-bare-write`), and under `standard` it replaces the value. A `VarArray` supports indexing and `len` (`a.len()` or `len(a)`); Rhai's array methods (`push`, `for` loops) work on a literal, not on a stored array: loop over `0..len(a)`. Reading a variable or an element that holds an array charges one budget unit per element copied (nested ones included), and so does storing one (`budget::COSTS`, `index$get$`/`index$set$`). A stored array lives as long as its variable (#791): a global array and one on a persistent (Run-scope) instance are carried into the next room, one on an instance of a persistent room is back when the player returns, and `World`'s postcard encoding keeps it, so a decoded snapshot hashes the same; `script_conformance::arrays` pins each. The save file does not: a `save::Checkpoint` holds only its fixed fields, and script state that must outlive a quit goes through flags (#1384). Maps are not stored values: GM8 has no map variable and no converted game calls a `ds_*` function (research census, #172), so a Rhai map (`#{ a: 1.0 }`) lives only inside one call, and storing one in a variable is a script error that says to store an array or one variable per key. A trace probe records an array as one string cell holding its compact text form (`[1.0, [2.0], "x"]`), not an empty cell, so a change in its elements shows in a trace diff (#1055; [traces](../traces.md)).
- **Globals (#997).** `global` is a script variable bound to a handle for the run's globals (`World::globals`): `global.difficulty` reads, `global.flags = [0.0, 0.0]` writes. A name the package knows keeps its load-time id; a new name gets a run-time id on first write, the way room creation code's `set_global` makes one (`room::run_time_var`), as GML creates a global on assignment. A global never set follows `ScriptRules::init`. The compile scope holds `global` as a constant, so strict variables accept it inside functions, and the engine's variable resolver gives its value; a local `let global = ..` shadows it.
- **Script semantics (decision 0005, `def/script.rs`).** `ScriptRules { init, values }` is the pair the ruleset selects; it is a value, never a package switch. `InitPolicy::Zero | Error`: `gm8` derives it from `GameDef::uninit_reads_zero` (19 games read 0; keep-celebrating-for-xia halts), while `standard` always uses `Error`, so an unset read is a script error with the script file, line and column. `ValueModel::Gm8 | Typed`: `gm8` stores a bool as the real 1.0/0.0, as GML does; `standard` keeps real, string and bool distinct. The stored value model is still `Value::{Real, Str, Inst, None, Array}` (world instance state belongs to the entity-model slice, #1175), so until the typed value lands a `standard` write of a bool is refused with a clear error instead of being silently turned into a real. Conditions are bool expressions in both models: the validator rejects a value it can see is a number, and the engine rejects a stored real at run time (there is no GML truthiness). `ScriptRuntime::new` uses `ScriptRules::gm8(def.uninit_reads_zero)`, so every existing package keeps its model; `new_with_script_rules` selects another pair (tests, and the `standard` ruleset once #1160 parses it).
- **Saves are data (decision 0005).** The script host never reads or compiles save bytes. A save file and a replay's `FromSave` carry a versioned `save::Checkpoint` (stable room name, position, counters, ruleset/profile and save-point key) that the client or the replay tool decodes before the sim starts; a malformed or hostile payload is a data error, and no save field is ever a script source. The formats are in [client storage](../client/storage.md) and [replay](../replay.md); `tests/script_save.rs` pins that GML/script text is refused as data.
- **The validator (WP9.3, `script/validate.rs`).** `script::validate::validate(&GameDef)` checks every script without running it and returns `Issue { script, line, column, severity, message }`; the format loader turns them into diagnostics (`scripts/boss.rhai:2:9: error: ...`), so the client, the server and `iwbtg pkg check` refuse the same scripts. Errors: the script does not compile (strict variables, `eval` and `**` disabled); a top-level item that is not `fn` or `const`; an event function (`step`, `alarm`, `moment_<name>`, ...) with the wrong argument count; a call of a function that is neither registered nor defined in the file, or with a wrong argument count; a string literal passed to `instance_create` or `instances`, or compared with `.kind`, that names no kind (`NAME_ARGS` also resolves sounds and rooms when an API function takes them); a call that draws from the RNG, changes state or calls a script function that does, in a right operand of `&&` or `||` (Rhai short-circuits, GML evaluates both; the left operand always runs, so it is fine; use `&` or `|` on bools, or evaluate into a variable first); `switch` on float case values (read from the token stream, because Rhai hashes case values away); a real-valued property or number function used as a condition (`if this.hspeed`; a number literal is already a Rhai compile error). Warning: raw `==` or `!=` where an operand is a float literal or a real property (use `gm_eq`/`gm_ne`). The walk runs on the AST the engine compiles with the simple optimizer, so code the optimizer removes (an empty `if`, an unused `let` of a pure call) is not checked. The function classification lists (`RNG_FNS`, `STATE_FNS`, `NUMBER_FNS`, `OTHER_PURE_FNS`) and the property lists (`REAL_PROPS`, `BOOL_PROPS`, `STR_PROPS`) are pinned to the registry by tests: a new API function or property must be added to one of them.
- **API descriptions (#364, `script/docs.rs`).** Each registered function, operator and property has a one-line description added next to its registration with `docs.add(name, text)` (overloads share one). `iwbtg script api-docs` prints them into `docs/format/script-api.md` and fails when a registered name has none, so a new API function cannot land undocumented.

### Script API (first version)

This is the starting surface. The generated reference is `docs/format/script-api.md`, and the code is the authority; a name marked *planned* below is not registered yet, and a script that calls it fails validation. Every number the API returns is a FLOAT. Every function that takes a kind, sound, room or trigger name is checked at load when the name is a string literal.

**Event functions** a script file may define: `create()`, `begin_step()`, `step()`, `end_step()`, `alarm(n)`, `collide(other)`, `trigger(name)`, `outside_room()`, `animation_end()`, `room_start()`, `room_end()`, `destroy()`, `late()`, `moment_<name>()`, and the client-only `draw(d)`.

**`this` and other instances** (`Inst` handles):

- Read and write: `x`, `y`, `hspeed`, `vspeed`, `speed`, `direction`, `gravity`, `gravity_direction`, `friction`, `sprite`, `image_index`, `image_speed`, `image_xscale`, `image_yscale`, `image_angle`, `image_alpha`, `visible`, `solid`, `depth`.
- Read only: `xstart`, `ystart`, `xprevious`, `yprevious`, `kind`, `name` and `group` (the room-file strings, or `()` when the room file gives none), `id`.
- Custom variables: `this.hp = 20.0`, arrays too (`this.pattern[3]`; see Array values above). Unset reads follow the run's init policy.
- Parameters: the map given to `instance_create` sets them. Reading a parameter set in the room file or the object file from a script is *planned* (there is no `param` function).

**Instances**

**Collision** (`script/collide.rs`, #777): `place_meeting(i, x, y, target)`, `place_free(i, x, y)`, `instance_place(i, x, y, target)`, `collision_point(x, y, target)`, `collision_rect(x1, y1, x2, y2, target)` and `collision_line(x1, y1, x2, y2, target)`; the three shape tests also take `prec, notme` (GML's arguments; the defaults are precise and no instance skipped). Each calls the built-ins' query in `collide/query.rs`, so it sees the same masks and 1 px rules, returns a bool or the first `Inst` in (rank, id) order (R21) or `()`, and never sees an instance destroyed this step (R22). A target is a role (a named class: `"block"`, `"killer"`), `"all"`, a kind (with the kinds derived from it, as `instances(kind)`) or an instance handle; a role wins over a kind of the same name. A literal target is checked at load (`validate::NAME_ARGS`, `Names::Target`), also in method form (`this.place_meeting(x, y, "block")`). They are pure queries for the validator. `collision_line` costs one budget unit per pixel it samples.

**Kid**: `kid()` returns the kid's `Inst` handle, or `()` if there is no kid. `kill_kid()`. On a kid instance the decision-0004 fields are registered: read/write `djump`, `curJumps` (integer 0-255), `tjump`, `onPlatform`, `ladder`, `frozen`, `frozen2`, `muteki`, `tempHspeed`, `maxSpeed`, `maxVspeed`, `maxFallSpeed`, `scale`; read only `ladderud`, `ladderjump`, `yflag`, `flipped`, `facing`, `jump`, `jump2`, `jump3`, `on_slope_last`, `walk_h`, `onVineL`, `onVineR`. A write to a read-only field is a script error rather than a custom variable. `facing` follows `image_xscale`, the one facing setter; `yflag` and `flipped` are reached through the gravity knobs: a gravity-flip setter is *planned* (`set_kid_gravity(dir)`). Reading or writing any kid field on an instance that is not a kid is an error. Other knobs are added only with a CLONE_SPEC reason.

**Kid slots** (decision [0004](../../decisions/0004-extension-model.md#kid-script-slots)): a `physics.toml` profile may run a function of its `[script] file` at a fixed position in a kid event list (`{ do = "script", fn = "dash" }`), including a collision row, where it takes `other`. The host calls it with `this` bound to the kid, the same budget, caps, world-lending and error handling as an object's event function, and no closure state. The loader checks that the function exists with the slot's arity. A room request ends the rest of the list. The profile's `[script] vars` are interned into `GameDef::var_names` at load; an undeclared `this.<name>` remains an error. A new movement mechanic is such a slot, not a shared-code switch (extension tier 2).

**Rooms, triggers and timing**: `emit(name)`, `this.set_alarm(n, ticks)` (a method of the instance, so `other.set_alarm(...)` works too), `this.get_alarm(n)`, `tick()` and `room_tick()` are registered, and the room functions (#731): `room_goto(room)` (a room id; an unknown one halts the sim, and a literal is checked at load), `room_goto_next()`, `room_goto_previous()` (by room order; past either end the change at row 15 is a `SimError::Script`) and `room_restart()`. Each sets the world's one pending request (`Ctx::request_room`, last wins, R13); the rest of the script runs, then the tick stops as after a built-in's request (R8). The loader's reachability check reads them from the source (`script::validate::room_calls`), with the kind literals passed to `instance_create`, whose calls count in the creating kind's rooms (#751). *Planned*: `start_timeline(i, timeline)`, `stop_timeline(i)`, `room_speed()`.

**State**: `global.<name>` reads and writes a global, arrays included (see Globals above). *Planned*: `flag(name)`, `set_flag(name, v)` (flags go into the save slot).

**Input** (*planned*; for menus and quizzes): `pressed(action)`, `held(action)`, `released(action)`.

**Audio and effects** (queued for the client, never read back): `play_sound(name)`, `play_music(name)` (a loop; another track stops or blocks it by the run's MULTIMEDIA rule), `stop_music()` and `shake(ticks, strength)` are registered; sound names are checked at load, and a pack sound is `engine:<pack>/<id>`. *Planned*: `play_music(name, #{ from_tick: n })`.

**Menus and text** (*planned*): `text_box(...)`, `menu(...)`. Exact shape **OPEN**, from the quiz, battle menu and difficulty menu in the shortlist games.

**Random**: `random(x)`, `irandom(n)`, `random_range(a, b)`, `irandom_range(a, b)`, `choose([...])`. All draw from the sim's GM8 generator.

**Math** (all in `sim::num`): `sin`, `cos`, `tan`, `arctan2`, `dsin`, `dcos`, `darctan2`, `sqrt`, `pow`, `exp`, `ln`, `abs`, `sign`, `floor`, `ceil`, `round` (banker's), `frac`, `min`, `max`, `clamp`, `lerp`, `div`, `mod`, `point_direction`, `point_distance`, `lengthdir_x`, `lengthdir_y`, `gm_eq`, `gm_ne`, `gm_lt`, `gm_le`, `gm_gt`, `gm_ge`, `gm_bool`, plus `sqr`, `degtorad`, `radtodeg`, `to_float`, `to_int` and `gm_repeat`.

**Draw** (*planned*; client only, inside `draw(d)`): `d.sprite(...)`, `d.rect(...)`, `d.text(...)`, `d.bar(...)`. No setters on anything.
