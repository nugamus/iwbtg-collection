# The simulation: Random numbers

Part of [the simulation](../sim.md).

## Random numbers

- One gameplay generator in `sim::rng`, compatible with GM8's Delphi-style 32-bit LCG, so rooms that use `random()` can match the original's traces. Constants and the float derivation come from the CLONE_SPEC (OpenGMK uses multiplier 0x08088405, increment 1, step 2^-32; **OPEN** until confirmed).
- The seed is in the replay header. It is the only randomness in the sim.
- Each built-in documents how many random draws it consumes, so the stream stays aligned with the original.
- **Hidden consumers draw in the sim.** In the originals, blood picks its frame and gravity with `choose` and `random`, and playerface draws `irandom(3)`, from the gameplay generator (CLONE_SPEC numbers, Confirmed). So the blood emitter, blood and playerface built-ins make those draws in the sim, in the original's order (blood Create draws subimage then gravity inside `spawn`, then the emitter draws direction and speed), and send the drawn values to the client as output events. Only drawing stays in the client.
- Particle systems (N10, `NumRules::particles_draw_rng`). The runner draws from the gameplay generator for particles (CLONE_SPEC numbers, Confirmed (recorder), "Particle draw rules", research#158). `sim::particles` models those draws: once per tick after End Step and before Draw, systems in creation order, in each system the live particles' step and death particles first, then the emitters in creation order; a stream of n < 0 makes one chance draw (a particle when u < 1/(|n|+1)), n > 0 makes n particles; each emitter particle costs its region's draws (linear, gaussian and invgaussian rules, ellipse and diamond redraws, in unit coordinates) then its type's draws (`PartType::draws`). It keeps no positions or looks: those stay with the client. A death count has no cap, and a negative one is a chance per dying particle like a stream; a burst of n < 0 is a chance like a stream; a burst of a type that does not exist (an id not in `Particles::types`) costs the chance draw and the region's draws per would-be particle and makes nothing; `part_particles_clear`, `part_system_destroy`, `part_emitter_destroy_all` and `part_emitter_destroy` draw nothing and fire no death particles, the emitters keep streaming after a clear and live particles of a destroyed emitter stay and still fire theirs (Confirmed (recorder), "Particle draw rules" item 8, research#167; #769; tests `particles_rng::n10_2::*` replay the 23 NUM-PART-RNG-2 runs bit for bit from `tests/fixtures/rely_num_part_rng_2.csv`). Settings the spec does not cover (stream, burst or death count of 0, a step count below 1, a missing type outside a burst, a random life on a type with step or death particles, nested step or death particles) are `Unsupported`. The test `particles_rng::n10::rely_room1_seed_column_replays_bit_for_bit` replays rely room1's num-rng-a seed column (`tests/fixtures/rely_num_rng_a.csv`). The state lives in `World::particles` (hashed) and the tick runs `Particles::update` at row 11b, after End Step and before Draw, when the switch is on (#764; test `particles_rng::world::*`). A tick that a room request ends before End Step skips the update, and systems are kept across room changes; both are Confirmed (recorder), CLONE_SPEC "Particle draw rules" item 9 (test `wp4a_room::wp4a::wp4a_particle_systems_survive_room_changes_and_game_restart`); live particles do not age on the request tick either, as the whole update is skipped (Confirmed (recorder), item 9, research#181; asserted in `particles_rng::world::room_request_tick_skips_the_update`). Packages create systems through `particles/<id>.toml` files (`GameDef::particle_systems`, `def::PartSystemDef`) and the `particle_system` built-in, whose Create runs `Particles::build` (types in name order, the system, emitters with their streams, bursts, then `part_particles_create` calls) and whose `on_room_start`, `on_room_end` and `on_destroy` params clear, stop or destroy it without draws (#765; tests `particles_rng::particle_system::*`, `wp7b_loader::*particle*`). Each system it builds is noted with its file in `World::particle_defs`, so the client can draw a system whose instance is already gone; the sim never reads that table and it is not hashed (#866). Each `clear` call is counted per system in `World::particle_clears` the same way, so the client follows clears it cannot see in the state (#883). The loader refuses what the model refuses, so a run never stops on it. `blood_emitter` in `particles` mode builds its own system at Create (one type of 4 draws, a linear rectangle emitter streaming 15: 90 draws per update) and destroys it in Destroy and Room End (#766; test `particles_rng::blood_emitter::k1_seed_column_replays_bit_for_bit` replays kaenbyou's NUM-PART-RNG-3 run k1 from `tests/fixtures/kaenbyou_num_part_rng_3_k1.csv`). The engine_rev 0 default is `true` (#766): no package is verified yet, and the switch only changes packages with `particle_system` instances (none until the converter writes them, research#183) or a particles-mode `blood_emitter` (kaenbyou, whose only particles these are, and eat-the-lemon, whose other systems wait for research#183). The real runner is unchecked (research#164).
- Ranked runs use a random seed per run, as in the originals; the server flags reused seeds (user decision, 2026-11-02, [product](../../product.md)).
