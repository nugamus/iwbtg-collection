# The simulation: Random numbers

Part of [the simulation](../sim.md).

## Random numbers

- One gameplay generator in `sim::rng`, compatible with GM8's Delphi-style 32-bit LCG, so rooms that use `random()` can match the original's traces. Constants and the float derivation come from the CLONE_SPEC (OpenGMK uses multiplier 0x08088405, increment 1, step 2^-32; **OPEN** until confirmed).
- The seed is in the replay header. It is the only randomness in the sim.
- Each built-in documents how many random draws it consumes, so the stream stays aligned with the original.
- **Hidden consumers draw in the sim.** In the originals, blood picks its frame and gravity with `choose` and `random`, and playerface draws `irandom(3)`, from the gameplay generator (CLONE_SPEC numbers, Confirmed). So the blood emitter, blood and playerface built-ins make those draws in the sim, in the original's order (blood Create draws subimage then gravity inside `spawn`, then the emitter draws direction and speed), and send the drawn values to the client as output events. Only drawing stays in the client.
- Particle systems (N10, `NumRules::particles_draw_rng`). The runner draws from the gameplay generator for particles (CLONE_SPEC numbers, Confirmed (recorder), "Particle draw rules", research#158). `sim::particles` models those draws: once per tick after End Step and before Draw, systems in creation order, in each system the live particles' step and death particles first, then the emitters in creation order; a stream of n < 0 makes one chance draw (a particle when u < 1/(|n|+1)), n > 0 makes n particles; each emitter particle costs its region's draws (linear, gaussian and invgaussian rules, ellipse and diamond redraws, in unit coordinates) then its type's draws (`PartType::draws`). It keeps no positions or looks: those stay with the client. Settings the spec does not cover (stream or burst of 0 or less, a random life on a type with step or death particles, nested step or death particles) are `Unsupported`. The test `particles_rng::n10::rely_room1_seed_column_replays_bit_for_bit` replays rely room1's num-rng-a seed column (`tests/fixtures/rely_num_rng_a.csv`). The state lives in `World::particles` (hashed) and the tick runs `Particles::update` at row 11b, after End Step and before Draw, when the switch is on (#764; test `particles_rng::world::*`). A tick that a room request ends before End Step skips the update, and systems are kept across room changes; both are OPEN (research#170). No format kind or built-in creates systems yet, so the engine_rev 0 default stays `false` and `blood_emitter`'s particles mode is still `Unsupported` with the switch on (#765, #766). The real runner is unchecked (research#164).
- Ranked runs use a random seed per run, as in the originals; the server flags reused seeds (user decision, 2026-11-02, [product](../../product.md)).
