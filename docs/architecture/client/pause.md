# The client: Pause menu

Part of [the client](../client.md).

Pause menu (`pause.rs`, `pause/page.rs`, `PausePlugin`, #479, #624; docs/product.md, Pause; m5 `D13_PauseTimeAttack`, `D14_PauseClassic`, `D16_Pause43Pad`, `Pause.dc.html`): Escape (`pause::PAUSE_KEY`, read straight from Bevy) or Start on a controller (`pause::PAUSE_PAD`, #624) opens and closes it, except while the [loading card](loading.md) shows (there Escape leaves the run). Neither has a game action by default: the game's `menu` action has no keyboard or controller default (#758, #624; see the view page), so pausing sends the game nothing and never reaches a replay, whatever the frame timing (test `pause::tests::escape_sends_the_game_nothing_on_any_frame_timing`). Binding anything to them is refused (#761): a game action or client key on Escape or Start would both open the menu and press the action, and whether the tick before the menu opens saw the press would depend on frame timing (`collect_input` runs before the fixed clock, `pause::keys` in Update). `Bindings::from_config` (which `--bind` and `Config::set` run) fails with `key `Escape` is the pause key and cannot be bound to menu` (or `controller input `start` is the pause button ...`), so `--bind menu=Escape` is an error and nothing is saved (test `bindings::tests::the_pause_key_and_button_are_refused`).

The menu is the run screen `RunScreen::Paused` ([shell](shell.md), #839). `keys` (in `Playing` and `Paused`) asks for `Paused` on the pause key, or at `--pause-preview`'s tick, and every pick asks for `Playing` (`act`). `Menu` keeps the selection and the pauses, and `mouse`, `hold_audio`, `publish` and `draw` read whether it is open from the state. While it is open the sim does not tick (it ticks only in `Playing`), every playing voice is paused and resumed on close (a voice the game paused stays paused), the backdrop keeps running and the HUD steps aside (`publish` sets `hud::Suspended` while the menu is open, so the page owns `UiScale`). In Time Attack the timer keeps running; Classic stops game time (m5 D14), so `count` adds nothing in `PlayMode::Original`. In Time Attack: `count` runs on the fixed clock while the menu is open and counts each tick in which the map's timer runs (started, not ended, sim running), keyed by the sim tick the pause began at (`Menu::pauses`); `publish` writes the total to `hud::Paused`, which run info adds to `Sim::ranked_ticks` and uses for the paused line. A retry clears the pauses (`pause::reset`). The replay's trailer carries them (`replays::sync_pauses`; docs/architecture/replay.md, Trailer) and the stats add them to the clear and the splits (#623).

Drawing (`pause/page.rs`): one page laid out on the artboard, 1920x1080, or 1366x1024 below a 1.5 aspect (`page::Board::for_window`), centred and scaled to the window by `UiScale`; it is rebuilt only when the board, the device (keyboard or pad hints) or the mode changes; the selection, a hold and the timer change it in place (`pause::tests::moving_the_selection_respawns_nothing`). Over the game: black at 50% (the board's `brightness(.5)`; there is no blur of the game yet) and the board's left-to-right gradient. Left: `Paused` (Barlow Condensed italic 104), the status pill (Time Attack: red, `Timer running · 38:09.02` with a pulsing dot, kept live; Classic: violet, `Game time stopped`), then the mode's items (`Item::list`) as 70 px sheared rows: label, a line under it, the key that picks it. The selected row is `white(0.2)` with a 2 px ring and slides 20 px right (OutQuint, 150 ms, `motion::SELECT`), the delicious fruit beside it stepping between its two frames every 320 ms: the package's sprite `cherry` (its first two 21x24 frames; docs/format/assets.md), else the client's own (`assets/ui/cherry.png`, credited there; #1608). Right, the run card (`page::Card`, read when the menu opens): the game's title, the map (Time Attack; `Time Attack` without maps) or `Classic` with the CLASSIC pill, the mod pills; three numbers (Time Attack: run time, kept live, `still running`; your PB on this board or `No clear yet`; the run's deaths and the game's Time Attack deaths. Classic: this session's time, `game time stopped`; this session's deaths and the game's Classic deaths; the room you are in); this session's deaths by room (`stats::SessionLog::deaths_by_room`, the top four, bars against the most); and the game's controls with the player's first binding of each (Move, Jump, Shoot, Retry from save, and each labelled extra action in amber; pad glyphs when the pad opened the menu). The hint bar at the bottom: Choose, Continue, Retry from save and (Time Attack) Hold to restart. Not built yet: the route line (m5 E7, group 4), `vs PB here`, the game icon (group 5), and Practice this stage, each filed.

Items (`Item::list`): Time Attack: Continue, Retry from save, Restart run, Options, Quit to game select. Classic: Continue, Retry from save, Options, Back to the shelf.

- Continue.
- Retry from save: closes and presses the game's `restart` action for the next tick (what R does).
- Restart run (Time Attack): `retry::request`, the quick-retry key.
- Options: opens the Options view in place (below); the menu stays open.
- Quit to game select / Back to the shelf: leaves the run (`shell::leave`, [shell](shell.md)): back to the `--select` list, else the client closes. No results screen; the run's timer has not ended, so no clear reaches the stats. The replay is written as for any unfinished run, like a window close.

Hold: once the run is older than a minute (`HOLD_AFTER_SECONDS`, game time), Restart run and Quit are not picked by a press: the key, pad button or mouse button that picked them must stay down for 0.6 s (`HOLD_SECONDS`) while the row fills red from the left; letting go earlier picks nothing (`hold`, test `a_long_runs_destructive_items_need_a_hold`). A click is a release, so the mouse starts the hold on the press (`mouse`).

Keys: Up/Down and the keys bound to `up`/`down` move the selector; Enter, Space and the keys bound to `jump`/`accept` pick; R (the keys bound to `restart`) and the quick-retry key pick their items at once; Escape continues. The mouse selects on hover and picks on click (`Activate`), except a held item. Key edges collected while the menu was open are dropped when it closes, so nothing pressed in the menu reaches the game.

Controller: `keys` reads the collector's pad state (`Collector::pad_down`, so the active-pad rule and the stick gate apply as in play) and acts on the inputs that went down since the last frame (`pad_command`). Start and B (east) continue; A (south) picks the selected item; the D-pad and the left stick move the selector; then, as for keys, the inputs bound to quick-retry pick Restart run, `restart` (Y by default) picks Retry from save, `jump`/`accept` pick and `up`/`down` move. Fixed buttons win over bindings, so B continues even though `suicide` is bound to it. The choice of Start, with `menu` moved off it, is cheap to change (#624, `revisit`).

Options view (`pause/options.rs`, m5 D15, #1654): the title reads `Paused · Options` and the run card's place holds the options instead: `Options`, a note that only what is safe mid-run is here, and eight rows (`options::Opt`): Music, Sound effects and Master volume and Backdrop blur as 200 px sliders with their percentage; Show the HUD and Input display as switches; Key bindings for this game (`Open`) and Audio offset (`Change`, with the saved offset in ms) shown faded, as the bindings editor and the offset calibration stay in Settings from the menus for now. Both the view and the run card are built with the page and shown or hidden by `options::looks`, so opening the view respawns nothing (`pause::tests::options_opens_its_view_and_escape_goes_back`); the focused row gets `white(0.08)` and a 2 px ring that never moves the layout (`ui::focus`). Keys: Up/Down move between rows, Left/Right step a slider by 10 (clamped to 0 to 100) or flip a switch, Enter/Space flip a switch; Escape, Backspace and pad B go back to the items; Start continues. The D-pad and stick do the same as the arrows. The mouse focuses on hover, a click on a switch flips it and a click on a slider's track sets it where it was clicked. A change applies at once (`options::apply`); the volumes, blur and input display are saved in the settings file: volumes through `settings::update` and `audio::apply_levels`, which rescales every playing voice; blur sets `ui::backdrop::Backdrop` (the menus' backdrop; the pause page has no blur of the game yet, #1657); Show the HUD toggles the HUD as Shift+Tab does; Input display sets the HUD's input display. Nothing here touches the sim, the timer or the replay. The hint bar reads Choose, Adjust, Back.

The game's own pause (the P key, the sim's `pause` action) is a different thing: it is sim input and stays the game's in both modes, recorded in the replay like any key. A game whose pause deactivates instances keeps ticking, so its timer runs; the originals' runner-modal pauses (a message box, `keyboard_wait`) are a client freeze per game (`world` built-in, `pause = "none"`).

`--pause-preview <continue|retry|restart|options|quit>` (hidden) opens the menu at sim tick 25 with that item selected (`options` opens the Options view), for screenshot checks.
