# The client: Mods

Part of [the client](../client.md).

Mods (`mods.rs`, `ModsPlugin`, #35): `--mods <codes>` (`SD`, `FL`, `HB`, `NB`, `SL`, `FA`; codes joined by `,` or `+`) picks the run's mods from `iwbtg_sim::mods::MODS`, and the client prints the play mode and mods on start: `Play original (unranked), mods: SD` without `--ranked` (Play original is never ranked), `Play ranked, mods: SD (ranked)` (or `unranked: <mod name>`) with it (#606). Sudden Death, Flashlight, Hitboxes, No background, Slow motion and Frame advance are built (Flashlight, Hitboxes and No background change only the picture, [visual mods](visual.md); the last two act on the clock, [practice assists](practice.md)); Save states saves and loads the world with F5/F6 ([practice](practice.md), #39). Sudden Death: after each tick `watch` compares the death counter (`global.death`) with the tick before (`ModSet::ends_run`); a rise ends the run on that tick. The view's fixed-clock systems are the `view::SimTick` set, and `ModsPlugin` gates it with a run condition, so the sim stops ticking and a red "SUDDEN DEATH / Run over at tick N" banner (a child of the game camera, so it stays centred on the view) shows over the last frame. The quick-retry key or auto-retry starts again (below).

Game select's mod select sheet (#497, [shell](shell.md)) picks the set too: it writes `RunMods`, offers only the mods in `mods::BUILT` (all seven, Save states included), and Slow motion's 75% / 50% set `practice::SlowSpeed` and save it as `[practice] slow_speed` (`--slow-speed` overrides it for one run).

Each run plays with the set it opens with (#903): `--mods` and `--slow-speed` only seed the first `RunMods` and `SlowSpeed`, and every run module reads those two in `OnEnter(AppScreen::Run)` instead of taking `--mods` when the app is built: `ModsPlugin`'s Sudden Death watch, the [visual mods](visual.md), the [practice assists](practice.md) and their clock speed, the [stats](stats.md) board and the [replay](replays.md) header. A module whose systems belong to one mod adds them once and gates them on the run (`mods::run_has(Mod::…)` for a `OnEnter` step, or the per-run resource that step inserts), so a run started from game select plays, records and counts with the sheet's picks. The start line `mods::describe` still names the `--mods` set; the practice line is printed when a run opens. `shell::tests::a_run_plays_with_the_mods_picked_on_the_select_screen` builds the app with `HB`, picks `SD+SL` at 50% and checks the clock, the replay header's mods, the stats board and the Sudden Death stop, then a second run with `NB`.
