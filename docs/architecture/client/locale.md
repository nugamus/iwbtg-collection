# The client: Locale

Part of [the client](../client.md).

Translations (`locale.rs`, `crates/client/locales/`): every player-visible UI string is a key in `en.toml` and `ja.toml`, never a literal in the modules. `locale::text("results_back")` reads the key in the language in effect; `locale::format("results_stage_number", &[("n", &3)])` fills `{n}` placeholders. The catalogue is parsed once from the compiled-in files; a key missing from a translation falls back to English, and a key missing everywhere shows the key itself (the tests keep the two files' key sets equal, so that is only a development mistake). Keys are flat and prefixed by area (`results_`, `hud_`, `pause_`, `notice_`, `pill_`, `date_`, `month_`, `input_`).

The language is the settings file's `language`, `en` (default) or `ja` ([settings](settings.md)). `locale::language()` reads it on the first lookup; a file without the key or with an unknown code is English. It applies on the next start, like the display settings. A settings screen that changes it live will need a reload path (#53); none exists yet.

Translated now: the UI kit's Ranked/Unranked pills and notices, the HUD's labels, the pause menu, the results page and the leaderboard's dates (month names and the date order: English `3 Nov 2026`, Japanese `2026年11月3日`). Not translated because they are data, not UI: game titles, room and stage names from a package, sign text, sound names, mod codes and player names; the `--ui-gallery` and results sample data (English placeholders); and the browser/game-select and other screens outside this issue's modules, which are tracked in #1626.

The hard-coded-string guard is `scripts/test_ui_strings.py`, which CI runs with every other `test_*.py` (the changes job, so every PR). It fails when a string literal is passed to a UI text constructor (`text`, `Text::new`, `button`, `pill`, `stat`, `head`, `label`) in a localised module, when `en.toml` and `ja.toml` have different keys or placeholders, when a catalogue key is unused, when a `locale::text`/`locale::format` call names a key that does not exist, and when `ja.toml` uses a kana or kanji the bundled Noto Sans JP subset does not carry (which would draw as tofu). It reads its scope from `SCANNED`; the browser and game-select modules join it when #1626 localises them. A literal with no word (a `0:00.00` placeholder, a bare `—`) is not text and is allowed, so there is no per-string allowlist.

Japanese is machine translation: `ja.toml` says so in its header, and the strings were checked for key/placeholder parity, terminology and length, but a native-speaker review is still pending (#1627). Japanese uses the bundled Noto Sans JP fallback ([UI](ui.md)), which every text family already lists after its Latin faces; the subset covers the kana and the kanji used here.
