# The client: Shell

Part of [the client](../client.md).

The app shell (`shell/`, #782) makes the client's screens a Bevy state and loads packages while the app runs, so one window can play one package after another.

- **`AppScreen`.** `Select` (pick a package) and `Run` (play the `shell::LoadedPackage`: the opened `Package` and the path it came from). The loading card, the pause menu and the results page are still overlays inside `Run`, each gating `SimTick` with its own flag; making them a `RunScreen` sub-state is #839.
- **Starting and leaving.** `shell::load(world, path, trace_mode)` opens the package (`package::open`) and builds its sim (`view::new_run`), so a package that does not open or a game that does not start is an error before anything changes; `shell::start` does that and sets `NextState(Run)`. `shell::leave` (pause Quit, Escape on the loading card) goes back to `Select` when the client was started with `--select`, and otherwise writes `AppExit`, as before.
- **Scoped to the run.** Each module builds its run in `OnEnter(Run)` and drops it in `OnExit(Run)`. The schedule order is fixed by `shell::RunSteps`: on enter `Core` (the view: room size, `ViewRect`, `Previous`, the fixed clock at the game's rate times `ClockSpeed`, the window title), then `Resources` (every `shell::run_resource`), then `InRun` (spawns: game camera, sprites' textures, HUD, overlay, sign box); on exit the other way round, so the replay is finished and the stats flushed (`replays::reset`, `stats::reset` in `InRun`) while the sim and the pause menu are still there, then the run resources go, then the sim (`Game`) and `LoadedPackage` last. `shell::run_resource(app, make)` inserts `make(world)` on enter and removes it on exit (art files and image cache, `Sounds`, `Queue`, `Shake`, the pause fruit and `Menu`, `Recorder`, `Results` and its room pictures, `Retry`, mods `Run`, `Loading`, save `Written`, hitboxes, frame advance); `shell::reset_on_enter` sets run state that app-level code may still read back to its default (HUD run info, stage deaths, leaderboard, `Suspended`, `Paused`, the screen's letterbox). Entities a run spawns carry `shell::RUN_ONLY` (`DespawnOnExit(AppScreen::Run)`); children go with their parents. Dropping the resources and entities drops their handles, so the run's images and sounds unload. App-level stays: the window, backdrop, UI kit, settings, bindings and `Collector`, the stats book, notices, `ClockSpeed`, `RunMods`.
- **`InRun`.** Run systems sit in `shell::InRun`, configured in `Update`, `PostUpdate` and `Last` with `run_if(in_state(AppScreen::Run))`. The whole fixed loop (`RunFixedMainLoopSystems::FixedMainLoop`) runs only in `Run`, so `FixedUpdate` systems need no condition and the fixed clock gathers no time on the select screen (a new run starts from its first tick). A system's own run condition is still evaluated when its set's condition is false, so a condition on a run resource reads it as `Option` (`retry.rs`).
- **Start-up.** With a package on the command line, `main` loads it before the window opens (errors exit with the message, as before; the window takes its first room's size) and the shell starts in `Run`. Bevy runs the first state's `OnEnter` before `Startup`. `--select <folder>` starts in `Select` with an 800 x 608 window.
- **The select screen** (`shell/select.rs`, a placeholder until the designed game select, #148): the folders with a `game.toml` and the `.iwbz` files in the folder, by name; Up and Down pick, Enter plays, Escape quits. A package that does not open shows the NOT OPENED notice and the list stays. Its camera and page carry `DespawnOnExit(AppScreen::Select)`.
- **Not yet.** Dropping a package on the window still restarts the client on it ([import](import.md); in place through `shell::start` is #841). `--ui-gallery` and `--card-preview` are separate apps. The modules keep one plugin each, so #792's registration list can collect them.
- **Test.** `shell::tests::two_runs_leave_nothing_behind` builds the run modules that need no renderer on a headless app (`MinimalPlugins`, assets, states), plays the `audio.pkg` test fixture, leaves to `Select`, plays the `clear.pkg` fixture, leaves again, and checks that the entities (not counting the ones Bevy keeps resources on), `Assets<Image>` and `Assets<AudioSource>` are back to the first `Select` frame's counts and that the next run starts from its first tick.
