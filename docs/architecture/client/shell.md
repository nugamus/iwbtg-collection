# The client: Shell

Part of [the client](../client.md).

The app shell (`shell/`, #782) makes the client's screens a Bevy state and loads packages while the app runs, so one window can play one package after another.

- **`AppScreen`.** `Select` (pick a package) and `Run` (play the `shell::LoadedPackage`: the opened `Package` and the path it came from). What a run shows is the sub-state `shell::RunScreen` of `Run` (#839): `Loading` (the [loading card](loading.md)), `Playing`, `Paused` (the [pause menu](pause.md)), `Results` (the [results](results.md)) and `Error` (the [script error screen](script_error.md), #101: the sim halted). It exists only in `Run`. The shell gates `view::SimTick` with `in_state(RunScreen::Playing)`, so the sim ticks only while the game plays. The gates for Sudden Death, a pending retry and frame advance stay on top of it. Each screen does its own covering in `OnEnter`/`OnExit`. The loading card and the results turn the game camera off, suspend the HUD (`hud::Suspended`) and set the backdrop's dim on enter (`shell::cover_game`), and undo the camera and HUD on exit. `OnEnter(Playing)` sets the gameplay dim (`screen::gameplay_dim`). The pause menu changes neither: it dims the game itself and holds the audio. Screens change through `NextState<RunScreen>` (`shell::go` from a world), so a change takes effect at the next frame's state transition, before that frame's fixed clock. That is the same frame on which the old flags took effect. A run opens on `shell::FirstScreen` (`Loading`, or `Playing` when a `--screenshot` check skips the card). The shell sets it as the pending next screen whenever `Run` is entered: in `ShellPlugin::finish` for a package on the command line, and in `start_map`. A Bevy sub-state keeps its current value when its parent re-enters (`Run` to `Run`, a dropped package), so without this the next run would not open on the card. A retry from the pause menu, the results or the script error screen goes back to `Playing` (`pause::reset`, `results::reset`, `script_error::reset`). A retry on the loading card leaves the card up.
- **Starting and leaving.** `shell::start(world, path)` opens the package (`package::open`), decodes its sprite strips (`package::sprite_images`) and builds its sim (`view::new_run`) without changing the world, so a package that does not open or a game that cannot be set up is an error (`shell::StartError`) before anything changes. A script error in the start room's first tick is not: the run opens with the sim halted and shows the [script error screen](script_error.md) (#946). It leaves the result as the non-send `NextRun` and sets `NextState(Run)` with `set`, so from `Run` too (a dropped package, [import](import.md), #841) the state goes Run to Run: the run that plays closes on `OnExit(Run)`, then `open_next`, first on `OnEnter(Run)` before `Core`, puts the new `Game`, `RunStart`, `RunSprites` and `LoadedPackage` in place. `shell::start_map(world, path, map)` is game select's start (#880, #1023): it **stages** the same work instead of doing it in the click's frame. `package::open` and `package::sprite_images` are `Send`, so `shell::stage` runs them on a worker thread (the browser build, which has no threads, runs them at once) and stores the `PendingStart` receiver; the select screen keeps drawing `Opening <name>…` and the run on screen, if any, keeps playing. `shell::poll_start`, an exclusive `Update` system, receives the result, builds the sim on the main thread (`view::new_run`, whose Rhai ASTs are `!Send`, so it must not move) and commits `NextRun` plus `NextState(Run)` in one step. Each request has a generation: a newer `start_map` replaces `PendingStart`, so the older worker's result is ignored and a stale result never commits (the replaced worker still finishes its open and decode; nothing is cancelled mid-flight). A failure (`StartFailed`) leaves the state and the run untouched. `shell::load` builds and puts a package in place at once, for the command-line package before the app runs. `shell::leave` (pause Quit, Escape on the loading card) goes back to `Select` when the client was started with `--select`, and otherwise writes `AppExit`, as before. A staged start that has not committed is simply dropped when the app exits.
- **Startup latency (#1023).** `shell::tests::startup_phases` is the reproducible measurement: it copies `audio.pkg`, adds 400 generated 256×256 sprite sidecars and PNGs, and times `package::open`, `package::sprite_images`, `Sim::prepare` and the first-room sim build (run it with `cargo test -p iwbtg-client --locked shell::tests::startup_phases -- --ignored --nocapture`; it is ignored so it is never a check). On 2026-11-24, a loaded shared developer host, debug build, one run each: open/parse 0.9 s (1.4 s and 3.0 s on more contended runs, so host load and disk cache dominate), PNG decode 139–157 ms for 100 MiB of RGBA, script prepare 12–22 µs and the first room 0.6–0.7 ms; the real `showcase.pkg` was open 13 ms warm (201 ms on the cold first run), decode 1.3–1.4 ms (15 sprites) and script prepare 3 µs. Opening and decoding are the staged worker's and leave the UI thread free; only the script prepare and the first-room build block the commit. The numbers are advisory (no reference machine), and browser startup is not measured here: the web app fetches one package and runs `load_package` before the app, so it has no `start_map` stage to time.
- **Scoped to the run.** Each module builds its run in `OnEnter(Run)` and drops it in `OnExit(Run)`. The schedule order is fixed by `shell::RunSteps`: on enter `Core` (the view: room size, `ViewRect`, `Previous`, the fixed clock at the game's rate times `ClockSpeed`, the window title), then `Resources` (every `shell::run_resource`), then `InRun` (spawns: game camera, sprites' textures, HUD, overlay, sign box); on exit the other way round, so the replay is finished and the stats flushed (`replays::reset`, `stats::reset` in `InRun`) while the sim and the pause menu are still there, then the run resources go, then the sim (`Game`) and `LoadedPackage` last. `shell::run_resource(app, make)` inserts `make(world)` on enter and removes it on exit (art files and image cache, `Sounds`, `Queue`, `Shake`, the pause fruit and `Menu`, `Recorder`, `Results` and its room pictures, `Retry`, mods `Run`, `Loading`, save `Written`, hitboxes, frame advance); `shell::reset_on_enter` sets run state that app-level code may still read back to its default (HUD run info, stage deaths, leaderboard, `Suspended`, `Paused`, the screen's letterbox). Entities a run spawns carry `shell::RUN_ONLY` (`DespawnOnExit(AppScreen::Run)`); children go with their parents. Dropping the resources and entities drops their handles, so the run's images and sounds unload. A global observer (`add_observer`: `Activate`, `PointerClick`) also fires on game select, so it takes a run resource as `Option` and does nothing without it; a plain `ResMut` fails validation there and panics (#1467). App-level stays: the window, backdrop, UI kit, settings, bindings and `Collector`, the stats book, notices, `ClockSpeed`, `RunMods`.
- **`InRun`.** Run systems sit in `shell::InRun`, configured in `Update`, `PostUpdate` and `Last` with `run_if(in_state(AppScreen::Run))`. The whole fixed loop (`RunFixedMainLoopSystems::FixedMainLoop`) runs only in `Run`, so `FixedUpdate` systems need no condition and the fixed clock gathers no time on the select screen (a new run starts from its first tick). A system's own run condition is still evaluated when its set's condition is false, so a condition on a run resource reads it as `Option` (`retry.rs`).
- **Start-up.** With a package on the command line, `main` loads it before the window opens (errors exit with the message, as before, except a first-tick script error, which opens on the script error screen; the window takes its first room's size) and the shell starts in `Run`. Bevy runs the first state's `OnEnter` before `Startup`. `--select <folder>` starts in `Select` with an 800 x 608 window.
- **The select screen** (`shell/select.rs`; the list is #149, the left side a placeholder until #148): the folders with a `game.toml` and the `.iwbz` files in the folder, by name, as game select's list (`Main.dc.html`, right side). `select/library.rs` reads each package once per folder into `Library` (kept between runs): title, authors and maps from `game.toml` (a package without `[[maps]]` has one map, named "Ranked mode" as on the loading card; one whose `game.toml` does not read is listed by its file name, without maps), its key art (`key_art::resolve` as the backdrop draws it, cut to the panel's middle band and at most 1280 px wide, so 20 games keep 20 small strips, not 20 key arts), and the first frame of its `cherry` sprite for the Cleared mark (the pause menu's fruit, else our own). A folder package is not read whole: only `game.toml`, the key art images, the first ranked room, its back layers and `sprites/cherry.*`. Each time the screen opens, `Records` (your PB per map on the ranked board with the mods set now, and whether any map was cleared) is read again from the stats book. `select/list.rs` draws it with the UI kit: game panels 72 px, map panels 45 px (30 px further right), 3 px apart, all sheared 0.2 with 10 px corners, starting 860 px from the window's right edge and running past it. A game panel shows its art behind the dark left-to-right veil, the title (ellipsis), the creator, a dot per map in its star colour and, when cleared, the fruit with CLEARED. A map panel shows the star-colour band, an upright star pill, the name and your PB or "No PB". Star ratings are #111: until then a map has none, its pill reads `★ –` and its colour is muted. `Selection { game, map }` is the pick (#148 reads it); `looks` slides the selected game 25 px left with a white outline and a lighter veil and opens its maps (OutQuint, 400 ms), slides the selected map and gives it light glass and a bold name, and scrolls the list (OutQuint) to keep the pick in the middle between y 150 and the footer, never past the list's ends (`list::scroll_for`; the artboard's list needs none). `ListDim(true)` dims the list to 50 % (#148's left side sets it; the artboards give no value, `revisit`). Up and Down step through the maps and on into the next or previous game, Left and Right through the games (`list::step`, wrapping); a click on a game opens it on its first map, on a map selects it, on the selected map plays. Enter plays the selected map, as does a click on it (`shell::start_map(world, path, Some(map id))`, which `view::new_run` passes on as `SimOptions::map`, so the loading card, the HUD leaderboard, the stats and the replay all follow `Sim::map_id`; a retry keeps it, #880), Escape quits. A package that does not open shows the NOT OPENED notice and the list stays. The page is laid out at the artboard's 1080 px height, scaled to the window. Its camera and page carry `DespawnOnExit(AppScreen::Select)`.
- **Search, group, sort and filters** (#150, `Main.dc.html` top right; `select/controls.rs` draws them, `select/filters.rs` decides). Row one: the search field (focused when the screen opens, so typing searches; every word must be in the title or the creator, any case) and Collections. Row two: Group, Sort, the Cleared and Uncleared chips (at most one on; a second click turns it off), Status, Creator, Year. Group, Sort and Creator open a dropdown of chips under the control (the artboards draw no open dropdown, `revisit`); a pick closes it and the focus goes back to the search field. An open dropdown spawns a full-screen click-catcher under its menu (`controls::Catcher`, `GlobalZIndex` 10: over the list and controls, under the menu's 20): a press on it closes the menu and the catcher, and as that press did not land on the control or game beneath, no click reaches it, so a click outside only closes (also on bare backdrop; a click on another dropdown's control closes the open one rather than opening that one). They write `filters::Filters` (kept between runs); `filters::rows` turns it and the library into `list::Shown`: the games that pass, grouped with a header row (name in small capitals and the count, 34 px, no panel: `revisit`) and sorted within, ties by title then package order. Wired now: Group by Game (no headers), Creator, Cleared; Sort by Title (the default: the artboard's `Stars` sorts nothing until #111 rates maps), Creator, Cleared (cleared first); Stars for both (easiest first, unrated last; grouped by whole stars) is offered as soon as any map has a rating. Collections (#105) is wired as the game select's personal lists, kept in `collections.toml` in the data store ([storage](storage.md)): the dropdown lists Any, Favorites and each named collection, and the list keeps the games in the pick. The left side writes them: a Favorite toggle for the selected game, a chip per named collection that adds or removes it, and a name field with Add that creates a collection with the selected game in it; a new collection gets its chip at once and every change is saved. Not wired, shown faded until their data exists: the Year, Tag and Status options and the Status and Year dropdowns (game metadata model, #805); tags are not searched yet either, so the placeholder reads `Search N games: title, creator`. The list places each row by hand (`list::place`; absolute rows moved by an `OffsetY` tween, not flex layout), so a new order, a header or a game's maps opening slide the rows below (OutQuint, 400 ms); a game the filters drop fades out where it is and is hidden when faded (no clicks), one that comes back fades in at its new place; headers come and go the same way. A selection the filters drop moves to the first game shown; the arrows walk only the games shown (`list::step`), and Left and Right move the search field's cursor instead while it holds text. Escape closes an open dropdown, else clears the search, else quits; Enter on a focused control activates it rather than playing. The map dots and star pills are upright kit shapes, so they fade and dim with the list.
- **Mod select** (#497, `ModSelect.dc.html`; `select/footer.rs`, `select/mod_sheet.rs`). The footer has, for now, only the Mods button (Primary, 52 px, `Mods` and the picked codes or `none`, left of where #148's player card goes). A click opens the sheet: the overlay (`GlobalZIndex(20)`) fades in a dim (`tokens::SHEET_DIM`) and slides the sheet up from below the window to 300 px from the top (OutQuint, 400 ms; reversed on close, then hidden). The sheet: the 3 px accent line, the `Mods` title and line, and on the right the header that follows the ranked rule (docs/product.md, Mods): with every mod ranked, the Ranked pill and `Counts for <map> + SD + NB` (`<map> · no mods` without mods); otherwise the Unranked pill and the loading card's reason (`loading::standing`, `Slow motion 75% is a practice assist, so this run won't reach the leaderboard.`). Three columns, Challenge, Visual and Practice (`· never ranked`), list `iwbtg_sim::mods::MODS` by kind as kit mod cards in the column colour (`tokens::MOD_CHALLENGE`, `MOD_VISUAL`, `MOD_PRACTICE`); a mod not in `mods::BUILT` (Save states) is a faded card that reads "Not built yet." and takes no clicks. Slow motion's 75% / 50% pills set `practice::SlowSpeed` and write `[practice] slow_speed`, so the next start keeps the pick (#904). The footer: Back, the Auto-retry switch (writes `[retry] auto`, which the next run reads), `Selected` and a pill per picked mod, Deselect all, Done. The picked set is `mods::RunMods`; the list's PBs are read again for it (`select::records`). Back and Escape put back the set the sheet opened with, Done keeps it. While the sheet is open the select screen's keys are off (`mod_sheet::closed`) and the search field loses the focus (it gets it back on close). Runs still play with `--mods` until #903. `--mod-select-preview` (hidden, with `--select`) opens the sheet at start for screenshots; `--mods` picks what it shows.
- **Not yet.** `--ui-gallery` and `--card-preview` are separate apps. The modules keep one plugin each, so #792's registration list can collect them.
- **Test.** `shell::tests::two_runs_leave_nothing_behind` builds the run modules that need no renderer on a headless app (`MinimalPlugins`, assets, states), plays the `audio.pkg` test fixture, leaves to `Select`, plays the `clear.pkg` fixture, leaves again, and checks that the entities (not counting the ones Bevy keeps resources on), `Assets<Image>` and `Assets<AudioSource>` are back to the first `Select` frame's counts and that the next run starts from its first tick. `a_staged_start_keeps_the_run_until_it_is_ready` stages `clear.pkg` while `audio.pkg` plays on a channel the test controls, checks the old run keeps ticking and the package does not change, then delivers the result and checks the new run installs with one camera from its first tick. `a_failed_staged_start_keeps_the_run_playing`, `a_newer_staged_start_wins` (a stale generation is ignored) and `start_map_refuses_an_unknown_map` cover the failure and cancellation paths; the staged start is driven to its result by `wait_for_stage`. `a_run_walks_loading_playing_paused_playing_results` opens `clear.pkg` with the card. It checks that the card shows for its minimum time with no tick and the game hidden. Then the game ticks, Escape pauses (no tick, the game shown, `hud::Paused::open`) and continues. The results open (`results::preview_next`, the sample run as a clear) with no tick and the game hidden, and Escape goes back to the game. A run that replaces this one opens on the card again, and leaving drops the sub-state. `a_skipped_card_opens_on_the_game` checks the `--screenshot` path.
