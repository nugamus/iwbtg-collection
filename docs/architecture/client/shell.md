# The client: Shell

Part of [the client](../client.md).

The app shell (`shell/`, #782) makes the client's screens a Bevy state and loads packages while the app runs, so one window can play one package after another.

- **`AppScreen`.** `Menu` (the main menu, below), `Select` (Time Attack's game select), `Shelf` (Classic's shelf, below) and `Run` (play the `shell::LoadedPackage`: the opened `Package` and the path it came from). What a run shows is the sub-state `shell::RunScreen` of `Run` (#839): `Loading` (the [loading card](loading.md)), `Playing`, `Paused` (the [pause menu](pause.md)), `Results` (the [results](results.md)) and `Error` (the [script error screen](script_error.md), #101: the sim halted). It exists only in `Run`. The shell gates `view::SimTick` with `in_state(RunScreen::Playing)`, so the sim ticks only while the game plays. The gates for Sudden Death, a pending retry and frame advance stay on top of it. Each screen does its own covering in `OnEnter`/`OnExit`. The loading card and the results turn the game camera off, suspend the HUD (`hud::Suspended`) and set the backdrop's dim on enter (`shell::cover_game`), and undo the camera and HUD on exit. `OnEnter(Playing)` sets the gameplay dim (`screen::gameplay_dim`). The pause menu changes neither: it dims the game itself and holds the audio. Screens change through `NextState<RunScreen>` (`shell::go` from a world), so a change takes effect at the next frame's state transition, before that frame's fixed clock. That is the same frame on which the old flags took effect. A run opens on `shell::FirstScreen` (`Loading`, or `Playing` when a `--screenshot` check skips the card). The shell sets it as the pending next screen whenever `Run` is entered: in `ShellPlugin::finish` for a package on the command line, and in `start_map`. A Bevy sub-state keeps its current value when its parent re-enters (`Run` to `Run`, a dropped package), so without this the next run would not open on the card. A retry from the pause menu, the results or the script error screen goes back to `Playing` (`pause::reset`, `results::reset`, `script_error::reset`). A retry on the loading card leaves the card up.
- **Starting and leaving.** `shell::start(world, path)` opens the package (`package::open`), decodes its sprite strips (`package::sprite_images`) and builds its sim (`view::new_run`) without changing the world, so a package that does not open or a game that cannot be set up is an error (`shell::StartError`) before anything changes. A script error in the start room's first tick is not: the run opens with the sim halted and shows the [script error screen](script_error.md) (#946). It leaves the result as the non-send `NextRun` and sets `NextState(Run)` with `set`, so from `Run` too (a dropped package, [import](import.md), #841) the state goes Run to Run: the run that plays closes on `OnExit(Run)`, then `open_next`, first on `OnEnter(Run)` before `Core`, puts the new `Game`, `RunStart`, `RunSprites` and `LoadedPackage` in place. `shell::start_map(world, path, map)` is game select's start (#880, #1023): it **stages** the same work instead of doing it in the click's frame. `package::open` and `package::sprite_images` are `Send`, so `shell::stage` runs them on a worker thread (the browser build, which has no threads, runs them at once) and stores the `PendingStart` receiver; the select screen keeps drawing `Opening <name>…` and the run on screen, if any, keeps playing. `shell::poll_start`, an exclusive `Update` system, receives the result, builds the sim on the main thread (`view::new_run`, whose Rhai ASTs are `!Send`, so it must not move) and commits `NextRun` plus `NextState(Run)` in one step. Each request has a generation: a newer `start_map` replaces `PendingStart`, so the older worker's result is ignored and a stale result never commits (the replaced worker still finishes its open and decode; nothing is cancelled mid-flight). A failure (`StartFailed`) leaves the state and the run untouched. `shell::load` builds and puts a package in place at once, for the command-line package before the app runs. `shell::leave` (pause Quit, Escape on the loading card) goes back to `Select` (the mode's screen) when the client was started with `--select`, and otherwise writes `AppExit`, as before. A staged start that has not committed is simply dropped when the app exits.
- **Startup latency (#1023).** `shell::tests::startup_phases` is the reproducible measurement: it copies `audio.pkg`, adds 400 generated 256×256 sprite sidecars and PNGs, and times `package::open`, `package::sprite_images`, `Sim::prepare` and the first-room sim build (run it with `cargo test -p iwbtg-client --locked shell::tests::startup_phases -- --ignored --nocapture`; it is ignored so it is never a check). On 2026-11-24, a loaded shared developer host, debug build, one run each: open/parse 0.9 s (1.4 s and 3.0 s on more contended runs, so host load and disk cache dominate), PNG decode 139–157 ms for 100 MiB of RGBA, script prepare 12–22 µs and the first room 0.6–0.7 ms; the real `showcase.pkg` was open 13 ms warm (201 ms on the cold first run), decode 1.3–1.4 ms (15 sprites) and script prepare 3 µs. Opening and decoding are the staged worker's and leave the UI thread free; only the script prepare and the first-room build block the commit. The numbers are advisory (no reference machine). Browser startup is measured separately (#1489): the web app has no `start_map` stage — it fetches one package and runs `load_package` before the app — and [web](web.md) (Measuring startup) records its phases. On 2026-11-25 (release wasm, headless Chrome 158 with SwiftShader, Windows 11 / Intel Arc 130T), the 400 × 256 synthetic package measured fetch 9–10 ms, unpack 9–11 ms, parse/masks 106–121 ms, sprite decode 81–92 ms, script prepare ≤0.1 ms, first room 2.5–3.2 ms, Bevy init 224–242 ms and 13 frames of sprite image build/queue (~0.2 ms of CPU, 4.1–4.2 s of wall time at the software renderer's frame rate), 4.66–4.80 s in total; the showcase totalled 448–526 ms. The package phases are the same order as native's; the browser's cost is Bevy and the software-rendered frames, not the load.
- **Scoped to the run.** Each module builds its run in `OnEnter(Run)` and drops it in `OnExit(Run)`. The schedule order is fixed by `shell::RunSteps`: on enter `Core` (the view: room size, `ViewRect`, `Previous`, the fixed clock at the game's rate times `ClockSpeed`, the window title), then `Resources` (every `shell::run_resource`), then `InRun` (spawns: game camera, sprites' textures, HUD, overlay, sign box); on exit the other way round, so the replay is finished and the stats flushed (`replays::reset`, `stats::reset` in `InRun`) while the sim and the pause menu are still there, then the run resources go, then the sim (`Game`) and `LoadedPackage` last. `shell::run_resource(app, make)` inserts `make(world)` on enter and removes it on exit (art files and image cache, `Sounds`, `Queue`, `Shake`, the pause fruit and `Menu`, `Recorder`, `Results` and its room pictures, `Retry`, mods `Run`, `Loading`, save `Written`, hitboxes, frame advance); `shell::reset_on_enter` sets run state that app-level code may still read back to its default (HUD run info, stage deaths, leaderboard, `Suspended`, `Paused`, the screen's letterbox). Entities a run spawns carry `shell::RUN_ONLY` (`DespawnOnExit(AppScreen::Run)`); children go with their parents. Dropping the resources and entities drops their handles, so the run's images and sounds unload. A global observer (`add_observer`: `Activate`, `PointerClick`) also fires on game select and the main menu, so it takes a run resource (or game select's `Library` and `Selection`) as `Option` and does nothing without it; a plain `ResMut` fails validation there and panics (#1467, #1608). App-level stays: the window, backdrop, UI kit, settings, bindings and `Collector`, the stats book, notices, `ClockSpeed`, `RunMods`.
- **`InRun`.** Run systems sit in `shell::InRun`, configured in `Update`, `PostUpdate` and `Last` with `run_if(in_state(AppScreen::Run))`. The whole fixed loop (`RunFixedMainLoopSystems::FixedMainLoop`) runs only in `Run`, so `FixedUpdate` systems need no condition and the fixed clock gathers no time on the select screen (a new run starts from its first tick). A system's own run condition is still evaluated when its set's condition is false, so a condition on a run resource reads it as `Option` (`retry.rs`).
- **Start-up.** With a package on the command line, `main` loads it before the window opens (errors exit with the message, as before, except a first-tick script error, which opens on the script error screen; the window takes its first room's size) and the shell starts in `Run`. Bevy runs the first state's `OnEnter` before `Startup`. `--select <folder>` starts on the main menu (`Menu`) with an 800 x 608 window; the hidden checks `--mod-select-preview`, `--practice-preview` and `--select-preview <time-attack|classic>` start in `Select`, and `--menu-preview <initial|top|play|classic>` opens the menu at an artboard's state.
- **The main menu and the mode** (`shell/menu.rs`, m5 `MainMenu.dc.html`: B6, B7, A1, A2; #1608). The player picks the play mode here once (docs/product.md, Two ways to play each game) and switches it in the toolbar on every screen outside a run (`ui::mode::Mode`, `ui::toolbar`). Three levels (`menu::MainMenu`): Initial (the delicious fruit alone and `Press any key`), Top (Play, Browse, Replays, Settings, Exit) and Play (Back, Time Attack, Classic, Race marked Later). Any key or click opens Top: the fruit slides left and shrinks (300 ms OutExpo, `motion::SCREEN`) and the band's buttons grow from nothing (300 ms OutExpo). Left and Right move the focus over the usable buttons, hover focuses (not in a `--screenshot` check), and a focused button widens 1.5x (150 ms OutQuint, `motion::SELECT`) in its own colour; Enter, Space or a click chooses; Escape steps back a level and exits at the top. A focused mode sets `Mode`, so the toolbar and every accent follow; choosing it opens the mode's screen (`shell::mode_home`: `Select` for Time Attack, `Shelf` for Classic); the toolbar's mode switch on either screen opens the other (`shell::mode_screen`), and leaving a run goes back to the mode's screen. Until their groups land, Browse, Replays and Settings do nothing. The page shows a library game's key art behind it (`library::backdrop_art`, the first that has one from a random start, the first package in a check), the client's own delicious fruit (`assets/ui/cherry.png`, credited there), the working title, the footer line, the toolbar and the player card. Back from game select reopens it on the Play level with the mode focused. **Updating (#1684):** the page is built once per visit (`rebuild` → `spawn_page`); a focus change only retargets the buttons' widths and shapes (`looks`) and moves the caption, and a level change rebuilds just the level's slots (the glow, the band's buttons, the fruit and the wordmark, `ui::live`) and shows or hides the parts of the other level (`ShownAt`): the toolbar, the player card, the band, the caption and the footer are never respawned. **Window sizes (#1692):** the shell's pages (menu, game select, shelf) scale with `select::scale`, which keeps them at least `select::MIN_WIDTH` (1720) design px wide; the menu's middle (glow, band, fruit, caption) is a 1080-tall block centred on the page, so a tall window keeps it in the middle; on the Initial level the fruit, the wordmark and the glow keep to the page's horizontal middle (50 %, `menu::place_x`) rather than to x 960, so they stay over `Press any key` on any aspect, and leaving it they slide from that middle (#1704).
- **The shelf** (`shell/shelf.rs`, m5 `A4_Shelf`, #1618): Classic's screen, one sheared cover per game (no map entries: a game's own difficulty select runs in the game). It shares game select's `Library`, whose preview worker also cuts each game's key art to a portrait cover (`library::cover_image`, 632 x 636 at most) around the pick (`ART_RADIUS` covers each side). The picked game's whole key art (`library::backdrop_art`, the client's scene without one) fills the backdrop at dim 0.22 and a light blur. Left: a Ranked pill and `N difficulties, picked in the game` (`One route` for one map), the title, the creator with a hued initial, and five numbers from the book's Classic numbers (`shelf::Facts`, `Book::game_mode`, #1619): `Time played` and `Deaths` in Classic (`all modes` for a game only played before the book kept modes apart), `Finished` with the last finish's date, `Furthest` (the furthest room until packages declare sections, E7) and `Last session` (its length, deaths and how long ago). Right: Your progress with `last played … ago`, the furthest room and the last finish (no save), Play (Primary in the mode's violet: `PlayMode::Original` on the first map, as the game starts) and Details (group 12). The Library row: the search (title and creator, every word) and the Played and Finished chips (`ShelfState`, kept between visits). Left and Right walk the covers shown (the row slides, OutQuint, to keep three before the pick; the picked cover is 236 x 318 with a violet ring and band, the others 200 x 270), Enter or a click on the picked cover plays, a click on another picks it, Escape clears the search, else goes back to the main menu. The footer: Back, Details, the key hints (`ui::hints`) and the player card. `--select-preview classic` opens it for screenshots. **Updating (#1685):** walking the shelf respawns no node; the picked cover grows and the others make room by `Tween<Width>`/`Tween<Height>` over `motion::SELECT` instead of jumping.
- **Game select's left side and footer** (#148, m5 `A3_SelectTimeAttack`; `select/hero.rs`, `select/footer.rs`). The title wedge: a sheared panel cut from the picked game's key art (faded into the ground on the left, the accent line fading along its bottom), the Ranked or Unranked pill (the mod sheet's standing), the star pill when the map has a rating, the map's name, the title (Barlow Condensed italic 76, cut with `…`) and the creator with an avatar initial. Under it the stats row (Stages, Your PB, Your deaths, Clears, Time played, World record) and the stage strip: one bar per stage of the map, coloured by your deaths there (the worst in the accent), labelled 1, 2, … or Boss with the count. Offline the world record is `—`; tags and the year wait for #1631. Under the strip the **Details and Ranking tabs** (#151, `select/ranking.rs`): Ranking (the default) lists the picked map's board with the mods set now; in the Local scope your runs from the stats book, fastest first, at most six, #1 in gold and the PB marked YOUR PB, or `No clears yet — be the first`; the Scope switch's Global says the global boards come with online play (#484). Details holds the folder and the collections until its own design (#498). The keys hint sits over the footer's left half and says `Opening <name>…` while a start prepares. Each part is a `ui::live` slot keyed on what it shows. The picked game's key art fills the backdrop; the library's preview worker builds it (`Library::backdrop`) so a pick never reads a package on the UI thread (the shelf uses the same). The footer: Back (main menu) and Options (settings) on the left; Random (another game among those shown), Practice and Mods on the right, then the compact player card.
- **The select screen** (`shell/select.rs`; the list is #149, the left side #148): the folders with a `game.toml` and the `.iwbz` files in the folder, by name, as game select's list (`Main.dc.html`, right side). `select/library.rs` lists a folder in two passes into `Library` (kept between runs): first every package's `game.toml` alone — title, authors and maps (a package without `[[maps]]` has one map, named "Full game"; one whose `game.toml` does not read is listed by its file name, without maps) — so ordering, search and selection work at once; then a background worker builds the previews for the shown games within `PREVIEW_RADIUS` rows of the pick and the rest of the list draws a dark placeholder until theirs arrive. A preview is the game's key art (`key_art::resolve` as the backdrop draws it, cut to the panel's middle band and at most 1280 px wide, so 20 games keep 20 small strips, not 20 key arts) and the first frame of its `cherry` sprite for the Cleared mark (the pause menu's fruit, else the client's own delicious fruit). Moving the pick evicts the strips outside that window, so the retained memory is one window of previews, not the whole library. A folder package is not read whole: only `game.toml`, the key art images, the first ranked room, its back layers and `sprites/cherry.*`; an archive's preview uses the selective reader (#1022, #1589). `Library` is reused only when the folder, the path set and every path's key (its length and mtime and its `game.toml`'s) are unchanged; a package replaced or changed at the same path is re-read, and the unreadable fallback stays (#1593). Each time the screen opens, `Records` (your PB per map on the ranked board with the mods set now, and whether any map was cleared) is read again from the stats book. `select/list.rs` draws it with the UI kit: game panels 72 px, map panels 45 px (30 px further right), 3 px apart, all sheared 0.2 with 10 px corners, starting 860 px from the window's right edge and running past it. A game panel shows its art behind the dark left-to-right veil, the title (ellipsis), the creator, a dot per map in its star colour and, when cleared, the fruit with CLEARED. A map panel shows the star-colour band, an upright star pill, the name and your PB or "No PB". Star ratings are #111: until then a map has none, its pill reads `★ –` and its colour is muted. `Selection { game, map }` is the pick (#148 reads it); `looks` slides the selected game 25 px left with a white outline and a lighter veil and opens its maps (OutQuint, 150 ms slide, 200 ms rows), slides the selected map and gives it light glass and a bold name, and scrolls the list (OutQuint) to keep the pick in the middle between y 150 and the footer, never past the list's ends (`list::scroll_for`; the artboard's list needs none). The left side's **Practice** button opens the practice panel ([practice](practice.md), #39): the map's stages, the game's save and every play room; Start stages a practice run from the pick. `ListDim(true)` dims the list to 50 % (#148's left side sets it; the artboards give no value, `revisit`). Up and Down step through the maps and on into the next or previous game, Left and Right through the games (`list::step`, wrapping); a click on a game opens it on its first map, on a map selects it, on the selected map plays. It plays in the picked mode (#1608, which replaced #43's per-game Ranked and Play original buttons): Time Attack is `PlayMode::Stripped`, starting at the map's ranked start with the timer on the first input, and Classic is `PlayMode::Original`, the game as ported (Enter and a click on the selected map: `shell::start_map(world, path, map, mode)`, which `view::new_run` passes on as `SimOptions::mode` and `map`; a package opened on the command line without game select takes `--ranked` as its default, so the loading card, the HUD leaderboard, the stats and the replay all follow the run's mode; a retry keeps mode and map, #880, #43). Escape goes back to the main menu: there is no Home button (m5 B8). The toolbar runs along the top and the page sits 48 px lower than m4's (`select::UNDER_TOOLBAR`, m5 A3). A package that does not open shows the NOT OPENED notice and the list stays. The page is laid out at the artboard's 1080 px height, scaled to the window. Its camera and page carry `DespawnOnExit(AppScreen::Select)`.
- **Search, group, sort and filters** (#150, `Main.dc.html` top right; `select/controls.rs` draws them, `select/filters.rs` decides). Row one: the search field (focused when the screen opens, so typing searches; every word must be in the title or the creator, any case) and Collections. Row two: Group, Sort, the Cleared and Uncleared chips (at most one on; a second click turns it off), Status, Creator, Year. Group, Sort and Creator open a dropdown of chips under the control (the artboards draw no open dropdown, `revisit`); a pick closes it and the focus goes back to the search field. An open dropdown spawns a full-screen click-catcher under its menu (`controls::Catcher`, `GlobalZIndex` 10: over the list and controls, under the menu's 20): a press on it closes the menu and the catcher, and as that press did not land on the control or game beneath, no click reaches it, so a click outside only closes (also on bare backdrop; a click on another dropdown's control closes the open one rather than opening that one). They write `filters::Filters` (kept between runs); `filters::rows` turns it and the library into `list::Shown`: the games that pass, grouped with a header row (name in small capitals and the count, 34 px, no panel: `revisit`) and sorted within, ties by title then package order. Wired now: Group by Game (no headers), Creator, Cleared; Sort by Title (the default: the artboard's `Stars` sorts nothing until #111 rates maps), Creator, Cleared (cleared first); Stars for both (easiest first, unrated last; grouped by whole stars) is offered as soon as any map has a rating. Collections (#105) is wired as the game select's personal lists, kept in `collections.toml` in the data store ([storage](storage.md)): the dropdown lists Any, Favorites and each named collection, and the list keeps the games in the pick. The left side writes them: a Favorite toggle for the selected game, a chip per named collection that adds or removes it, and a name field with Add that creates a collection with the selected game in it; a new collection gets its chip at once and every change is saved. While a named collection is the pick, its menu also offers Rename and Delete: Rename puts the name in the field (Add reads Rename; Enter saves, Esc cancels) and the filter follows the new name, while Delete removes only the list — the games and the favorites stay, and the filter goes back to Any (#1495). Not wired, shown faded until their data exists: the Year, Tag and Status options and the Status and Year dropdowns (game metadata model, #805); tags are not searched yet either, so the placeholder reads `Search N games: title, creator`. The list places each row by hand (`list::place`; absolute rows moved by an `OffsetY` tween, not flex layout), so a new order, a header or a game's maps opening slide the rows below (OutQuint, 200 ms); a game the filters drop fades out where it is and is hidden when faded (no clicks), one that comes back fades in at its new place; headers come and go the same way. A selection the filters drop moves to the first game shown; the arrows walk only the games shown (`list::step`), and Left and Right move the search field's cursor instead while it holds text. Escape closes an open dropdown, else clears the search, else goes back to the main menu; Enter on a focused control activates it rather than playing. The map dots and star pills are upright kit shapes, so they fade and dim with the list.
