# The client: Practice assists

Part of [the client](../client.md).

The practice assists that act on the clock (`practice.rs`, `PracticePlugin`, #551; [product](../../product.md#mods)): Slow motion (`--mods SL`) and Frame advance (`--mods FA`), picked like every mod ([mods](mods.md)). Neither changes what a tick computes, only when ticks run, so the replay plays back the same at normal speed. Both are practice mods, so the run is never ranked: the start line says `unranked: <mod name>` (`ModSet::unranked_by`, `mods::describe`) and the HUD's mod row shows the Unranked pill and the codes, until the loading card (#495) shows it. On start the plugin prints how to play them, for example `Slow motion at 50%; Frame advance: the frame-advance key (F by default) runs one tick`.

- **Slow motion.** `--slow-speed <75|50>` (default 75, also `50%`; anything else is refused) is a client setting, not stored in the replay. The plugin inserts `view::ClockSpeed` (0.75 or 0.5) and sets the first tick's timestep; `view::follow_room_speed` multiplies the room's rate by it after every tick, so a 50 Hz game ticks at 37.5 or 25 Hz. Every voice plays at the same factor ([audio](audio.md)), so music stays on the tick clock. Stats count play time from the fixed timestep, so a slowed run's play time is the real time played.
- **Frame advance.** The run's first tick runs (so the room is on screen), then `SimTick` is gated until a step is pending. `frame-advance` is a client key (`bindings::ClientKey`, F by default, no controller default; `--bind frame-advance=...`); the collector counts its presses (`Collector::take_advance`), which never enter an `InputFrame`. `take` turns them into pending steps before `SimTick` in each fixed step, and `spend` (in `SimTick`, after `view::tick`) uses one when a tick ran. So one press is one tick, two presses before a fixed step are two ticks on two fixed steps, and a press while something else holds the sim (the pause menu, a pending retry) waits for it. Input collected between steps reaches the next tick with its edges. Looping tunes (`audio::MusicSync`) are held paused; `audio::sync_music` keeps their position on the tick count. One-shot sounds play.
- **Both.** With `SL+FA` each press still runs one tick; the slower clock only delays when within a fixed step it lands.
