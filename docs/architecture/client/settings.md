# The client: Settings

Part of [the client](../client.md).

Settings (`settings.rs`): one versioned TOML file, `settings.toml` in the config area of Storage (natively `iwbtg-collection/settings.toml` in the config folder: `%APPDATA%` on Windows, else `$XDG_CONFIG_HOME` or `~/.config`; `$IWBTG_CONFIG_DIR` replaces the whole folder). It holds `version` (1), `name` (the local profile name for the player card, at most 32 characters; absent or empty falls back to the system account's name, see the card page; the same file in browser storage on the web), `language` (`en`, the default, or `ja`; an unknown code is a warning and English; absent reads as English; see [Locale](locale.md), #196), `[display]` (`fullscreen`, `ratio` as `native` or `W:H`, `window` as `WIDTHxHEIGHT`, `integer_scale`, `backdrop_blur`, the UI backdrop's blur in percent, 0 to 100, default 60), `[audio]` (`offset_ms`, 0 to 500; `master_volume`, `music_volume`, `sound_volume`, each a percentage 0 to 100, default 100; music and sound are each multiplied by the master volume, see the audio page; `--volume` sets `master_volume` and is saved, while `--mute` and `IWBTG_MUTE` are never saved), `[hud]` (`overlay`, the F3 overlay, default `false`, see [Overlay](overlay.md); `ui_scale`, the HUD side panels' scale in percent, 75 to 150; `[hud.show]`, one `true`/`false` per HUD element: `leaderboard`, `timer`, `deaths`, `stage`, `stage_deaths`, `input`, `mods`, all on by default), `[retry]` (`auto`, auto-retry after every death, default `false`; `--auto-retry` overrides it for one run and is not saved), `[practice]` (`slow_speed`, Slow motion's speed in percent, 75 or 50, default 75; any other value is a warning and keeps 75; the mod select sheet's 75% / 50% pills write it, `--slow-speed` overrides it for one run and is not saved, #904; see the practice page), `[results]` (`heatmap`, the results page's per-stage death heatmap, default `false`; `--results-heatmap true|false` sets it and is saved; see the results page), `[ghost]` (`pick`: `off`, the default, `pb` or `top`, the ghost the mod sheet's Ghost switch picks; an unknown value is a warning and `off`; ghosts are drawn only and never ranked, drawing them is #64), `[accessibility]` (`shake`, screen shake, default `true`; `flashes`, full-screen flashes, default `true`; the toggles are for players who need them off, so off is the changed state and a file without the table reads both on, #106) and `[bindings]` (kept exactly as written here; `bindings.rs` reads and checks it as `[bindings.keys]` and `[bindings.pad]` and saves its changes through `settings::update`, #541; an old `bindings.toml` is moved in once, see the view page). `main.rs` calls `settings::load` once before anything else (the browser entry, `web.rs`, does the same, [Web](web.md)); a missing file is the defaults; broken TOML, an unknown key, a wrong type or an out-of-range value is a warning on stderr (`warning: settings <path>: ...`) and that entry keeps its default while the rest still counts. A newer `version` warns and reads what it understands. Each module merges its own flags: `screen::configure` (`--fullscreen`, `--ratio`, `--window`), `hud::configure` (`--integer-scale`, `--ui-scale`, `--hud-show`, `--hud-hide`) and `audio::AudioPlugin::new` (`--audio-offset`, `--volume`) write a given flag into the settings, so the next start without it keeps it; F11, F10, F9, F7, `[` / `]` (backdrop blur, 10% a step), Ctrl+=/Ctrl+- and F3 save their choice as they change it. `settings::get()` reads the current values and `settings::update(|s| ...)` changes them and rewrites the file only when something changed (a failed write is a warning; the change still holds for this session); settings screens (phase 5) only call these. A `--screenshot` run neither reads nor writes the file, so checks look the same on every machine and never change the player's settings. Nothing in the file reaches the sim.

## The settings overlay

`settings_screen.rs` (#53; m5 `C1_Settings`, `C2_SettingsAudio`, `C4_SettingsSearch`, `Settings.dc.html`) is the player's way to change these settings: an overlay over any screen outside a run, opened by the main menu's Settings and the toolbar's gear, closed by Escape (which first clears a search) or a click on the dimmed screen. Other screens' keys wait while it is open (`settings_screen::closed` gates the main menu, game select and the shelf).

- **Layout.** At the screen's 1920x1080 UI scale: the screen behind dimmed to 55%, a 72 px section strip (General, Graphics, Audio, Input, Gameplay and HUD; a click jumps to the section's first row, the focused row's section is lit with the accent bar) and the 660 px panel: `Settings`, `Changes apply and save at once`, the search, then the rows by section in a scrolling list (the wheel scrolls; the focused row is kept in view). A row: its label and description, and its control: a switch, a row of sheared choices (picked in the mode's accent; the HUD elements row switches each one), a slider with its value, a value stepped with Left and Right (`‹ ›`), or a value only.
- **Keys.** Up and Down walk the rows, Tab jumps to the next section, Left and Right change the value (or move along the HUD elements' choices), Enter or Space switch or press. Typing goes to the search: every word must be in the label, the description or the section title; Backspace deletes.
- **Updates.** General ends with the updater's rows (#1675, native only): **Update channel**
  (Latest build, Releases; `[updates] channel`; a change checks at once) and **Updates** (the
  running build, the last check's result, and **Check now** or, with a build ready, **Show
  update**). See [updates](updates.md).
- **What changes when.** Every change is saved at once (`settings::update`). At once: display mode, fullscreen ratio and window size (`screen::Screen::set`, the window's size), integer scale and UI scale (`hud::HudOptions`), backdrop blur (`Backdrop::blur`) and the HUD elements (`hud::Shown`). On the next start: the language. From the next game opened: the volumes. The run's own settings (auto-retry, slow motion speed, death map, shake, flashes) are read when a run opens.
- **Not built yet.** The key bindings screen (#52) and the audio calibration (#464) rows only say where they are tracked; the profile name shows but is edited in the settings file; Online (section W, deferred), Streaming (#1577), the frame limit, crash reports and the About notice (B2, group 8) are left out; the controller (LB/RB sections) and the slide-in motion come later; the session panel switch (`[hud.show] session`) joins the Gameplay rows once #1661 lands.
- **Preview.** `--settings-preview <query>` (hidden) opens it at once with that search (`""` for none), e.g. with `--select <folder> --menu-preview top`.
