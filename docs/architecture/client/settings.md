# The client: Settings

Part of [the client](../client.md).

Settings (`settings.rs`): one versioned TOML file, `settings.toml` in the config area of Storage (natively `iwbtg-collection/settings.toml` in the config folder: `%APPDATA%` on Windows, else `$XDG_CONFIG_HOME` or `~/.config`; `$IWBTG_CONFIG_DIR` replaces the whole folder). It holds `version` (1), `[display]` (`fullscreen`, `ratio` as `native` or `W:H`, `window` as `WIDTHxHEIGHT`, `integer_scale`), `[audio]` (`offset_ms`, 0 to 500), `[hud]` (`overlay`, the F3 overlay; `ui_scale`, the HUD side panels' scale in percent, 75 to 150; `[hud.show]`, one `true`/`false` per HUD element: `leaderboard`, `timer`, `deaths`, `stage`, `stage_deaths`, `input`, `mods`, all on by default), `[retry]` (`auto`, auto-retry after every death, default `false`; `--auto-retry` overrides it for one run and is not saved) and `[bindings]` (kept exactly as written here; `bindings.rs` reads and checks it as `[bindings.keys]` and `[bindings.pad]` and saves its changes through `settings::update`, #541; an old `bindings.toml` is moved in once, see the view page). `main.rs` calls `settings::load` once before anything else; a missing file is the defaults; broken TOML, an unknown key, a wrong type or an out-of-range value is a warning on stderr (`warning: settings <path>: ...`) and that entry keeps its default while the rest still counts. A newer `version` warns and reads what it understands. Each module merges its own flags: `screen::configure` (`--fullscreen`, `--ratio`, `--window`), `hud::configure` (`--integer-scale`, `--ui-scale`, `--hud-show`, `--hud-hide`) and `audio::AudioPlugin::new` (`--audio-offset`) write a given flag into the settings, so the next start without it keeps it; F11, F10, F9, F7, Ctrl+=/Ctrl+- and F3 save their choice as they change it. `settings::get()` reads the current values and `settings::update(|s| ...)` changes them and rewrites the file only when something changed (a failed write is a warning; the change still holds for this session); settings screens (M6) only call these. A `--screenshot` run neither reads nor writes the file, so checks look the same on every machine and never change the player's settings. Nothing in the file reaches the sim.
