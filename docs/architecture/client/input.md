# The client: Input

Part of [the client](../client.md).

The device collector and the global bindings: how a key or controller becomes the one `InputFrame` the sim latches (`input.rs`, `bindings.rs`; [replay](../replay.md#actions-and-input-frames)).

- **The collector.** `Collector` derives `held`, `pressed` and `released` from device events between ticks. Edges are per input: a press and a release inside one tick keep both bits, and a second key or pad input bound to an already-held action sets its press bit again while the action stays held. The sim latches the frame and never re-derives an edge; a replay stores the frames. `Collector::take_frame` clears the edges it returns and recomputes `held`, so the pause menu's close (`pause.rs`) drops what was pressed while the menu was open and keeps keys that are still held.
- **Client keys.** `quick-retry`, `skip-cutscene` and `frame-advance` are `ClientKey`s beside the action bindings, not `Action`s: the collector raises a flag for `retry.rs`, `skip.rs` and `practice.rs`, and they never enter an `InputFrame` or a replay.
- **Bindings.** `Bindings` is the one global map: the IWBTG default keys (arrows, Shift jump, Z shoot, R restart, Q suicide, S skip, Enter accept, P pause, M mute, F2 reset) and the default controller inputs (D-pad or left stick move, A jump, X shoot, Y restart, B suicide). Escape and Start open the client's pause menu, so the game's `menu` action has no default key or button (#758, #624) and neither can be bound (#761); the sim's `IWBTG_DEFAULT_KEYS` still maps Escape to `menu` for the research `.inputs` files. An action named in the settings or `--bind` loses its default inputs and gets the listed ones; a broken entry warns and keeps its default.
- **The active controller.** Only the active controller counts, and activity moves only on a **new** button press (`PadReader`, #1014): holding a button on another pad does not take over, and releasing on an inactive pad does not either. If several pads press in the same frame, the active pad keeps priority; otherwise the lowest entity index wins, so the choice is deterministic. A takeover or disconnect resets the stick gates, so a newly active pad's axes must be seen at the centre (press above 0.6, release below 0.3) before a stick counts; that keeps a device with a resting axis, such as a DualSense's motion sensors over Bluetooth, from holding a direction. The same `PadReader` runs natively and in the browser (#474).
