# The client: UI

Part of [the client](../client.md).

The client's screens (game select, mod select, loading, HUD, pause, results) are built with bevy_ui and the kit in `crates/client/src/ui/` ([0003 UI toolkit](../../decisions/0003-ui-toolkit.md) has the options weighed). Screens are built from the phase 6 mockups (`docs/design/mockups/m4/`); every colour, size and shape comes from the kit, never from the screen. Player-visible labels are keys in the locale files ([Locale](locale.md), #196), never literals in a screen or the kit.


**Foundation rules (#1680).** Every screen follows these; the settings overlay is the first built on them (#1681), the others move over in #1684–#1686.

1. **Build once, update in place.** A screen spawns its tree when it opens, or when what it lists changes (a search, the language). A focus move or a value change never respawns the tree.
2. **Focus never moves the layout.** A screen marks the focused part with `focus::Focused`; the part declares how focus looks (`FocusFill`, `FocusRing`, `FocusInk`). The ring is an `Outline` on a plain node or the `Shape` ring on a sheared one: both draw outside the layout box. Never a border, a padding or a size that depends on focus.
3. **Data changes rebuild the smallest part.** A part that shows data keeps it in `live::Live<T>`; `live::refresh` rebuilds that part's children only when the data differs.

- `tokens.rs`: the mockups' colours by name (ground, ink, muted, soft, the creator's light grey over art (`ON_ART`), accent, ahead, behind, gold, amber, ranked, the glass fills, the leaderboard rows and the player card's glass and its solid colour, avatar gradient and progress bar, the results' rules and death bars, the heatmap's red `HEAT` and its room filter values, mixed in sRGB like the card's track), the star ramp (`star_color`: the last step at or below the rating), shear 0.2, radius 10 px and the motion durations by role (`motion::FEEDBACK` 100 ms, `SELECT` 150 ms, `PANEL` 200 ms, `SCREEN` 300 ms, `AMBIENT` 350 ms, `ACCENT` 400 ms OutElastic, and the 3 s pace hold; #1682: every tween takes one of these, never a literal). Artboard alphas (#627): the mockups' CSS blends `rgba(...)` in sRGB, Bevy blends in linear light, so an alpha copied from the CSS covers less (black at 0.5 leaves about 73 % of what is under it, not 50 %). Any translucent colour a screen takes from an artboard goes through the kit: `tokens::black(a)` for shadows and dims (`1 - (1 - a)^2.2`: black over anything comes out as the browser draws it, at most about 8 of 255 sRGB steps darker near black), `tokens::dark(colour, a)` for near-black glass (the same rule; `CARD`, `GLASS` and `ROW` are it precomputed, #713), `tokens::over(colour, a, ground)` for a light or coloured overlay (the alpha that gives the browser's luminance over that ground, `GROUND` for the dark screens; only approximate over other grounds), `tokens::white(a)` for white glass over the backdrop art (#692: `over(WHITE, a, BACKDROP)`, where `tokens::BACKDROP` is the typical blurred, dimmed backdrop measured from the screenshots; the art's brightness varies, so it is exact only there and within about 10 of 255 sRGB steps over the measured backdrops, where the copied alpha was up to 60 too bright; `SECONDARY`, `CHIP`, `SWITCH`, `ROW_YOU`, `ROW_PAST`, `KEY_IDLE`, `BUTTON_IDLE`, the held keys' glows (`KEY_GLOW`, `BUTTON_GLOW`) and the focus ring are it precomputed, the secondary button's hover too), or an opaque colour mixed in sRGB by hand when the ground is fixed (`TRACK`, the results' `RULE` and `BAR` colours). A shape's own layers (veil over its image, band, ring) are mixed in sRGB inside `shape.wgsl` and take the CSS alphas as they are; only what blends with what is behind the node (fill, shadow) needs converting. A blurred shadow converts its peak alpha; the falloff stays the shader's.
- `fonts.rs`: the bundled fonts, compiled into the binary (Barlow, Barlow Condensed, Pixelify Sans for the pause box only, a Noto Sans Symbols 2 subset as the fallback for `★ ▾ ▸ ✓` and heavy arrows, an Inter subset for the basic arrows `← ↑ → ↓` (U+2190–2199, #655) in weights 400, 500, 600 and 700 so arrows in bold text are bold (#720), and a Noto Sans JP subset as the Japanese fallback; all SIL OFL 1.1, licences next to the files in `crates/client/assets/fonts/`). The fallback faces carry Barlow's vertical metrics (ascent 1.0 em, descent 0.2 em, no line gap; `assets/fonts/fallback_metrics.py`, which the subset scripts call): the layout puts a line's baseline by its tallest ascent and descent, so Symbols 2's 0.63 em descent lifted any Barlow line holding a `▾` or `★` by about 0.18 em (2.5 px at 14 px). With the fallbacks inside Barlow's box, every line keeps Barlow's baseline, as in a browser (#546). Pixelify text (ascent 0.92 em) would move if it ever held a fallback glyph; the pause box has none. `Type` is a text style (family, size, weight, italic, tracking in em, capitals) with the mockups' styles as constants (`LABEL`, `STAT`, `BODY`, `BUTTON`, `PRIMARY`, `STARS`, `PILL_CAPS`, `MOD_CODE`, `TITLE`). Every style turns on tabular numerals.
- `shape.rs`, `shape.wgsl`: `Shape` on a node draws it sheared (0.2) with rounded corners while its children stay upright. A shape has a fill and optionally an image (upright, covering the shape, clipped to it), a three-stop veil gradient, a band along the left or bottom edge, an outer ring and a drop shadow. A `ShapeLayer` child, grown past the node's box by the overhang, ring and shadow, draws it with `ShapeMaterial`; `sync_shapes` (PostUpdate, after layout) adds the layer and rewrites the material only when something changed. `UiOpacity` multiplies opacity down the tree; `FadeMask { top, bottom }` fades a list over its top and bottom edges (shapes per pixel, text per line); text spawned through the kit carries its colour in `Ink` so both can apply, and an icon given an `Ink` (its tint) fades the same way. Stacking is plain bevy_ui: a shape's layer draws right after its node and before its children, so a shape in a higher `GlobalZIndex` covers everything below it. The glass fills (`CARD`, `CARD_MID`, `CARD_WARM`) are see-through by design, and because Bevy blends in linear light even `CARD`'s 0.6 % shows white text under it; a shape that floats over other UI uses a solid fill (`CARD_SOLID`, #664).
- `widgets.rs`: `text`, `text_leading` (text with its own line height), `rich` (one line in several styles and colours, as spans; spans do not fade), `ellipsis_text` (one line that ends in `…` where it does not fit its box, CSS `text-overflow: ellipsis`: the box takes its width from its parent and clips; `fit_ellipses` sets the text to the whole line plus `…` for one frame whenever the box width, the UI scale or `Ellipsis::full` changes, then reads that layout's cluster widths from Bevy's parley layout and shows the whole line or its longest prefix that fits with the `…`; Barlow, Barlow Condensed and the fallbacks resolve `…`, `fonts.rs` tests it), `sheared`, `panel`, `pill`, `star_pill`, `mod_pill`, `ranked_pill`, `unranked_pill`, `tag_pill`, `stat`, `button` (Primary, Secondary, Control) and `control` (a Control button with a key and a value, `Sort  Stars ▾`: the key in `CONTROL_KEY`, Barlow 14/400 muted `#a2a8bc`, the value 14/600 ink, `CONTROL_KEY_GAP` 6 px apart, as `Main.dc.html`; an empty key gives a value-only control; its value text carries `ControlValue` so a screen can write the picked value), `control_off` (the same, faded, for a dropdown whose data does not exist yet), `chip(label, on)` (a value-only control that is on or off, `Main.dc.html`'s Cleared and Uncleared: off is dark glass with soft text, on is the `ControlOn` kind's `white(.2)` glass with white text; the screen writes `Chip { on }` and `chip_looks` follows; `chip_off` cannot be picked), `menu_panel` (a dropdown's upright dark card with a shadow over everything, `GlobalZIndex(20)`, holding chips; #150, the artboards draw no open dropdown, `revisit`) and `search_field(placeholder, text)` (`Main.dc.html`'s 48 px sheared glass with the search icon and Barlow 16/400 text: Bevy's `TextInput`/`EditableText` on the `SearchField` entity, which takes the focus when spawned (`AutoFocus`); the muted placeholder shows while the text is empty), each a function returning a bundle; `button_with` makes a button at another size or with other content (the results footer's 48 and 38 px buttons, `Retry  hold R`), `button_off` one that cannot be used yet (faded to 40 %, no hover, focus or `Activate`). `switch(label, hint, on)` is the on/off switch from `ModSelect.dc.html`'s Auto-retry (#558): a 52 px button of kind `Switch` (`tokens::SWITCH` glass, raised from the artboard's `white(.06)` so the control's own boundary clears WCAG 1.4.11's 3:1 against every ground, #1492; 20 px padding, hover lightens it like the secondary button) holding an upright 38×22 px track and 16 px knob, then the label (Barlow 15/700) over the hint (12/400 muted). Off is the artboard's (track `white(.2)`, knob `SOFT` at the left); the artboard has no on state, so on is the kit's accent track with an ink knob slid 16 px right (OutQuint, `QUICK`). `Activate` flips the `Switch { on }` component; a screen that owns the setting reads it on `Changed<Switch>` and writes `on` to set it, and `switch_looks` moves the knob and recolours either way. The gallery shows it off and on; the mod select sheet's footer uses it (#497). `mod_card(code, name, description, colour, on, options)` is a mod select card (`ModSelect.dc.html`): 70 px, sheared, a 48×44 code tile (radius 9), the name (17/700) over the description (13/400) and option pills at the right end (upright, 24 px, radius 6; the picked one `white(.18)`). Off it is `white(.05)` glass over the sheet (`over(WHITE, a, CARD_SOLID)`) with a `white(.1)` tile; on, the column colour at .22 with a 2 px ring (outside the shape; the artboard's is inset) and a solid tile with dark ink. A click, Enter or Space sends `Activate`; the screen writes `ModCard::on` and `ModOption::on`, and `mod_card_looks` recolours, lightens on hover, scales on press and draws the focus ring. `mod_card_off` is the faded card of a mod that cannot be picked yet; `selected_mod_pill(code, colour)` the footer's picked mod (32 px, at least 48 wide, Condensed 17/700). The gallery shows a picked card and pill under the pills. Buttons are `bevy_ui_widgets::Button` (click, Enter or Space sends `Activate`) with Tab navigation; hover lightens the fill, press darkens it and scales to 0.96 (OutQuint, 150 ms), and keyboard focus adds a 2 px white ring.
- `latency.rs`: `UiLatency`, the UI's answer time (#1683): every frame in which a key, mouse button or gamepad button went down, the main thread's time for that frame (`First` to `Last`; the pipelined render is not counted) is recorded; the last and the worst of the last second show in the F3 overlay in a run and in a bottom-left readout outside one (the `hud.overlay` setting; never in a `--screenshot` check). `node_set` (tests only) lists every UI node, so a screen's test can show a key press spawned or despawned none (UI foundation, #1680).
- `focus.rs`: `Focused` and the declared focus looks (`FocusFill`, `FocusRing`, `FocusInk`; `focus::ring` for a plain node, `focus::shape_ring` for a sheared one), applied by one PostUpdate system on `Changed<Focused>` (foundation rule 2).
- `live.rs`: `Live<T>` and `refresh(world, entity, &data, build)`: rebuilds a part's children only when its data changed (foundation rule 3).
- `motion.rs`: `Ease::OutQuint`, `Ease::OutElastic` and `Ease::OutExpo` (the main menu's slides); `Tween<P>` drives `OffsetX`, `OffsetY`, `Scale` (`UiTransform`, so layout does not move), `Width` (`Node::width`) or `Opacity` (`UiOpacity`) and can be retargeted from wherever it is. `ReducedMotion` (`--reduced-motion`) makes every tween land at once.
- `live.rs`: `Live<T>` and `refresh(world, entity, &data, build)`: rebuilds a part's children only when its data changed (`queue_refresh` does the same from a system with `Commands`) (foundation rule 3).
- `latency.rs`: `UiLatency`, the UI's answer time (#1683): every frame in which a key, mouse button or gamepad button went down, the main thread's time for that frame (`First` to `Last`; the pipelined render is not counted) is recorded; the last and the worst of the last second show in the F3 overlay in a run and in a bottom-left readout outside one (the `hud.overlay` setting; never in a `--screenshot` check). `node_set` (tests only) lists every UI node, so a screen's test can show a key press spawned or despawned none (UI foundation, #1680).
- `motion.rs`: `Ease::OutQuint`, `Ease::OutElastic` and `Ease::OutExpo` (the main menu's slides); `Tween<P>` drives `OffsetX`, `OffsetY`, `Scale` (`UiTransform`, so layout does not move), `Width` and `Height` (`Node::width`, `Node::height`) or `Opacity` (`UiOpacity`) and can be retargeted from wherever it is. `ReducedMotion` (`--reduced-motion`) makes every tween land at once.
- `mode.rs`: `Mode` (Time Attack, Classic; m5 A1, A2), the play mode the player picked on the main menu or in the toolbar, and its accent (`Mode::accent`: cherry `tokens::ACCENT` or violet `tokens::CLASSIC`). `button_looks` paints Primary buttons and their glow in the mode's accent, so every screen's primary action follows the mode (#1608).
- `hints.rs`: `hints(&[(glyph, label)])`, the key hint bar (m5 `Hints.dc.html`): controller faces A, B, X, Y as round light discs, every other key a keycap with a dark lip, 22 px apart, 15/600 labels. Screens pass keyboard keys until the last device is tracked (#117).
- `toolbar.rs`: `toolbar(mode)`, the 56 px bar across the top of every screen outside a run (m5 `Toolbar.dc.html`, B8): the mode switch (`ModeTab`: a click, Enter or Space sets `Mode`; the picked tab is ink at 700 with its accent icon and a 3 px line under it), then the Update pill (hidden until the updater has a verified build, `UpdateSlot`, #1675), the clock and session time (from 1600 px wide), the bell, the gear and `Sign in` (`ToolbarButton`). No Home button. Until their parts exist there is no "now playing", no badge, and the bell, gear and Sign in do nothing (notifications m5 D2, settings #53, accounts #159).
- `filter.rs` (+ `filter.wgsl`): `filter::filtered(materials, image, saturate, brightness)` gives a `MaterialNode<FilterMaterial>` that draws a picture stretched over its node as CSS `filter: saturate(s) brightness(b)` does (on sRGB values, the Filter Effects saturate matrix, then a multiply), cut to the node's own corner radius (bevy_ui clips overflow to a rectangle, so a parent's radius does not round a child picture). An `ImageNode` tint only multiplies, so it cannot take colour out. It runs on the GPU, so it works on render targets (the results heatmap's room, #705) on native and wasm32.
- `backdrop.rs` (+ `backdrop.wgsl`): the one background behind every screen. Screens set the `Backdrop` resource (art handle, blur 0 to 1, dim from `backdrop::dim`: select 0.38, loading 0.55, gameplay 0.45, results 0.62) and never draw their own. A camera of its own (`BackdropCamera`, order -100) draws two full-window layers with `BackdropMaterial`; cameras over it use `ClearColorConfig::None`. `art_image` builds an image with its mip chain; the shader covers the window with the art (never stretched) and blurs by sampling the mip level that matches the radius (blur 1 is the mockups' 40 px at 1600 px wide), so the slider is smooth and cheap. A new art cross-fades over 300 ms (`motion::SCREEN`, OutQuint; at once with reduced motion). `key_art_image` turns `iwbtg_format::key_art::resolve` into art (package key art, else the first ranked room's first back layer, or its colour, else the client's own dusk scene; under `--mods NB` a room background or colour becomes plain grey, see the visual page). A back layer (`KeyArt::RoomBackground(RoomLayer)`: path, `stretch`, `tile`, `offset`, room colour; #601) is composed by `compose_layer` over the room's size the way `art.rs` draws it: it uses art.rs's `axis` cutting, so a stretched layer fills the room, a one-axis-tiled layer repeats only on that axis and leaves the room colour elsewhere, and the offset moves the first copy (the layer's start position; scrolling is ignored). `screen.rs` sets it from the package when the game opens.
- `icons.rs`: `Icon` (the stat marks, search, back, random, music bars, the input arrow, person, the toolbar's mode, bell, gear and sign-in marks and the main menu's nine button icons; text arrows such as `→` come from the fonts) and `icon(Icon, height, colour)`. The mockups' SVG paths are rasterised with tiny-skia at the node's laid-out pixel size and tinted by the node's colour, so icons are crisp at any scale on native and wasm32. `widgets::stat` takes an optional icon.
- `glow.rs`: `Glow { color, blur }` and `glowing(glow, content)`: a soft glow under an icon or a line of text, the mockups' `drop-shadow(0 0 <blur> ...)` and `text-shadow: 0 0 <blur> ...` (#616; the held keys of the HUD's input display). The wrapper takes the content's size; `sync_glows` (PostUpdate, after layout, before `sync_shapes`) gives it a `GlowLayer` child under the content (first child, `ZIndex(-1)`) that reaches 1.5 blur radii past the box (three deviations; CSS's deviation is half the blur radius) and draws the content's own shape blurred into the layer's image at physical pixels: an icon's paths through tiny-skia (`icons::draw`), a text's glyphs copied from the font atlas (`TextLayoutInfo`; the atlases keep their pixels in the main world). The image is redrawn only when the content's size, glyphs or scale change (icon glows are cached and shared); turning a glow on and off is only its colour (`Color::NONE` for off), so a display that changes every frame costs no rasterising. The colour goes through `Ink`, so `UiOpacity` and `FadeMask` apply. Peak alphas come from the artboard through `tokens::white` (`KEY_GLOW`, `BUTTON_GLOW`). Same on native and wasm32: CPU only, no shader. Put a rotation on the wrapper, not the content, so the glow turns with it.
- `notice.rs`: notices (m5 D2, D3), short cards that outside a run drop in under the toolbar's bell (top right, 350 ms OutQuint, `motion::AMBIENT`) and in a run slide in at the bottom of the leaderboard's column (OutQuint, 400 ms), stay 6 s (real time, so a pause does not hold them) and fade out. `notice::post(Kind, message)` queues one from anywhere, any thread, even before the app exists (settings load first); the kit's `notice` system shows queued ones on the next frame. A `Kind` gives the heading (capitals, in the kind's tone with its icon: `Kind::tone`, `Kind::icon`: amber for storage, red for a file that did not open, blue for controller and controls), the body (soft ink, wrapped, cut at 100 characters with `…`) and whether it shows once per session (`Shown`): storage problems show once (`storage::warn`, #566); a dropped file that does not open (`Kind::Drop`, "NOT OPENED", #648) shows every time, with the file's name and why (`import.rs` writes the text); a controller the browser does not map (`Kind::Pad`, "CONTROLLER", web only, #717) shows once, with a fixed text; a game whose package labels extra actions shows the line from `controls::extra_actions_notice` (`Kind::Controls`, "CONTROLS", #52) each time it loads. The card is the player card's colour without its glass (`tokens::CARD_SOLID`) with a 4 px band in the kind's tone on the left, a 2 px bar under the message that runs down over the 6 s, and a drop shadow, over the HUD and the pause overlay (`GlobalZIndex(30)`). The HUD sets `notice::Area` to the leaderboard's column, so a notice stays off the game; its stack is that column less a 12 px margin each side, and each card leaves 12 px each side for its shear, so the card, its shear and its shadow stay inside the column at 16:9 and 4:3 (#668). The stack is 180 to 340 UI px wide: 180 is the narrowest leaderboard column outside a small window (`hud::layout::MIN_LEFT`, 204) less the margins, which a HUD test keeps true. Only a small window (960x540) has a narrower column; there the card reaches over the game's edge rather than wrap word by word. `--notice-preview [storage|drop|list]` (hidden, after the package path) posts a sample notice of that kind for screenshots (`storage` when no kind is given; `list` posts one of each and opens the bell's list).
- `notifications.rs`: the bell's list (m5 D2). Every notice also goes into `Notifications` (this session, newest first). The bell shows a red badge with the count since the list was last opened; a click on it opens the 460 px panel on the right under the toolbar (the screen beneath dimmed to 35%): `Notifications`, `Clear all`, `Today` and each notification with its kind's icon tile, heading, time and message. Escape, the bell or a click outside closes it. A row whose kind opens something (`Kind::opens`: the update-ready notification, `Kind::UpdateReady`, #1675) has an edge in its tone and takes clicks: it closes the list and triggers `notice::Opened { kind }`, which the owner observes (the updater shows its dialog). The In progress part (downloads, uploads) waits for a producer (online phase).
- `gallery.rs`: `iwbtg-client --ui-gallery [--screenshot <png>] [--reduced-motion] [--window WxH] [--ratio W:H]` shows every token and component at the mockups' 1920×1080, scaled to fit the window (`UiScale`; `--window` sets an exact size in physical pixels, `--ratio` alone makes a 1600-wide window of that ratio, so screenshots come out at the size asked for), for comparing with the canvas: hover a game panel and it slides 25 px left, Pop and Fade run the OutElastic and OutQuint tweens, Tab shows the focus ring, M toggles reduced motion. Its panel art is drawn at run time. The layout fits 1920×1080 with nothing clipped (#770): the left column holds the tokens, type, star ramp, pills beside the ellipsis samples, buttons and icons (one row, 8 px apart); Stats close the right column. A new section goes where the column still has room, so check a 1920×1080 `--screenshot` after adding one. The Control buttons sit on an upright art `Shape` with 14 px padding: an `ImageNode` draws its image inside its padding, so it cannot show art around its children (#546). The wasm32 build opens the gallery directly ([dev-setup](../../dev-setup.md#ui-gallery-in-a-browser)).
- **Japanese text and line breaking (#502, #734).** The fallback face is in `fonts.rs`. Line breaking needs no extra data: bevy_text builds parley without its `complex-scripts` feature, so the line breaker is the UAX #14 rule segmenter and a Japanese run breaks between any two characters, as browsers do. The dictionaries that feature would add are used by one thing the client does have: Bevy's `EditableText` moves and selects by visual word (Ctrl/Alt+arrow, double-click), and the game select's search field is one; without the dictionaries a whole Japanese run counts as one word there. [0003](../../decisions/0003-ui-toolkit.md) (Japanese text) keeps them off — the CJK data is a size cost on native and wasm32, and the case needs Japanese pasted or typed into one field — so revisit only if players report it or a screenshot shows wrapped Japanese breaking badly. The notice `ICU4X data error: No segmentation model for complex script: Chinese/Japanese` is `icu_segmenter` reporting that absent model: it builds an `icu_provider` `DataError`, which `DataError::with_display_context` reports. `crates/client/Cargo.toml` turns on `icu_provider`'s `logging` feature so that report is a `log` record with target `icu_provider::error` that Bevy's `LogPlugin` forwards to tracing; with the feature off it was an `eprintln!` in debug builds only, which no log filter could drop. `logging::log_plugin` adds `icu_provider::error=off` to Bevy's own filter, and every app the client opens (the normal run and `--select` in `view.rs`, `--ui-gallery`, `--card-preview`) uses it. The directive is target-wide: it hides every ICU4X data error, not this message alone, which is acceptable because all ICU4X data here is baked in at compile time and cannot fail at run time; a message-scoped filter would need a `custom_layer` for one line.
