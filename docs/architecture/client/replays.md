# The client: Replays

Part of [the client](../client.md).

Replays (`replays.rs`, `ReplaysPlugin`, #476): every run is recorded as an `.iwbr` replay ([replay format](../replay.md#replay-file-iwbr)) in the data area of Storage, for the replay viewer and upload (phase 7). A run is one sim: the client's start, and each quick-retry or auto-retry. `view::tick` hands the `Recorder` each tick's input frame and splits; the header comes from the sim's options and the package (id, `gameplay_hash` from `package::open`, `engine_rev`, seed, start: `NewGame`, or `FromSave` with the postcard bytes of the resumed save slot, play mode, `Sim::map_id`, the run's mods (the `mods::RunMods` it opened with, so the mod select sheet's picks, #903), `iwbtg-client <version>`). Checkpoints are taken every 500 ticks. The trailer's pauses are the pause menu's (`pause::Menu::pauses`, #623): `replays::sync_pauses` hands them to the `Recorder` (`Recorder::set_pauses`) on the fixed clock before every sim tick, so the clear's write has them, and a retry (`replays::reset`, which runs before `pause::reset` clears them) and the window closing hand them over before the last write; a new run starts with none. The file is written when the run's timer ends (a ranked run's replay stops there; Play original keeps recording into the same file, so one Play original session until a retry is one replay), when a retry starts the next run (`replays::reset`, before the new sim replaces the old) and when the window closes (`Last`, after Bevy's exit check, while the sim is still there). Each write prints `replay: <path> (<ticks> ticks, <bytes> bytes) hash <final state hash>`; `iwbtg replay verify <pkg> <file>` prints the same hash. The data write and the index write are tracked separately (#1012): a recording is `stored` once its bytes are on disk and `listed` only after `replays/index.txt` has been written. A failed index write keeps the name pending on the `Recorder` across `finish`, and every later write retries it even when the run's data is clean; `replays::list` drops any existing copy of the name first, so a retry never lists it twice. Names are `replays/<game id>/<unix seconds>-<n>.iwbr`, listed oldest first in `replays/index.txt` (browser storage cannot list its entries); natively every replay is kept, on the web only the newest 50 (an hour's replay is a few KB) plus the ones a stats board points at. A cleared run on a stats board points at its replay. Web pruning (#607, `replays::to_remove`) runs when a new replay is first listed: it reads `stats.toml` and, while more than 50 are listed, removes first the oldest replays no board run points at, then the oldest replays of top runs that are not a PB. A board's PB replay and the replay just written are never removed, so when the boards' top runs alone exceed 50, the older top runs lose their replays (their `replay` entry then names a missing file); more than 50 stay only when there are 50 or more PB replays. An unreadable `stats.toml` removes nothing that time. When a web replay write itself fails because `localStorage` is full, `replays::recover_quota` makes room instead of giving up (#1013): it removes eligible older replays one at a time in the pruning order above (oldest no board points at first, then the oldest top runs that are not a PB), retries the write after each removal and is bounded by the index. A PB's replay, the replay being written and every replay when `stats.toml` cannot be read (#607) are never removed; the evicted names leave the index, and the normal first-time listing adds the new replay. Seeds: every run (and every retry) draws a new random seed (`replays::fresh_seed`: the OS-keyed `RandomState` and the clock natively, `Math.random` on the web), as the originals randomize; a `--screenshot` check keeps seed 0 and records nothing. `--ranked` plays the ranked (stripped) mode: always a new game, never the save file (it implies `--no-save-file`); without it the client plays Play original.
