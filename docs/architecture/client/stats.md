# The client: Stats

Part of [the client](../client.md).

Stats (`stats/`, #40): the local stats, one versioned TOML file `stats.toml` in the data area of Storage, written only by this module; the screens (results, live leaderboard, player card, game select) read the `Stats` resource. The book holds, per map, keyed `<game id>/<map id>` (map ids are only unique within a game; `Sim::map_id`, `main` for a package without `[[maps]]`): the game, its tick rate, clears, deaths, deaths per segment, ticks and seconds played, and boards keyed `<mode>/<mods>` (`ranked/NM`, `original/SD`; mods as `ModSet::codes`). A board keeps its clear count, your top 100 runs fastest first (ties: earlier run first; the first is the PB) and the best time of each segment (gold), whose sum is the sum of best. A run is its time as the HUD showed it: ranked time (`Sim::ranked_ticks`, #34) plus the ticks the timer ran in the pause menu (`pause::Menu::paused_ticks`, #623), deaths, that time at the end of each segment (so a split counts only the pauses before it) (a game with `n` stages has `n + 1` segments: start to stage 1, ..., stage `n` to end), deaths per segment, its finish date, its replay (`replay = "replays/<game id>/<name>.iwbr"`, absent for runs from before #476) and its death log (#679, file version 2): each death's run time, room and kid position, for the results' death timeline and per-stage heatmap (#654). The log is a `death_log` table of parallel lists (`ticks`, `room_names` once per room, `rooms` as indexes into them, `x`, `y` in whole pixels), so 1,000 deaths cost a few kilobytes; the first `segment_deaths[0]` entries are segment 0 and so on. A death's time and spot are the kid's last sighting alive before the counter went up (the death itself, not the R that counts it; an R while alive logs where the kid stood, not the new kid at the save); a death before any kid was seen has no spot (`rooms` holds `u32::MAX`). Only a board's fastest 10 runs (`DEATH_LOG_RUNS`) keep their log; a run pushed below drops it. Runs from version 1 files load with an empty log. The results screen reads a run's deaths with `Run::death_marks()` (time, segment, room and position per death); the segment boundaries are `Run::splits`. After every tick `stats::watch` (FixedUpdate, after the sim's tick) reads the tick, the death counter, the timing state and the kid's room and position (read only; the sim's state is never touched) into a tracker (`stats/track.rs`): a death counts in the segment the run is in (before the timer starts: the first), and the `end` trigger records the run. Only a run started as a new game goes on a board; a clear from a save counts as a clear only. Play original runs go on `original/...` boards: personal stats only, never uploaded (docs/product.md, Modes). Deaths per segment for this session are kept in memory only. Account totals (games with a cleared map, deaths, clears, play time) are summed over the maps. A clear prints one line (`stats: cleared in 0:04.20 (0 deaths): PB 0:04.00 (+0:00.20), #2 of your runs, 1 gold segment(s), sum of best 0:03.80`) and writes the file; deaths and play time are written on a retry, every 30 s and when the window closes. An unreadable file or one from a newer build is copied to `stats.broken.toml` with a warning and the session starts an empty book, so nothing is overwritten. A `--screenshot` run reads and writes no stats.
