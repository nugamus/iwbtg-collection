# The client: Particles

Part of [the client](../client.md).

Particles (`particles/`, `ParticlesPlugin`, #815) draw the systems that [`particle_system`](../../format/builtins/particle_system.md) instances build from `particles/<id>.toml` ([format](../../format/particles.md)). The sim keeps only what decides its RNG draws (`World::particles`: types' draw ranges, emitters' regions and streams, `destroyed` flags), never positions or looks, so the client keeps its own drawing copy of each system. It only reads the sim and draws from its own generator, so following it never changes a tick, a replay or the state hash (test `particles::tests::following_the_sim_never_changes_it`).

- **Following the sim** (`mod.rs`, `Tracker::follow`, in `FixedUpdate` after `view::tick`). Each sim system that a `particle_system` instance built (one per file of its `system` list) is built as the sim's Create builds it (`model::DrawSystem::build`: each emitter's burst, then the creates), from the `PartSystemDef` the sim noted for it in `World::particle_defs` (not hashed, #866; so a system is drawn even when its instance is gone before the client looks) and a fixed seed per system, so a screenshot looks the same every run. `destroy` and `destroy_emitters` are read from the sim's state, so they are exact. `clear` is too: the sim counts each `clear` call per system in `World::particle_clears` (not hashed, #883), and a drawing copy whose count moved since the client last looked is cleared (a new copy starts at 0, so a clear on the tick that built it counts; several clears in one tick are one). So the clears of an instance gone before the client saw it (one that destroys itself in the first room's Room Start, or in a room entered on that tick) are followed as well. One particle update runs per tick, none on a tick that entered a room (the sim skips it on a room request tick, CLONE_SPEC numbers "Particle draw rules" 9; the first room's start runs in `Sim::new`, and its room-entry output stays in the first step's output, #466, so it does not count as an entry on that tick). A sim that went back in time (a retry builds a new one) starts the copies over. A particles-mode `blood_emitter` system (#766) is not drawn here.
- **The particles** (`model.rs`). Building picks each type's `{ random = [min, max] }` alpha values first, one per system (`DrawSystem::alpha`). Each particle has a position, speed, direction, size, orientation, life and, for `color_mix`, `color_rgb` and `color_hsv`, a color fixed at birth. An update ages every particle (death particles where one dies, step particles where one lives), moves it, then each streaming emitter makes its particles in emitter order. Counts follow the spec: `n > 0` makes `n`, `n < 0` one with chance `1 / (|n| + 1)` (items 3 and 8). Region points use the sim's own region rule (`Region::draw_point`) on our generator, scaled to the emitter's rectangle.
- **OPEN** (not in the spec; choices of ours, to replace when a spec item covers them): wiggle is a sine of a 16-tick period with a random phase; speed and size never go below 0; gravity is added to the motion after the speed and direction increments and stays in it; colors and alpha blend evenly over the life (two values start to end, three through the middle); the built-in shapes (`shapes.rs`) are our own 64 px pictures drawn in code from the shape names (`pixel` is one pixel), not GM's images. Which draw sets which value is not in the spec either (item 6), so the particles on screen are where a particle of that system could be, not where the original's are.
- **Drawing** (`draw.rs`, in `Update` after the instances). One 2D mesh per system, picture (shape or package sprite) and blend, one quad per particle tinted by its color and alpha, sized by size times the type's scale, turned by its angle, on its sprite frame (`animate`, `stretch`, `random`). Additive types (`additive = true`, `bm_add`) use a material with an additive blend. The meshes are rebuilt only when the tracker's `generation` changes. Each sits at its own system's depth (`Tracker::depth`, the file's `depth`, so the systems of one `system` list draw at their own depths) after every instance of that depth (`order::Ladder::depth_z`), between the tile layers like the instances ([view](view.md)).
- **Limits.** With `NumRules::particles_draw_rng` off the sim builds no systems, so nothing is drawn (on in every engine_rev so far). No interpolation: particles move once a tick.

The showcase (`crates/client/showcase.pkg`, [view](view.md)) shows it: fireflies in the courtyard, and snow and brazier embers on the summit (each system destroyed at Room End). The test fixture `crates/client/tests/fixtures/particles.pkg` has snow over the room behind the blocks (a burst of 120 when built, then a stream), a fountain of additive sparks with ember death particles over the middle block, and a burst of stars: `cargo run -p iwbtg-client -- crates/client/tests/fixtures/particles.pkg --mute`. Tests: `cargo test -p iwbtg-client particles::`.
