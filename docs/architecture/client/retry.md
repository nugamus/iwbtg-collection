# The client: Retry

Part of [the client](../client.md).

Retry (`retry.rs`, `RetryPlugin`, #38): the quick-retry key (bound as `quick-retry` with the other bindings, Backquote by default, controller input optional; the collector sets a client-key flag that `retry::key` takes each frame, and `key_action` never maps it, so it is never a sim `Action`, never in an `InputFrame` and never in a replay) and, with auto-retry on, any tick that raises the death counter set a pending retry. While one is pending the `SimTick` set does not run, so no tick follows the death. In `Update` the exclusive `apply` system calls `view::restart_run`, which builds a new `Sim` from the `RunStart` resource (the definition and `SimOptions` the window opened with, so a run started from a save restarts from that save), despawns every drawn sprite, clears interpolation history, pending input edges (held keys stay held) and the sign; then `audio::reset` stops every voice and clears the cue queue, mixer memory and shake (the new room start plays from the first step's output), `mods::reset` clears Sudden Death's run-over state and banner, and `pause::reset` closes the pause menu and forgets the run's pauses. The pause menu's Restart run asks for the same retry (`retry::request`). The terminal prints `retry: run restarted (quick-retry)` or `(auto-retry)`. Auto-retry is the settings file's `[retry] auto` (default false); `--auto-retry` forces it on for one run and `--auto-retry=false` off, and neither is saved. The bottom-bar toggle is #558.
