# The client: Script error screen

Part of [the client](../client.md).

The script error screen (`script_error/`, #101) keeps format principle 3 (docs/format/README.md): a script error stops that game, never the client.

- **When.** A system in `RunScreen::Playing` watches the sim's status. When the sim halts (`SimStatus::Halted`: a script error, or a case the sim refuses to guess such as `unsupported`), the run goes to `RunScreen::Error` ([shell](shell.md)). The sim ticks only in `Playing`, so the frozen game stays where it stopped. The halt is also printed to the terminal (`the game stopped: ...`). An error in the very first tick (a Create of the start room, run while `view::new_run` builds the sim) is this screen too (#946): `view::new_run` and `view::restart_run` build the sim with `Sim::new_or_halted`, so the run opens with a sim halted at tick 0, shows the loading card as usual, and goes to `Error` on the first frame of `Playing`. Retry builds it again and the screen opens again. Only a game that cannot be set up (a package that does not open, a missing map, scripts that do not compile) is still a `shell::StartError`.
- **What it says.** `Report::new` reads the halt. A script error's message is the script host's (`<file>: <what> (line L, position P) [kind K, instance I, <event>, tick T]`); the report splits out the file (`scripts/boss.rhai`), the line and column, the message, and the bracket as context (`kind @boss · instance 100089 · Alarm(0) · tick 24`). Whatever is missing is left out; another halt reads `The game stopped` with the sim's words.
- **Look.** No artboard draws this screen, so it is the [loading card](loading.md)'s look built from the [UI](ui.md) kit (`script_error/page.rs` reuses `loading::page::strip` and `glass`): the key art strip with the title and creator, then the accent `SCRIPT ERROR` pill and the place, the message (24 px, wraps), the context and a line saying the game stopped and nothing else did. Under the card: `Esc back` (or `Esc quit`), Retry (Secondary) and the Primary `Back to game select` (or `Quit` when the client was started on one package). `OnEnter` hides the game camera and the HUD and sets the loading dim (`shell::cover_game`); `OnExit` undoes them. The layout is a default to revisit (#101).
- **Keys.** Escape, Enter (no button focused) and Start pick Back: `shell::leave`, so back to game select with `--select`, else the client exits. Retry, or the quick-retry key, starts the run again (`retry::request`; `script_error::reset` closes the screen, back to `Playing`).
- **Preview.** `--script-error-preview` (hidden) opens the screen on the first frame of play with the `script_error.pkg` fixture's error, for `--screenshot` checks.
- **Test.** `crates/client/tests/fixtures/script_error.pkg` is the clear fixture with a scripted `@boss` whose alarm reads past an array half a second in. `shell::tests::a_script_error_stops_the_game_and_goes_back_to_select` plays it headless: the screen opens with `scripts/boss.rhai`, line 9 and the message, no tick runs while it shows, the HUD is hidden, Escape goes to game select, and another package then plays. `retry_on_the_script_error_screen_plays_again` checks Retry. `crates/client/tests/fixtures/start_error.pkg` is the same with a `@boss` whose Create reads past its array, so the sim halts in the start room: `a_first_tick_script_error_opens_the_error_screen_from_select` (the screen opens with line 5 at tick 0, Retry shows it again, Escape goes to game select) and `..._from_the_command_line` (the package loaded as `main` does: the loading card, then the screen, Back quits) cover both launch paths. `script_error::tests` covers the report's parsing, the card's words and the keys.
