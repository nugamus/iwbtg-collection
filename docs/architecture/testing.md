# Testing strategy

Part of [Architecture](../architecture.md).


| Layer | What | Where | When |
|---|---|---|---|
| Unit tests | `num` (rounding, comparisons, trig table), `rng`, motion coupling, masks and bounding boxes, collision queries, input edges, replay round trip | `crates/sim`, `crates/format` | every `cargo test` |
| Script conformance | Every IWS math function over 10,000 fixed inputs, every operator and overload, operation-count fixtures | `crates/sim/tests/script_conformance/` (hashes pinned in `expected.txt`; `UPDATE_CONFORMANCE=1` rewrites) | every CI target |
| Engine test rooms | Small worlds we make ourselves (no creator content, built with `GameDefBuilder`), one pinned state hash per case in `expected.txt`. Probe cases, one kid course per kid family (A1 to C) plus one for param variants (`golden/courses.rs`: engine kinds, a floor, warps and a group of built-ins under a scripted input of runs, jumps, shots and retries) and a script API case whose scripts call every function and property of the script API. After the case lines, `expected.txt` names per built-in and per kid family the first case that had a live instance of it (`builtin <name> <case>`, `family <name> <case>`); `golden_corpus.rs` fails when one names no case (only `inert`, a trace-mode kind, is allow-listed) or when a script API name from `docs/format/script/iws.d.rhai` is missing from the golden scripts (#786). Running is not touching, so `expected.txt` then has one `touched <name> <case>` line per built-in with a collision handler between it and the kid or a kid bullet (on either side), naming the first case where the two met in the collision phase (#847). The harness sees that from outside: it runs the ticks with `Hooks::ENGINE` except for an `overlaps` hook that returns the engine's result and notes the pairs that met, so sim state, hash and RNG are untouched. `golden_corpus.rs` fails on a `touched <name> -` line unless the built-in is in `UNTOUCHED_BUILTINS` with its reason (only `game_clear`: touching it ends the run). Many built-ins get their own kid, kid bullet or blood handler only under a param (`vanish_on = "touch"`, `on_shot`, `destroys_bullets`, `start_on_touch`, ...), so each such own handler of a built-in also gets a `touched <name>/<handler classes> <case>` line (for example `touched save/kid_bullet kid_param_variants`), counted per handler, not per param: two params that add the same handler share a line (#898). The `kid_param_variants` course places every such variant where the kid, a bullet (its `block_check` is `collision_destroy` there) or blood meets it; the allow-list entry of a built-in covers its handler lines too. Built-ins the kid finds by query rather than by a collision event (`vine`, `slope`, `ladder`) get no line. A new built-in or family goes into a course in the same PR. A deliberate sim change re-pins it: `cargo xtask repin` | `crates/sim/tests/golden/` | every CI target |
| Validator fixtures | A set of broken packages, each expecting one specific error with file, line and column (and every `valid/` package must pass the full load, as `pkg check` does, with no warnings) | `crates/format/tests/invalid/` | every `cargo test` |
| Client package fixtures | Small original packages, one feature each (`input`, `audio`, `save`, `particles`, `clear`, `maps`: three maps and its own key art for game select), that the client's unit tests open; placeholder art, not for testers, who play `crates/client/showcase.pkg` (#852). Change a fixture only with the tests that read it | `crates/client/tests/fixtures/` | every `cargo test` |
| Trace tests | Every research trace case, run and diffed bit for bit | research path given by the `IWBTG_RESEARCH` environment variable; skipped when absent | locally: `cargo xtask fidelity` after each merge wave (below), before ranking a game |
| Replay corpus | Each ported game's full-clear replay, plus every stored leaderboard replay once Phase 8 exists | games repo, server | every sim change |
| Cross-platform equality | `iwbtg determinism report` on golden rooms, conformance suite and replay corpus on `x86_64-pc-windows-msvc`, `x86_64-unknown-linux-gnu`, `wasm32-wasip1` under wasmtime and `wasm32-unknown-unknown` through wasm-bindgen-test in Node. A final job requires all hash lists to be byte-identical. | GitHub Actions matrix | every PR touching `sim` or `format` |
| Fuzzing | Replay decoder, package loader, script host | `cargo-fuzz`, native | nightly |
| Budget and speed | Peak script units under 25% of the budget; benchmarks of the Rori Girl and Easy Miku 2 avoidances and a 28,900-instance load, native and WASM | `iwbtg profile`, `cargo bench` | CI, early in Phase 3 |
| Lints | `cargo clippy -D warnings` with the sim bans, `cargo deny check`, `cargo fmt --check` | CI | every PR |

## CI and the fidelity sweep

CI is public and sees only this repo: everything in the table above except the trace tests and the replay corpus, which need the private research and games repos (`wp2_traces.rs` skips without `IWBTG_RESEARCH`, and CI never sets it). So CI proves the sim is deterministic and matches its own pinned hashes, not that it still matches the original games.

`cargo xtask fidelity` closes that gap on the home PC (#785). With `IWBTG_RESEARCH` set, it runs `iwbtg trace sweep`: one process that loads every package folder in `$IWBTG_RESEARCH/build/packages` and runs every case of `crates/tools/cases/<package id>/` against it (packages in parallel, through the same `check_case` as `iwbtg trace check`). It prints one row per game with its OK / OPEN / FAIL counts (`-` when the game has no cases yet), one line per case that is not OK with its reason, and a summary line. FAIL covers a difference, an error, a panic and a cases folder whose package is missing or does not load. Every status is compared with `crates/tools/fidelity-baseline.txt` (`<game>/<case> <STATUS>` lines: names and statuses only, no private data); a case that got worse (OK to OPEN or FAIL, OPEN to FAIL) or a new case that fails is a regression, and the command exits 1. Improvements and new passing cases are listed as changes but pass; `cargo xtask fidelity --bless` rewrites the baseline, committed in the PR that caused the change. The lead runs it after each merge wave (CLAUDE.md, Agent teams).

The roadmap Phase 3 check is the trace-test row plus the cross-platform row: the Phase 2 inputs reproduce the original traces exactly on Windows, WASM and Linux x86_64.
