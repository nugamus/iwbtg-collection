# Testing strategy

Part of [Architecture](../architecture.md).


| Layer | What | Where | When |
|---|---|---|---|
| Unit tests | `num` (rounding, comparisons, trig table), `rng`, motion coupling, masks and bounding boxes, collision queries, input edges, replay round trip | `crates/sim`, `crates/format` | every `cargo test` |
| Script conformance | Every IWS math function over 10,000 fixed inputs, every operator and overload, operation-count fixtures | `crates/sim/tests/script_conformance/` (hashes pinned in `expected.txt`; `UPDATE_CONFORMANCE=1` rewrites) | every CI target |
| Engine test rooms | Small worlds we make ourselves (no creator content, built with `GameDefBuilder`), one pinned state hash per case in `expected.txt`. Probe cases, one kid course per kid family (A1 to C) plus one for param variants (`golden/courses.rs`: engine kinds, a floor, warps and a group of built-ins under a scripted input of runs, jumps, shots and retries) and a script API case whose scripts call every function and property of the script API. After the case lines, `expected.txt` names per built-in and per kid family the first case that had a live instance of it (`builtin <name> <case>`, `family <name> <case>`); `golden_corpus.rs` fails when one names no case (only `inert`, a trace-mode kind, is allow-listed) or when a script API name from `docs/format/script/iws.d.rhai` is missing from the golden scripts (#786). Running is not touching, so `expected.txt` then has one `touched <name> <case>` line per built-in with a collision handler between it and the kid or a kid bullet (on either side), naming the first case where the two met in the collision phase (#847). The harness sees that from outside: it runs the ticks with `Hooks::ENGINE` except for an `overlaps` hook that returns the engine's result and notes the pairs that met, so sim state, hash and RNG are untouched. `golden_corpus.rs` fails on a `touched <name> -` line unless the built-in is in `UNTOUCHED_BUILTINS` with its reason (only `game_clear`: touching it ends the run). Many built-ins get their own kid, kid bullet or blood handler only under a param (`vanish_on = "touch"`, `on_shot`, `destroys_bullets`, `start_on_touch`, ...), so each such own handler of a built-in also gets a `touched <name>/<handler classes> <case>` line (for example `touched save/kid_bullet kid_param_variants`), counted per handler (#898). Two params can add the same handler with different code behind it (`hidden_block` `stops_bullets` and `destroyed_by_bullet`, `fake_block` `vanish_on = "touch"` and `"group_fade"`), so each value of a `builtins::event_set_params` param that adds such a handler also gets a `touched <name>/<param>=<value> <case>` line (for example `touched fake_block/vanish_on=group_fade kid_param_variants`), touched when a handler it adds ran on a kind with that value (#917). A value adds a handler when the kind with only that param set has a kid, kid bullet or blood handler the kind with none of those params set lacks. The `kid_param_variants` course places every such variant where the kid, a bullet (its `block_check` is `collision_destroy` there) or blood meets it; the allow-list entry of a built-in covers its handler lines too. Built-ins the kid finds by query rather than by a collision event (`vine`, `slope`, `ladder`) get no line. A new built-in or family goes into a course in the same PR. A deliberate sim change re-pins it: `cargo xtask repin` | `crates/sim/tests/golden/` | every CI target |
| Validator fixtures | A set of broken packages, each expecting one specific error with file, line and column (and every `valid/` package must pass the full load, as `pkg check` does, with no warnings) | `crates/format/tests/invalid/` | every `cargo test` |
| Client package fixtures | Small original packages, one feature each (`input`, `audio`, `save`, `particles`, `clear`, `maps`: three maps and its own key art for game select), that the client's unit tests open; placeholder art, not for testers, who play `crates/client/showcase.pkg` (#852). Change a fixture only with the tests that read it | `crates/client/tests/fixtures/` | every `cargo test` |
| Trace tests | Every research trace case, run and diffed bit for bit | research path given by the `IWBTG_RESEARCH` environment variable; skipped when absent | locally: `cargo xtask fidelity` after each merge wave (below), before ranking a game |
| Feel contracts | Scenario + assertions over what the player observes: timing window, position envelope, death/time/counter outcome, control latency, reset scope, sound event. The public set is compiled into `cargo test -p iwbtg-sim --test feel`; the port set runs with `cargo xtask feel` and `IWBTG_GAMES` and/or `IWBTG_RESEARCH` | `crates/sim/tests/feel/` (public fixtures), `crates/tools/feel/` (ports), `crates/tools/feel-baseline.txt` | public set on every CI target; port set after merge waves and before a game is ranked |
| Replay corpus | Each ported game's full-clear replay, plus every stored leaderboard replay once Phase 8 exists | games repo, server | every sim change |
| Cross-platform equality | `iwbtg determinism report` on golden rooms, conformance suite and replay corpus on `x86_64-pc-windows-msvc`, `x86_64-unknown-linux-gnu`, `wasm32-wasip1` under wasmtime and `wasm32-unknown-unknown` through wasm-bindgen-test in Node. A final job requires all hash lists to be byte-identical. | GitHub Actions matrix | every PR touching `sim` or `format` |
| Fuzzing | `.iwbz` unpack, package load and check, replay decoder, script compile and a bounded run | `fuzz/` (workspace-excluded `cargo-fuzz` crate, seeded by committed `fuzz/corpus/<target>/`) | `.github/workflows/fuzz.yml`, nightly and manual dispatch, 10 minutes per target; locally `cd fuzz && cargo +nightly fuzz run <target>` |
| Budget and speed | Peak script units under 25% of the budget; benchmarks of the Rori Girl and Easy Miku 2 avoidances and a 28,900-instance load, native and WASM | `iwbtg profile`, `cargo bench` | CI, early in Phase 3 |
| Stress packages | `crates/sim/tests/stress/*.pkg` load in strict mode (warnings fatal) and each `.inputs` replay runs twice from the smallest room of its variant, with the same final hash. The test reads the packages with the format loader, so `iwbtg-format` is a **dev**-dependency of the sim: a permitted dev cycle (the format crate depends on the sim), kept out of the runtime graph by `exclude-dev = true` in `crates/sim/deny.toml`. Do not "fix" the cycle by moving a loader into the sim (#1068) | `crates/sim/tests/stress_packages.rs` | every `cargo test` |
| Lints | `cargo clippy -D warnings` with the sim bans, `cargo deny check`, `cargo fmt --check` | CI | every PR |

## Naming tests

Tests are named after the module or subject they test (`rooms.rs`, `determinism.rs`), not after the work package that added them. A test module's docs describe the behavior it covers; ownership belongs in the lane docs. A WP-era id (a `WP` followed by a number) stays only where it explains history a reader needs (the historical `docs/plans/sim-core.md`, or a comment naming the work a later change replaced); new files, tests and docs carry none. `cargo test -p xtask no_new_wp_era_identifiers` is a per-area ceiling on the remaining ids: it fails when an area gains one, and a sweep that removes them lowers the ceiling in the same PR.

## Citation ids

Five kinds of id appear in client docs and code. Each has one home, one format and one rule for when to mint it; the research tree's [`specs/IDS.md`](https://github.com/nugamus/iwbtg-collection-research/blob/main/specs/IDS.md) is the model for all five (research#1121).

| Namespace | Format | Home | Minted when | Resolves in |
|---|---|---|---|---|
| Claim id | `PREFIX-NNN`, for example `TICK-001`, `A1-007`, `NUM-058` | research `specs/engines/gm8/**`, `specs/mechanics/**` | a new behavior claim in a spec file (research only) | research `specs/INDEX.md`; the client commits the ids alone in `docs/architecture/sim/claim-ids.txt` |
| Register id | `R12`, `R3b`, `C3`, `N14`, `M2`, `K1`, `I1`, `S1` (`[CIKMNSR]` + digits + optional letter) | client `docs/architecture/sim/register-*.md` | a new sim rule, default or test in the register | the register row; its `Claim` column names the matching claim or says why none applies |
| Converter request | `CR7`, `CR23` | client `docs/format/converter-requests.md` | the converter or the format needs a change to write a package | the CR table row; the canonical list is research `specs/converter-requests.md` |
| Trace / real-runner request | a free-form token: `T-COL-11`, `NUM-PART-RNG-4`, `audio-sound0`, `TR-ROOM-15`, `A3-T20`, `LR-jumps` | research `specs/engines/gm8/traces/requests/*.md`, indexed by `traces/REQUESTS.md` | a behavior claim needs a recorder trace, a real-runner capture or a probe (research only) | the request row and research `specs/INDEX.md` |
| Issue number | `<repo>#<n>`, for example `research#130`, `client#629` | the GitHub repositories | a work item, question or follow-up | the issue |

`python -I scripts/test_spec_claims.py` (also the `SpecClaimTests` unittest in CI) checks the three namespaces the client owns: every claim id cited in `docs/**` and in `crates/**/*.rs` comments is in `claim-ids.txt`; every register id cited there is a row of a `register-*.md` table; and every `CR<n>` cited there has a row in `converter-requests.md`. The checker's ignore list names the few id-shaped words that are not ids (the old milestone names `M2b` and `M9`-`M11` in the roadmap, the `M9`/`M12`/`M13` icon variants, `ISO-8601`, `RUSTSEC-2026`, `NNN`); add an entry there with a reason rather than a second id scheme.

Trace-request ids stay research-owned: their tokens are free-form and would collide with trace file names, so the client does not mint, list or machine-check them. Cite one only as the research request or file it names; the research checker (`uv run python -I -m scraper.spec_index --check`) resolves it against `REQUESTS.md`/`specs/INDEX.md`, which client CI cannot read. Issue numbers are not checked.

To regenerate the ids-only claim list after a research spec change, run `IWBTG_RESEARCH=../iwbtg-collection-research python3 -I scripts/test_spec_claims.py --write` and commit the result.

## CI and the fidelity sweep

CI is public and sees only this repo: everything in the table above except the trace tests and the replay corpus, which need the private research and games repos (`motion_traces.rs` skips without `IWBTG_RESEARCH`, and CI never sets it). So CI proves the sim is deterministic and matches its own pinned hashes, not that it still matches the original games.

`cargo xtask fidelity` closes that gap on the home PC (#785). With `IWBTG_RESEARCH` set, it runs `iwbtg trace sweep`: one process that loads every package folder in `$IWBTG_RESEARCH/build/packages` and runs every case of `crates/tools/cases/<package id>/` against it (packages in parallel, through the same `check_case` as `iwbtg trace check`). It prints one row per game with its OK / OPEN / FAIL counts (`-` when the game has no cases yet), one line per case that is not OK with its reason, and a summary line. FAIL covers a difference, an error, a panic and a cases folder whose package is missing or does not load. Every status is compared with `crates/tools/fidelity-baseline.txt` (`<game>/<case> <STATUS>` lines: names and statuses only, no private data); a case that got worse (OK to OPEN or FAIL, OPEN to FAIL), a new case that fails, or a baseline case that disappeared is a regression, and the command exits 1. Improvements and new passing cases are listed as changes but pass; `cargo xtask fidelity --bless` rewrites the baseline, committed in the PR that caused the change, and is also how a removed case is acknowledged. A missing or unreadable packages/cases tree, and an unreadable explicit baseline, are errors (exit 2) instead of an empty comparison (#1016). The lead runs it after each merge wave (CLAUDE.md, Agent teams); every sweep that ran (clean, or with a regression; not a failed build or a tool error) writes `target/xtask/last-fidelity.txt` (the `origin/main` commit and a unix time), and `issues.py start` prints a `FIDELITY STALE` line when commits touching `crates/sim` or `crates/format` landed on `origin/main` after that commit (local git, no fetch; the baseline file's last commit stands in when the stamp is missing; the stamp lives in the checkout the sweep ran in, normally `client/`).

**Feel contracts** are the fourth layer ([feel contracts](feel-contracts.md), specified by [0005](../decisions/0005-standard-mechanics.md)). They state the player-observable outcome a trace or playtest supports: a retry delay, a jump envelope, a collision winner, a reset scope, a control latency, an RNG draw on a played path. The public fixture set runs in CI (`cargo test -p iwbtg-sim --test feel`), so it needs no private repo; `cargo xtask feel` sweeps the same directory and, with `IWBTG_GAMES` and/or `IWBTG_RESEARCH` set and `crates/tools/feel/` present, the port set against `crates/tools/feel-baseline.txt` (`<area>/<name> <STATUS>` lines), exactly as `cargo xtask fidelity` uses `crates/tools/fidelity-baseline.txt`. A failing contract is a regression even when the pinned hashes are unchanged; a deleted contract is a regression like a removed trace case and is acknowledged in the PR and the game's deviation log. `--bless` rewrites statuses only, never an assertion value; an unloadable package and a contract that fails to load are FAIL; a package in no source is SKIP and keeps its baseline entry. An F1 contract with no `evidence` loads but reports OPEN until a trace or playtest justifies it, and every non-exact assertion carries a one-line `why`; a tolerance is a declared window or envelope in pixels or speeds, never ULP. The command exits 0 for OK/OPEN/SKIP, 1 for a failure or regression, and 2 when a tool or an unreadable root/baseline stops the sweep. `cargo xtask feel` with `IWBTG_GAMES` and/or `IWBTG_RESEARCH` set is the one command that checks every port's contracts; the lead runs it after merge waves and before a game is ranked, as with `cargo xtask fidelity`. The games repo is looked up first and the converter output second ([porting](../porting.md) step 2.4). With neither set it runs the public set and prints that the port set was not run. Golden hashes prove the build is reproducible, traces prove the original's path, and contracts state what the player must still observe after a redesign.

The public set is five contracts under `crates/sim/tests/feel/{lifecycle,physics,collision,sound}/`, each naming a fixture built in code with `GameDefBuilder` (the golden courses' builder): retry after a death, a jump's apex envelope, two overlapping hazards counting one death, an F2 reset's scope, and the music play event on the first tick. The test's compiled-in list is generated from the folder by `cargo xtask feel`; a filesystem-target test fails when the two disagree, so a new contract cannot be silently skipped (#1241).

The roadmap Phase 3 check is the trace-test row plus the cross-platform row: the Phase 2 inputs reproduce the original traces exactly on Windows, WASM and Linux x86_64.
