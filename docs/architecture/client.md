# The client (`iwbtg-client`)

Part of [Architecture](../architecture.md).

Structure (#530): each module owns its command-line flags, a clap `Args` group flattened into `main.rs` (`package::PackageArgs`, `view::ViewArgs`, `audio::AudioArgs`, `screen::ScreenArgs`, `ui::UiArgs`), and its systems, a Bevy `Plugin` (`screen::ScreenPlugin`, `art::ArtPlugin`, `audio::AudioPlugin`; the UI kit's `ui::UiKitPlugin` is added by the screens that use it, so far only the gallery, which builds its own app instead of `view::run`). `view::run` builds the app with the window, the sim and the view's own systems, then calls back into `main.rs`, which adds the plugins in one list. A new module adds one `mod` line, one group and one plugin to `main.rs`; its flags, resources and systems stay in its own file. A test (`the_command_line_is_consistent`) catches two modules claiming the same flag.


`cargo run -p iwbtg-client -- <package folder> [--trace-mode] [--fps <N|unlimited>] [--interpolate]` opens a package in a window (Bevy 0.20, 2D rendering, windowing, audio and bevy_ui with picking and the headless widgets; gamepad and 3D features are off until they are needed, because they pull system libraries). `--ui-gallery` opens the [UI](#ui) gallery instead. `package.rs` opens the folder like `iwbtg pkg check` does (engine pack bundled from `../_engines`, strict load) and prints the errors of a broken package. `view.rs` owns the `sim::Sim` as a non-send resource (the script host is not `Send`) and draws every visible instance that has a sprite, one Bevy sprite each, using the image of its `SpriteId`, a strip or, with `columns`, a grid read row by row (the frame is found from the image width; `iwbtg_format::sprites::sprite_pngs` gives the order), its origin, frame, scale, angle and alpha, at the position and depth the sim reports. The room is letterboxed to fit the window and drawn with nearest-neighbor filtering. The sim ticks on Bevy's fixed clock (`Time<Fixed>`, set to the game's `tick_rate`, 50 for the IWBTG games), so the tick rate does not depend on the frame rate; a slow frame runs several ticks, a fast one none (Bevy clamps one frame's catch-up to 250 ms, so after a long stall the sim slows down instead of racing). Each tick takes one `InputFrame` from `input.rs`, whose collector keeps per-key edges between ticks and uses the IWBTG default keys (arrows, Shift jump, Z shoot, R restart, Q suicide, P pause, M mute, F2 reset). Frames draw the state the last tick left, with no interpolation by default (the originals draw every step, so a frame between two ticks would show something the game never had). `--interpolate` is an option for fast displays: each frame draws every instance that way between its position before the last tick and its position after it, by how far the fixed clock is into the next tick; an instance that moved more than 32 px in one tick, a new instance, and any instance after a room change is drawn at its new place at once. It changes only the picture, never the sim. The frame cap (`--fps`, default 60, or `unlimited`) is a sleep-and-spin limiter at the end of each frame; vsync is off. An overlay in the top-left corner shows ticks per second, frames per second, the tick count, the room (name and size) and the kid's x, y, hspeed and vspeed (or `no kid`); F3 hides and shows it. A halted sim stays on screen with its error in the overlay. After every tick `follow_room_speed` reads the sim's `room_speed` (a room's file speed on entry, or what the game set) and retunes `Time<Fixed>` to it, clamped to 1 to 1000 ticks per second, so a room or game that changes `room_speed` ticks at the new rate from the next tick; the overlay's `game N` shows the current rate. The `world` built-in sets `room_speed` back to the game's `tick_rate` at every room start, so in the IWBTG games it only differs where a game's own code sets it. Two things the sim reports are drawn by `view/hud.rs`: the sign text box (a white-framed black panel at the bottom of the room, shown while ticks keep sending `BuiltinOutput::TextBox`, so it goes away on the first tick without one) and the `time_limit` countdown (read from the running timer's built-in state, drawn as `H:MM:SS` in white at the timer's own position; the position is a guess, the spec only says the timer's Draw event draws text). `crates/client/demo.pkg` is a small original package for trying it; `demo-grid.pkg` is the same with a four-colour 2x2 `columns` kid; `demo-hud.pkg` adds a brown sign, a 1:30 time limit and a green start zone. `--screenshot <png>` saves the window after a few frames and exits, for checks.

Room art (`art.rs`): when the sim's room changes the client rebuilds the room's background colour, background image and tile layers from `rooms/<id>.toml` and `rooms/<id>.tiles.toml` (how they are drawn: docs/format/v0.md, Tiles). `crates/client/demo-art.pkg` shows a tiled background and two tile layers.

Audio (`audio.rs`): each tick's `SoundOutput` events (and a script `emit(name)`, which plays the package sound of that name) go into a queue that is played back through Bevy's audio (Ogg Vorbis only, `bevy_audio` + `vorbis`). The sim decides what plays and for how long; the client only plays, loops, stops, pauses and sets volume and pitch per voice. SuperSound volumes are hundredths of a dB and become a linear factor; DLL handles (`Load { file }`) map to the package sound with the same file stem. `--audio-offset <ms>` (0 to 500, default 0) holds every cue back by that long, so it moves playback only and never the sim; it is not saved yet. The first room's start runs inside `Sim::new` and `step` clears the output, so the client queues that initial output itself. `shake(ticks, strength)` moves the camera by up to `strength` pixels each frame while it runs, on top of the view centre (`apply_shake` runs after `view::follow_view`) (a client effect with its own wobble, not the sim's random numbers). Music sync (docs/product.md): a looping tune with a known length (`length_ticks`) carries a `MusicSync`, which turns the sim's tick count (plus the fixed clock's fraction of the next tick) into where the tune should be: ticks played over the tick rate, times the pitch, wrapped to the loop; a pause holds it and a pitch change re-anchors it. `sync_music` compares that with the sink's position every frame and seeks the tune to the expected position when it is more than 2 ticks (40 ms at 50 Hz) off, measuring the short way round the loop; smaller drift is left alone, and a tune is left alone for 10 ticks after it starts, is paused or is seeked. A lag spike therefore pulls the tune back to the beat; a stop, restart or new `play` starts a fresh voice, which is exact by construction. Sound effects are not synced.
`crates/client/demo-audio.pkg` has jump, shoot and death sounds and a looping tune.

Screen (`screen.rs`, `ScreenPlugin`): the game is scaled by whole steps (never blurred) and centred; `layout` picks the biggest whole scale that fits the area the chosen ratio allows (a window smaller than the game shrinks it instead of cutting it off). The camera runs one world unit per `scale` physical pixels, with a half-pixel shift when the leftover is odd so game pixels sit on screen pixels. Views: `view::follow_view` runs every frame after the sim's tick. It keeps `RoomSize` equal to the sim's current room, reads view 0 (`enabled` and `visible`; else the whole room) into `ViewRect`, centres the game camera on that rectangle and turns it by `view_angle`, and keeps the overlay at the view's top-left corner. `screen.rs` scales the view (not the room) to the window, and when the view shows less than the room or is turned it clips the game camera to the view's rectangle (`Camera.viewport`), so nothing of the room shows beside it. Only view 0 is drawn (ports of other views are not). OPEN: `--interpolate` does not smooth the view, and the direction of `view_angle` on screen is assumed counter-clockwise (the gravity-flip trace logs only the value). Outside the game the window shows a dimmed, blurred copy of the room's background image (or its colour), kept under a black panel the size of the room. There is no settings screen yet (#53): `--fullscreen`, `--ratio native|4:3|16:9|16:10|21:9|32:9`, `--window WIDTHxHEIGHT` (physical pixels) and the keys F11 (fullscreen), F10 (next ratio) and F9 (next windowed size: 800x608, 1280x720, 1600x1216, 1920x1080, 2560x1440, 3200x2432). The window title shows the size, scale and ratio. `demo-art.pkg` has a background to see the blur.

## UI

The client's screens (game select, mod select, loading, HUD, pause, results) are built with bevy_ui and the kit in `crates/client/src/ui/` ([0003 UI toolkit](../decisions/0003-ui-toolkit.md) has the options weighed). Screens are built from the M4 mockups (`docs/design/mockups/m4/`); every colour, size and shape comes from the kit, never from the screen.

- `tokens.rs`: the mockups' colours by name (ground, ink, muted, soft, accent, ahead, behind, gold, amber, ranked, and the glass fills), the star ramp (`star_color`: the last step at or below the rating), shear 0.2, radius 10 px and the motion durations.
- `fonts.rs`: the bundled fonts, compiled into the binary (Barlow, Barlow Condensed, Pixelify Sans for the pause box only, and a Noto Sans Symbols 2 subset as the fallback for `★ ▾ ✓` and arrows; all SIL OFL 1.1, licences next to the files in `crates/client/assets/fonts/`). `Type` is a text style (family, size, weight, italic, tracking in em, capitals) with the mockups' styles as constants (`LABEL`, `STAT`, `BODY`, `BUTTON`, `PRIMARY`, `STARS`, `PILL_CAPS`, `MOD_CODE`, `TITLE`). Every style turns on tabular numerals.
- `shape.rs`, `shape.wgsl`: `Shape` on a node draws it sheared (0.2) with rounded corners while its children stay upright. A shape has a fill and optionally an image (upright, covering the shape, clipped to it), a three-stop veil gradient, a band along the left or bottom edge, an outer ring and a drop shadow. A `ShapeLayer` child, grown past the node's box by the overhang, ring and shadow, draws it with `ShapeMaterial`; `sync_shapes` (PostUpdate, after layout) adds the layer and rewrites the material only when something changed. `UiOpacity` multiplies opacity down the tree; `FadeMask { top, bottom }` fades a list over its top and bottom edges (shapes per pixel, text per line); text spawned through the kit carries its colour in `Ink` so both can apply.
- `widgets.rs`: `text`, `sheared`, `panel`, `pill`, `star_pill`, `mod_pill`, `ranked_pill`, `unranked_pill`, `tag_pill`, `stat` and `button` (Primary, Secondary, Control), each a function returning a bundle. Buttons are `bevy_ui_widgets::Button` (click, Enter or Space sends `Activate`) with Tab navigation; hover lightens the fill, press darkens it and scales to 0.96 (OutQuint, 150 ms), and keyboard focus adds a 2 px white ring.
- `motion.rs`: `Ease::OutQuint` and `Ease::OutElastic`; `Tween<P>` drives `OffsetX`, `OffsetY`, `Scale` (`UiTransform`, so layout does not move), `Width` (`Node::width`) or `Opacity` (`UiOpacity`) and can be retargeted from wherever it is. `ReducedMotion` (`--reduced-motion`) makes every tween land at once.
- `gallery.rs`: `iwbtg-client --ui-gallery [--screenshot <png>] [--reduced-motion] [--window WxH] [--ratio W:H]` shows every token and component at the mockups' 1920×1080, scaled to fit the window (`UiScale`; `--window` sets an exact size in physical pixels, `--ratio` alone makes a 1600-wide window of that ratio, so screenshots come out at the size asked for), for comparing with the canvas: hover a game panel and it slides 25 px left, Pop and Fade run the OutElastic and OutQuint tweens, Tab shows the focus ring, M toggles reduced motion. Its panel art is drawn at run time. The wasm32 build opens the gallery directly ([dev-setup](../dev-setup.md#ui-gallery-in-a-browser)).
