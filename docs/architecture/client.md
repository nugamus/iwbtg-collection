# The client (`iwbtg-client`)

Part of [Architecture](../architecture.md).

Structure (#530): each module owns its command-line flags, a clap `Args` group flattened into `main.rs` (`package::PackageArgs`, `view::ViewArgs`, `audio::AudioArgs`, `screen::ScreenArgs`, `ui::UiArgs`, `hud::HudArgs`, `mods::ModsArgs`, `savefile::SaveArgs`, `retry::RetryArgs`), and its systems, a Bevy `Plugin` (`screen::ScreenPlugin`, `art::ArtPlugin`, `audio::AudioPlugin`; `hud::HudPlugin`; the UI kit's `ui::UiKitPlugin` is added by the screens that use it: the HUD, and the gallery, which builds its own app instead of `view::run`). `view::run` builds the app with the window, the sim and the view's own systems, then calls back into `main.rs`, which adds the plugins in one list. A new module adds one `mod` line, one group and one plugin to `main.rs`; its flags, resources and systems stay in its own file. A test (`the_command_line_is_consistent`) catches two modules claiming the same flag.


`cargo run -p iwbtg-client -- <package folder> [--trace-mode] [--fps <N|unlimited>] [--interpolate] [--bind ACTION=INPUT] [--show-bindings]` opens a package in a window (Bevy 0.20, 2D rendering, windowing, audio, gamepads and bevy_ui with picking and the headless widgets; 3D features are off until they are needed, because they pull system libraries). `--ui-gallery` opens the [UI](#ui) gallery instead. `package.rs` opens the folder like `iwbtg pkg check` does (engine pack bundled from `../_engines`, strict load) and prints the errors of a broken package. `view.rs` owns the `sim::Sim` as a non-send resource (the script host is not `Send`) and draws every visible instance that has a sprite, one Bevy sprite each, using the image of its `SpriteId`, a strip or, with `columns`, a grid read row by row (the frame is found from the image width; `iwbtg_format::sprites::sprite_pngs` gives the order), its origin, frame, scale, angle and alpha, at the position and depth the sim reports. The room is letterboxed to fit the window and drawn with nearest-neighbor filtering. The sim ticks on Bevy's fixed clock (`Time<Fixed>`, set to the game's `tick_rate`, 50 for the IWBTG games), so the tick rate does not depend on the frame rate; a slow frame runs several ticks, a fast one none (Bevy clamps one frame's catch-up to 250 ms, so after a long stall the sim slows down instead of racing). Each tick takes one `InputFrame` from `input.rs`, whose collector keeps per-input edges (keys and controller) between ticks. `bindings.rs` holds the one global binding set: the IWBTG default keys (arrows, Shift jump, Z shoot, R restart, Q suicide, P pause, M mute, F2 reset) and default controller inputs (D-pad or left stick move, A jump, X shoot, Y restart, B suicide, Start menu). Changes are saved with `--bind ACTION=INPUT[,INPUT...]` (a key name or `pad:<name>`, e.g. `--bind jump=Space,pad:select`) in `bindings.toml` in the user's config folder (`--bindings-file` overrides); `--show-bindings` prints them. An action named in the file loses its default keys (or controller inputs); a double binding is an error. No rebinding screen yet (menus are later). Only the active controller counts (the one that last had a button pressed), and a stick axis counts only after it has been seen near the centre (press above 0.6, release below 0.3), so a device with a resting axis, such as a DualSense's motion sensors over Bluetooth, cannot hold a direction. The F3 overlay's last line shows the actions the last tick saw and the controller inputs that are down. The bindings file is still its own `bindings.toml`, not the `[bindings]` table of the settings file (Settings, Storage); moving it there, so it also works in the browser, is #541. Frames draw the state the last tick left, with no interpolation by default (the originals draw every step, so a frame between two ticks would show something the game never had). `--interpolate` is an option for fast displays: each frame draws every instance that way between its position before the last tick and its position after it, by how far the fixed clock is into the next tick; an instance that moved more than 32 px in one tick, a new instance, and any instance after a room change is drawn at its new place at once. It changes only the picture, never the sim. The frame cap (`--fps`, default 60, or `unlimited`) is a sleep-and-spin limiter at the end of each frame; vsync is off. An overlay in the top-left corner shows ticks per second, frames per second, the tick count, the room (name and size) and the kid's x, y, hspeed and vspeed (or `no kid`); F3 hides and shows it. A halted sim stays on screen with its error in the overlay. After every tick `follow_room_speed` reads the sim's `room_speed` (a room's file speed on entry, or what the game set) and retunes `Time<Fixed>` to it, clamped to 1 to 1000 ticks per second, so a room or game that changes `room_speed` ticks at the new rate from the next tick; the overlay's `game N` shows the current rate. The `world` built-in sets `room_speed` back to the game's `tick_rate` at every room start, so in the IWBTG games it only differs where a game's own code sets it. Two things the sim reports are drawn by `view/hud.rs`: the sign text box (a white-framed black panel at the bottom of the room, shown while ticks keep sending `BuiltinOutput::TextBox`, so it goes away on the first tick without one) and the `time_limit` countdown (read from the running timer's built-in state, drawn as `H:MM:SS` in white at the timer's own position; the position is a guess, the spec only says the timer's Draw event draws text). `crates/client/demo.pkg` is a small original package for trying it; `demo-grid.pkg` is the same with a four-colour 2x2 `columns` kid; `demo-hud.pkg` adds a brown sign, a 1:30 time limit and a green start zone; `demo-clear.pkg` is the one that can be cleared: walk right, jump the block, take the blue warp to the `goal` room (its one stage split, `enter_room`), jump the spike and touch the gold `game_clear`, which raises `run_end` (test `stats::tests::the_clear_demo_clears_twice_with_a_split` plays it twice). `--screenshot <png>` saves the window after a few frames and exits, for checks.

Settings (`settings.rs`): one versioned TOML file, `settings.toml` in the config area of Storage (natively `iwbtg-collection/settings.toml` in the config folder: `%APPDATA%` on Windows, else `$XDG_CONFIG_HOME` or `~/.config`; `$IWBTG_CONFIG_DIR` replaces the whole folder). It holds `version` (1), `[display]` (`fullscreen`, `ratio` as `native` or `W:H`, `window` as `WIDTHxHEIGHT`, `integer_scale`), `[audio]` (`offset_ms`, 0 to 500), `[hud]` (`overlay`, the F3 overlay; `ui_scale`, the HUD side panels' scale in percent, 75 to 150; `[hud.show]`, one `true`/`false` per HUD element: `leaderboard`, `timer`, `deaths`, `stage`, `stage_deaths`, `input`, `mods`, all on by default) and `[bindings]` (kept exactly as written; the input layer, #27, owns its layout and checks it). `main.rs` calls `settings::load` once before anything else; a missing file is the defaults; broken TOML, an unknown key, a wrong type or an out-of-range value is a warning on stderr (`warning: settings <path>: ...`) and that entry keeps its default while the rest still counts. A newer `version` warns and reads what it understands. Each module merges its own flags: `screen::configure` (`--fullscreen`, `--ratio`, `--window`), `hud::configure` (`--integer-scale`, `--ui-scale`, `--hud-show`, `--hud-hide`) and `audio::AudioPlugin::new` (`--audio-offset`) write a given flag into the settings, so the next start without it keeps it; F11, F10, F9, F7, Ctrl+=/Ctrl+- and F3 save their choice as they change it. `settings::get()` reads the current values and `settings::update(|s| ...)` changes them and rewrites the file only when something changed (a failed write is a warning; the change still holds for this session); settings screens (M6) only call these. A `--screenshot` run neither reads nor writes the file, so checks look the same on every machine and never change the player's settings. Nothing in the file reaches the sim.

Room art (`art.rs`): when the sim's room changes (or a retry starts the sim again) the client rebuilds the room's background colour, background layers and tile layers from `iwbtg_format::art` (`load_room_art`, `load_tiles`; the format crate reads and checks the keys, the client parses no TOML of its own; how they are drawn: docs/format/v0.md, Rooms). Each background layer is cut along each axis into at most two pieces (the part of the copy that hangs over the room's top or left edge, then a repeating part), so it covers exactly the room and nothing beside it; a stretched layer is one sprite scaled to the room. The colour sits at z -996, the layers behind instances from z -995 and the foreground layers from z 995 (under the overlay at 1000), each later layer 0.001 in front. `scroll_backgrounds` rebuilds a layer with a `speed` once per tick at its new place. `crates/client/demo-art.pkg` shows a tiled background and two tile layers; `demo-layers.pkg` a sky scrolling one pixel per tick, a stretched haze, a foreground stone strip tiled only horizontally, and tiles of their own size with a `step`.

Storage (`storage.rs`, #473): the one place the client keeps things between sessions, so no other module uses `cfg` for it. `Store::config()` (the settings file, with the bindings in its `[bindings]` table) and `Store::data()` (save slots, `saves/<game id>.save`, the local stats, `stats.toml`, and replays, `replays/...`) return a store, or `None` when there is nowhere to keep things; a store reads, writes and removes bytes or text by a `/`-separated name, and every failure is an error string the caller turns into `storage::warn` while the game keeps running. Natively a store is a folder (config: as in Settings; data: `iwbtg-collection` in `%LOCALAPPDATA%` on Windows, else `$XDG_DATA_HOME` or `~/.local/share`), and a write goes to `<name>.tmp` beside the file and is renamed over it, so a crash never leaves half a file; warnings go to stderr. On the web (`wasm32-unknown-unknown`) a store is the browser's `localStorage`, one entry per name under the key `iwbtg-collection/config/<name>` or `iwbtg-collection/data/<name>`; text is stored as is (the settings TOML stays readable in the browser's dev tools) and bytes as lowercase hex (a save slot is a few dozen bytes, far below the quota). Private browsing or a blocked site (no `localStorage`) is one console warning when the store opens, and the session then runs without keeping anything; a full quota on a write is a console warning and the next change tries again. The web build itself, and so a reload test in a browser, comes with #29.

Stats (`stats/`, #40): the local stats, one versioned TOML file `stats.toml` in the data area of Storage, written only by this module; the screens (results, live leaderboard, player card, game select) read the `Stats` resource. The book holds, per map, keyed `<game id>/<map id>` (map ids are only unique within a game; `Sim::map_id`, `main` for a package without `[[maps]]`): the game, its tick rate, clears, deaths, deaths per segment, ticks and seconds played, and boards keyed `<mode>/<mods>` (`ranked/NM`, `original/SD`; mods as `ModSet::codes`). A board keeps its clear count, your top 100 runs fastest first (ties: earlier run first; the first is the PB) and the best time of each segment (gold), whose sum is the sum of best. A run is its ranked time (`Sim::ranked_ticks`, #34), deaths, the ranked time at the end of each segment (a game with `n` stages has `n + 1` segments: start to stage 1, ..., stage `n` to end), deaths per segment its finish date and its replay (`replay = "replays/<game id>/<name>.iwbr"`, absent for runs from before #476). After every tick `stats::watch` (FixedUpdate, after the sim's tick) reads the tick, the death counter and the timing state into a tracker (`stats/track.rs`): a death counts in the segment the run is in (before the timer starts: the first), and the `end` trigger records the run. Only a run started as a new game goes on a board; a clear from a save counts as a clear only. Play original runs go on `original/...` boards: personal stats only, never uploaded (docs/product.md, Modes). Deaths per segment for this session are kept in memory only. Account totals (games with a cleared map, deaths, clears, play time) are summed over the maps. A clear prints one line (`stats: cleared in 0:04.20 (0 deaths): PB 0:04.00 (+0:00.20), #2 of your runs, 1 gold segment(s), sum of best 0:03.80`) and writes the file; deaths and play time are written on a retry, every 30 s and when the window closes. An unreadable file or one from a newer build is copied to `stats.broken.toml` with a warning and the session starts an empty book, so nothing is overwritten. A `--screenshot` run reads and writes no stats.

Replays (`replays.rs`, `ReplaysPlugin`, #476): every run is recorded as an `.iwbr` replay ([replay format](replay.md#replay-file-iwbr)) in the data area of Storage, for the replay viewer and upload (M7). A run is one sim: the client's start, and each quick-retry or auto-retry. `view::tick` hands the `Recorder` each tick's input frame and splits; the header comes from the sim's options and the package (id, `gameplay_hash` from `package::open`, `engine_rev`, seed, start: `NewGame`, or `FromSave` with the postcard bytes of the resumed save slot, play mode, `Sim::map_id`, the run's mods, `iwbtg-client <version>`). Checkpoints are taken every 500 ticks. The file is written when the run's timer ends (a ranked run's replay stops there; Play original keeps recording into the same file, so one Play original session until a retry is one replay), when a retry starts the next run (`replays::reset`, before the new sim replaces the old) and when the window closes (`Last`, after Bevy's exit check, while the sim is still there). Each write prints `replay: <path> (<ticks> ticks, <bytes> bytes) hash <final state hash>`; `iwbtg replay verify <pkg> <file>` prints the same hash. Names are `replays/<game id>/<unix seconds>-<n>.iwbr`, listed oldest first in `replays/index.txt` (browser storage cannot list its entries); natively every replay is kept, on the web only the newest 50 (an hour's replay is a few KB). A cleared run on a stats board points at its replay. Seeds: every run (and every retry) draws a new random seed (`replays::fresh_seed`: the OS-keyed `RandomState` and the clock natively, `Math.random` on the web), as the originals randomize; a `--screenshot` check keeps seed 0 and records nothing. `--ranked` plays the ranked (stripped) mode: always a new game, never the save file (it implies `--no-save-file`); without it the client plays Play original.

Audio (`audio.rs`): each tick's `SoundOutput` events (and a script `emit(name)`, which plays the package sound of that name) go into a queue that is played back through Bevy's audio (Ogg Vorbis only, `bevy_audio` + `vorbis`). The sim decides what plays and for how long; the client only plays, loops, stops, pauses and sets volume and pitch per voice. SuperSound volumes are hundredths of a dB and become a linear factor; DLL handles (`Load { file }`) map to the package sound with the same file stem. `--audio-offset <ms>` (0 to 500, default the saved value, else 0) holds every cue back by that long, so it moves playback only and never the sim; it is saved in the settings file. The first room's start runs inside `Sim::new`; the first `step` keeps that output (#466), so it plays with the first tick's. `shake(ticks, strength)` moves the camera by up to `strength` pixels each frame while it runs, on top of the view centre (`apply_shake` runs after `view::follow_view`) (a client effect with its own wobble, not the sim's random numbers). Music sync (docs/product.md): a looping tune with a known length (`length_ticks`) carries a `MusicSync`, which turns the sim's tick count (plus the fixed clock's fraction of the next tick) into where the tune should be: ticks played over the tick rate, times the pitch, wrapped to the loop; a pause holds it and a pitch change re-anchors it. `sync_music` compares that with the sink's position every frame and seeks the tune to the expected position when it is more than 2 ticks (40 ms at 50 Hz) off, measuring the short way round the loop; smaller drift is left alone, and a tune is left alone for 10 ticks after it starts, is paused or is seeked. A lag spike therefore pulls the tune back to the beat; a stop, restart or new `play` starts a fresh voice, which is exact by construction. Sound effects are not synced.
`crates/client/demo-audio.pkg` has jump, shoot and death sounds and a looping tune.

Mods (`mods.rs`, `ModsPlugin`, #35): `--mods <codes>` (`SD`; codes joined by `,` or `+`) picks the run's mods from `iwbtg_sim::mods::MODS`, and the client prints `mods: SD (ranked)` (or `unranked: <mod name>`) on start. Only Sudden Death is built; any other code is refused as not built yet (#550, #551, save states #39). Sudden Death: after each tick `watch` compares the death counter (`global.death`) with the tick before (`ModSet::ends_run`); a rise ends the run on that tick. The view's fixed-clock systems are the `view::SimTick` set, and `ModsPlugin` gates it with a run condition, so the sim stops ticking and a red "SUDDEN DEATH / Run over at tick N" banner (a child of the game camera, so it stays centred on the view) shows over the last frame. The quick-retry key or `--auto-retry` starts again (below).

Retry (`retry.rs`, `RetryPlugin`, #38): the quick-retry key (`KeyCode::Backquote`, the key left of 1; read straight from Bevy, not through the input collector, so it never becomes a sim `Action` or reaches a replay) and, with `--auto-retry`, any tick that raises the death counter set a pending retry. While one is pending the `SimTick` set does not run, so no tick follows the death. In `Update` the exclusive `apply` system calls `view::restart_run`, which builds a new `Sim` from the `RunStart` resource (the definition and `SimOptions` the window opened with, so a run started from a save restarts from that save), despawns every drawn sprite, clears interpolation history, pending input edges (held keys stay held) and the sign; then `audio::reset` stops every voice and clears the cue queue, mixer memory and shake (the new room start plays from the first step's output), and `mods::reset` clears Sudden Death's run-over state and banner. The terminal prints `retry: run restarted (quick-retry)` or `(auto-retry)`. The bottom-bar toggle is #558; settings and rebinding are #559.

Pause menu (`pause.rs`, `PausePlugin`, #479; docs/product.md, Pause; artboards `Pause169`, `Pause43`, `PauseBox`): Escape (`pause::PAUSE_KEY`, read straight from Bevy like the quick-retry key, so it never reaches the sim or a replay) opens and closes it. While it is open the `SimTick` set does not run (a run condition, as for Sudden Death), every playing voice is paused and resumed on close (a voice the game paused stays paused), and the backdrop and HUD keep running. The timer keeps running: `count` runs on the fixed clock while the menu is open and counts each tick in which the map's timer runs (started, not ended, sim running), keyed by the sim tick the pause began at (`Menu::pauses`); `publish` writes the total to `hud::Paused`, which run info adds to `Sim::ranked_ticks` and uses for the paused line. A retry clears the pauses (`pause::reset`). The box is drawn by bevy_ui on the HUD's camera, in game pixels: the root covers the game's rectangle (`HudLayout::game`) with the 50% dim and centres the box, and every size is `PauseBox`'s times the game's scale (rebuilt when that scale changes), so it scales with the game at every ratio. The dim's alpha is 0.78, not the artboard's 0.5, because Bevy blends in linear light: 0.78 halves the sRGB value as the browser does. Items: Continue; Retry from save (closes and presses the game's `restart` action for the next tick, what R does); Restart run (`retry::request`, the quick-retry key); Quit (closes the client: there is no game select to return to yet; no results screen, and as the run's timer has not ended no clear reaches the stats; the replay is written as for any unfinished run, like a window close). Up/Down and the keys bound to `up`/`down` move the selector; Enter, Space and the keys bound to `jump`/`accept` pick; the mouse selects on hover and picks on click (`Activate`); R and the quick-retry key pick their items at once; Escape continues. Key edges collected while the menu was open are dropped when it closes, so nothing pressed in the menu reaches the game. The selected item is white, weight 600, and slides 4 game px right (OutQuint, 300 ms); the selector is the delicious fruit, stepping between two frames every 320 ms: the package's sprite `cherry` (its first two 21x24 frames) when the package has one, else a placeholder cherry drawn in code (no game art in this repo). The game's own pause (the P key, the sim's `pause` action) is unrelated: it is sim input and stays the game's in both modes (a game whose pause deactivates instances keeps ticking, so its timer runs; a runner-modal pause in an original is a client freeze per game, `world` built-in). `--pause-preview <continue|retry|restart|quit>` (hidden) opens the menu at sim tick 25 with that item selected, for screenshot checks.

Screen (`screen.rs`, `ScreenPlugin`): `area` is the part of the window the chosen ratio allows (the largest centred rectangle of that ratio); `hud::layout::compute` places the game and the HUD columns in it (see HUD below), and `apply` clips the game camera to the game's rectangle (`Camera.viewport`, always) and runs it at one world unit per `scale` physical pixels, so the view fills the rectangle and nothing of the room shows beside it. The game is drawn with nearest sampling at any scale; with integer scale on (F7, `--integer-scale`) the scale is the largest whole step that fits. Views: `view::follow_view` runs every frame after the sim's tick. It keeps `RoomSize` equal to the sim's current room, reads view 0 (`enabled` and `visible`; else the whole room) into `ViewRect`, centres the game camera on that rectangle and turns it by `view_angle`, and keeps the overlay at the view's top-left corner. `screen.rs` scales the view (not the room) to its rectangle. Only view 0 is drawn (ports of other views are not). With `--interpolate` the view (position and angle) is blended between its place before the last tick and its place now, like the instances, and lands at once after a room change, a snap of more than 32 px, a resize or a turn of more than 45 degrees in one tick. OPEN: the direction of `view_angle` on screen is assumed counter-clockwise (the gravity-flip trace logs only the value; research#94). Outside the game the window shows the [UI backdrop](#ui) (the game's key art, blurred and dimmed for gameplay, over the whole window), with a black panel the size of the view under the game. `[` and `]` blur the backdrop less and more in steps of 10% (shown in the window title; not saved until the settings file has a blur entry, #509). There is no settings screen yet (#53), so the choices are flags and keys, each saved in the settings file (see Settings): `--fullscreen`, `--ratio native|4:3|16:9|16:10|21:9|32:9`, `--window WIDTHxHEIGHT` (physical pixels) and the keys F11 (fullscreen), F10 (next ratio) and F9 (next windowed size: 800x608, 1280x720, 1600x1216, 1920x1080, 2560x1440, 3200x2432). The window title shows the size, scale, ratio, UI scale and blur. A `--screenshot` run with `--window` lays out at one physical px per logical px, so its picture does not depend on the machine's display scaling. `demo-art.pkg` has a background to see the blur.

HUD (`hud/`, `HudPlugin`; docs/product.md, In-game display; artboards `Hud169`, `Hud43`, `Hud219`, `HudSmall`): three columns, the live leaderboard left, the game centre, run info right. `hud::layout::compute` is pure (unit-tested at every artboard size) and works in logical px (the artboards' CSS px; physical px divided by the display scaling). The game fills the area's height unless the columns would get less than 204 px (left) and 180 px (right), then it shrinks (`Hud43`: 0.8x at 1024x768). A window of 960x540 or less in either direction is small: the columns keep 124 px each, the leaderboard shows rank and avatar plus your time, run info stacks under the timer and the input display hides. Spare room is split evenly; each column stops at 360 px (times the UI scale) and the rest is backdrop (`Hud219`). Density: full from 240 px per column (at the UI scale), else compact. The UI scale (75 to 150%, Ctrl+= and Ctrl+-, `--ui-scale`) scales only the panels (`UiScale`), never the game: when a column is too narrow for the panel at that scale the panel scale stops at what fits (`Layout::content`). Shift+Tab hides the whole HUD and gives the game the whole area; the HUD always starts shown. The panels (`hud/panels.rs`) draw on a camera of their own (order 10, UI only) and are rebuilt only when their density or width changes; the leaderboard is 92% of its column, 7% from the game, run info 84%, 9% from it. A box shadow around the game (`0 0 60px` at 60% black) is drawn by the backdrop's camera, under the game. Until the live leaderboard lands, it is a frame with placeholders: skeleton rows with the no-avatar mark and your row at #1 with the run's time. Run info (`hud/run_info.rs`, #37; `RunInfo.dc.html`): `read` fills the `RunInfo` resource every frame from the sim and `show` writes it into the panel; the panel is rebuilt only when its `Look` changes (ranking, mods, toggles, bound extra actions). From top: a `Paused · timer running` line while the pause menu is open (`hud::Paused`, written by `pause.rs`); the mod row, only for an unranked run (the amber Unranked pill: Play original, or a mod that is not ranked) or when mods are on (24 px sheared pills with the codes); a plain ranked run shows nothing there. The timer is `Sim::ranked_ticks` plus the run's paused ticks (`hud::Paused::ticks`) as `m:ss` with the hundredths smaller and in the soft colour. Deaths is the death counter (`global.death`, so a run from a save starts with its deaths); Stage is `stages_done + 1` of the map's stage splits + 1; This stage counts deaths since the stage began and starts again at a new stage or a retry (`StageDeaths`). The input display draws the four arrows and Jump, Shoot, Restart from the frame the last tick took (`input::Collector::last`), lit white with an accent bar while held or pressed; Extra 1-4 appear when the player has bound them. Small windows stack the stats under the timer and hide the input display. Every element toggles on its own (`[hud.show]`, `--hud-show`, `--hud-hide` with comma-separated names); `leaderboard` hides the left panel. The hidden flag `--hud-preview-held right,jump` draws keys as held for screenshot checks.

## UI

The client's screens (game select, mod select, loading, HUD, pause, results) are built with bevy_ui and the kit in `crates/client/src/ui/` ([0003 UI toolkit](../decisions/0003-ui-toolkit.md) has the options weighed). Screens are built from the M4 mockups (`docs/design/mockups/m4/`); every colour, size and shape comes from the kit, never from the screen.

- `tokens.rs`: the mockups' colours by name (ground, ink, muted, soft, accent, ahead, behind, gold, amber, ranked, and the glass fills), the star ramp (`star_color`: the last step at or below the rating), shear 0.2, radius 10 px and the motion durations.
- `fonts.rs`: the bundled fonts, compiled into the binary (Barlow, Barlow Condensed, Pixelify Sans for the pause box only, a Noto Sans Symbols 2 subset as the fallback for `★ ▾ ✓` and arrows, and a Noto Sans JP subset as the Japanese fallback; all SIL OFL 1.1, licences next to the files in `crates/client/assets/fonts/`). `Type` is a text style (family, size, weight, italic, tracking in em, capitals) with the mockups' styles as constants (`LABEL`, `STAT`, `BODY`, `BUTTON`, `PRIMARY`, `STARS`, `PILL_CAPS`, `MOD_CODE`, `TITLE`). Every style turns on tabular numerals.
- `shape.rs`, `shape.wgsl`: `Shape` on a node draws it sheared (0.2) with rounded corners while its children stay upright. A shape has a fill and optionally an image (upright, covering the shape, clipped to it), a three-stop veil gradient, a band along the left or bottom edge, an outer ring and a drop shadow. A `ShapeLayer` child, grown past the node's box by the overhang, ring and shadow, draws it with `ShapeMaterial`; `sync_shapes` (PostUpdate, after layout) adds the layer and rewrites the material only when something changed. `UiOpacity` multiplies opacity down the tree; `FadeMask { top, bottom }` fades a list over its top and bottom edges (shapes per pixel, text per line); text spawned through the kit carries its colour in `Ink` so both can apply.
- `widgets.rs`: `text`, `sheared`, `panel`, `pill`, `star_pill`, `mod_pill`, `ranked_pill`, `unranked_pill`, `tag_pill`, `stat` and `button` (Primary, Secondary, Control), each a function returning a bundle. Buttons are `bevy_ui_widgets::Button` (click, Enter or Space sends `Activate`) with Tab navigation; hover lightens the fill, press darkens it and scales to 0.96 (OutQuint, 150 ms), and keyboard focus adds a 2 px white ring.
- `motion.rs`: `Ease::OutQuint` and `Ease::OutElastic`; `Tween<P>` drives `OffsetX`, `OffsetY`, `Scale` (`UiTransform`, so layout does not move), `Width` (`Node::width`) or `Opacity` (`UiOpacity`) and can be retargeted from wherever it is. `ReducedMotion` (`--reduced-motion`) makes every tween land at once.
- `backdrop.rs` (+ `backdrop.wgsl`): the one background behind every screen. Screens set the `Backdrop` resource (art handle, blur 0 to 1, dim from `backdrop::dim`: select 0.38, loading 0.55, gameplay 0.45, results 0.62) and never draw their own. A camera of its own (`BackdropCamera`, order -100) draws two full-window layers with `BackdropMaterial`; cameras over it use `ClearColorConfig::None`. `art_image` builds an image with its mip chain; the shader covers the window with the art (never stretched) and blurs by sampling the mip level that matches the radius (blur 1 is the mockups' 40 px at 1600 px wide), so the slider is smooth and cheap. A new art cross-fades over 400 ms (OutQuint; at once with reduced motion). `key_art_image` turns `iwbtg_format::key_art::resolve` into art (package key art, else the first ranked room's background, tiled over the room as the room shows it, or its colour, else the client's own dusk scene). `screen.rs` sets it from the package when the game opens.
- `icons.rs`: `Icon` (the stat marks, search, back, random, music bars) and `icon(Icon, height, colour)`. The mockups' SVG paths are rasterised with tiny-skia at the node's laid-out pixel size and tinted by the node's colour, so icons are crisp at any scale on native and wasm32. `widgets::stat` takes an optional icon.
- `gallery.rs`: `iwbtg-client --ui-gallery [--screenshot <png>] [--reduced-motion] [--window WxH] [--ratio W:H]` shows every token and component at the mockups' 1920×1080, scaled to fit the window (`UiScale`; `--window` sets an exact size in physical pixels, `--ratio` alone makes a 1600-wide window of that ratio, so screenshots come out at the size asked for), for comparing with the canvas: hover a game panel and it slides 25 px left, Pop and Fade run the OutElastic and OutQuint tweens, Tab shows the focus ring, M toggles reduced motion. Its panel art is drawn at run time. The wasm32 build opens the gallery directly ([dev-setup](../dev-setup.md#ui-gallery-in-a-browser)).
