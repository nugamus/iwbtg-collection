# Game package format v0 (draft)

Status: draft for roadmap Phase 3. Accepted by Claude on the user's behalf, 2026-10-24 (user may revisit).

This page defines the files in a game package. It follows the [format principles](README.md), the [script language decision](../decisions/0001-script-language.md) and the [data syntax decision](../decisions/0002-data-syntax.md). How the simulation runs a package is in [architecture](../architecture.md).

Version 0 is a draft. It may change without migrators until format 1, the first stable version. From format 1 on, every change follows [versioning](#versioning).

Items marked **OPEN** are not decided yet. Each names where the answer will come from.

## Package layout

One package is one folder in the games repo, `games/<game_id>/`. For download it is zipped and served by content hash.

```
games/rely_the_needle/
  game.toml                  manifest
  physics.toml               kid physics profile
  objects/<id>.toml          package objects: presets of built-ins and scripted objects
  scripts/<id>.rhai          scripts, only for behavior built-ins cannot express
  timelines/<id>.toml        tick-indexed moments (avoidance, boss phases)
  paths/<id>.toml            movement paths (`path_start`)
  rooms/<room_id>.toml       gameplay instances of one room
  rooms/<room_id>.tiles.toml optional decorative tiles of that room
  sprites/<id>.png           horizontal strip of frames
  sprites/<id>.toml          sprite sidecar: frames, origin, collision mask
  backgrounds/<id>.png       backgrounds and tilesets
  backgrounds/<id>.toml      optional sidecar for tilesets (tile size, separation)
  sounds/<id>.ogg            sound effects
  sounds/<id>.toml           optional sidecar: length_ticks, volume, pan
  music/<id>.ogg             music
  music/<id>.toml            optional sidecar: length_ticks, volume, pan (loop points and preview start are `[music]` in game.toml)
  fonts/<id>.png             bitmap fonts
  fonts/<id>.toml            font sidecar: glyph size, character map
  art/<name>.png             key art for the background system and game select (optional, see Key art)
  engine/<pack>/            bundled engine pack (engine.toml and the pack files used), see engine.md
  CREDITS.md                 human-readable credits (game.toml is the machine source)
  tests/                     not shipped, not hashed
    replays/full_clear.iwbr  a verified full clear (replay format 2)
    inputs/<case>.inputs     trace and test inputs
    trace-map.toml           maps original rooms, objects, sprites and variables to ours
```

Shared engine assets (kid sprites, blood, default save and sounds of an engine family) live once in `games/_engines/<pack>/`, with their own `engine.toml` and credits. Packages reference them as `engine:<pack>/<id>`; the full page is [engine.md](engine.md). A built package carries the pack files it uses under `engine/<pack>/`. An engine pack can also provide a default `object_order` and default physics values. **Decided: bundled.** The package builder copies the pack assets a game uses into its package, so a built package is self-contained. Reasons: a download works offline and alone; the content hash covers every byte the game shows, so a later pack fix cannot change a game silently; the gameplay hash never depends on a pack version. The cost is the same kid sprites stored once per game, which is small next to music. The pack stays the single source in `games/_engines/`; only the built package carries copies.

## Ids and references

- Ids are lowercase snake_case ASCII: `[a-z][a-z0-9_]*`, at most 48 characters.
- An asset id is its file stem: `sprites/boss1.png` is the sprite `boss1`. Ids are unique within their namespace (rooms, objects, sprites, backgrounds, sounds, music, fonts, timelines, scripts).
- A field's type says what it points to. `sprite = "boss1"` always means a sprite. References carry no prefix, with two exceptions:
  - Package objects are written with `@`: `@boss1` is defined in `objects/boss1.toml`. Built-in kinds are bare (`spike`). A built-in name can never be shadowed.
  - Engine pack assets are written `engine:<pack>/<id>`.
- An instance that something points to gets `name = "..."`, unique within its room.
- Trigger names are global to the package.
- `group = "..."` tags instances for triggers and scripts.
- Original GM ids never appear in a package. `tests/trace-map.toml` holds the mapping.
- Every reference is resolved at load. An unknown id is an error with file, line and column.

## Common rules for data files

- TOML 1.1. Unknown keys are errors.
- The first line is a `#:schema` comment that points at the generated JSON Schema, for example `#:schema ../../client/docs/format/schema/v0/game.schema.json`. The schemas (`game`, `engine`, `object`, `room`, `tiles`, `sprite`, `timeline`, `path`, `sound`, `physics`) live in `docs/format/schema/v0/`. They are generated from the types in `crates/format` (and, for `physics`, `PhysicsProfileDraft` in `crates/sim` through its `schema` feature, which the format crate's `schema` feature turns on), never edited by hand: `UPDATE_SCHEMAS=1 cargo test -p iwbtg-format --test schemas` rewrites them, and the plain test fails when one is stale or an example in this page stops validating. They check the shape of a file (keys, types, ranges of the fixed keys); the loader still checks references and param values. Params of a built-in or a kind are open in the schema until the built-in param lists are generated too.
- Numbers are TOML integers or decimals. Any number may instead be written `{ bits = "3FDCCCCCCCCCCCCD" }` (16 hex digits of an IEEE double) when a trace shows it must match a GM8 constant bit for bit.
- A decimal means the nearest double to it, in TOML and in scripts. Values converted from a GM8 game can look odd, like `0.9500000000000001` for the original's `0.95`: GM8 (as the recorder reads it) parses some decimal literals one ulp above the nearest double, so the converter writes the exact double the original used in its shortest form. Keep such a value as it is when you edit a converted package; changing it to `0.95` changes the game's physics by one ulp per use, which a replay notices.
- `iwbtg pkg fmt <dir> [--check]` is the canonical formatter (`iwbtg_format::fmt::format_toml`). The level editor writes through the same rules. It keeps comments and the order of keys, tables and lists, and sets:
  - LF line ends, no byte order mark, one newline at the end of the file; `key = value` spacing; inline tables as `{ key = value }`; short arrays on one line as `[1, 2]` (an array already spread over several lines, or with a comment inside, is left as written).
  - Floats in their shortest form that reads back to the same bits; integers and strings as written.
  - Lists of rows (`instances`, `views`, `on_create`, tile `layers` and `tiles`, `moments`, `object_order`, `stages`, and `[stripped]`'s `cutscenes`, `dialogues` and cut `rooms` and `instances`) with one inline table per line, two spaces of indent, a trailing comma, so a one-instance edit is a one-line diff. In a row the keys the format names come first in a fixed order (an instance: `kind, x, y, name, group, xscale, yscale, angle, visible, depth, run, step`; then its params as written). It never reorders a list.
  - Running it twice changes nothing. `--check` writes nothing, lists the files that would change and exits 1 if there are any.

## Manifest: `game.toml`

```toml
#:schema ../../client/docs/format/schema/v0/game.schema.json
format = 0                       # format major version (integer)
id = "rely_the_needle"
title = "I Wanna Rely The Needle"
version = "1.0.0"                # version of our port (semver)
source_version = "4.2"           # version of the original we ported
engine_pack = "yuuutu"           # engine pack in games/_engines/, optional
engine_rev = 1                   # built-in behavior revision this package was verified against
runner = "gm80"                  # gm80 | gm81: original runner, selects event-order differences
physics = "physics.toml"
start_room = "title"
tick_rate = 50                   # default room speed; rooms may override
max_ticks = 1_080_000            # the server rejects longer replays (6 hours at 50)
object_order = [                 # event and collision order; every kind used must be listed
  "kid", "block", { kind = "spike", dir = "up" }, { kind = "spike", dir = "down" },
  "save", "warp", "platform", "trigger", "@boss1",
]
room_order = ["title", "room_1", "room_2"]   # optional; GM room order for room_goto_next/previous

[engine]                         # optional; engine settings
new_game_room = "room_1"         # where a new game starts; default start_room (with a warning)
boot = ["@world"]                # persistent kinds created before the first room; default the world kind
uninit_reads_zero = true         # GM "treat uninitialized variables as 0"; default true
float_model = "f64"              # runner number model; only f64 so far
roles = { kid_bullet = "@bullet", bow = "none" }   # which kind the sim spawns for an engine role

[engine.restart]                 # the retry key (R)
kind = "room_goto_saved"         # game_restart_via_boot | room_goto_saved | showdown_load | recreate_in_place
trigger = "step_pressed"         # key_press_event | step_held | step_pressed | step_pressed_unless_paused
excluded_roles = ["title", "menu"]
# a death-only save that adds no death (wanna saveDeathTime): death_on_restart = "nothing" with kid_steps.save_death_time = true
# death_on_restart = "nothing" | "save_counters" | "save_counters_per_kid"   # per kid: one death for each live kid, none with no kid (showdown)
kid_steps = { add_time = 2, save_death_time = true, clear_frozen = true }   # kid-side steps, all off by default: add_time (ticks added to the play timer first), save_death_time, clear_frozen (frozen and frozen2, globals and every kid), release_death_sound (B: stop the death sound, restore the music volume and destroy the `death_sound` object before the retry), reset_jump_values (showdown; the new kid's jump values, speeds and jump flags), clear_triggers (showdown; the trigger arrays and `global.triggered` after the load)

[engine.reset]                   # the reset key (F2)
kind = "game_reset"              # delete_temp_and_restart | game_reset
trigger = "key_press_event"

[defaults.spike]                 # default sprite and mask of a bare built-in, per variant
sprite = "spike_up"
variants = [{ dir = "down", sprite = "spike_down" }]

[[creators]]
name = "<creator>"
role = "author"                  # author | co-author | music | art | tester | other

[source]
url = "https://delicious-fruit.com/game/19483"
permission = "community-assumed" # granted | community-assumed | pending | revoked
permission_date = 2026-10-24     # when the status was last set
permission_note = ""             # where the permission came from, or why it is pending

[budget]
ops_per_tick = 1_000_000         # script budget units per tick; hard cap 2_000_000

[timing]
start = { trigger = "run_start" }
end = { trigger = "run_end" }
stages = [
  { id = "stage1", name = "Stage 1", trigger = "stage1_clear" },
  { id = "boss", name = "Boss", trigger = "boss1_dead" },
]

[[maps]]                         # optional; see Maps
id = "medium"
name = "Medium"
difficulty = "Medium"            # the original's built-in difficulty, as the game names it

[[maps]]
id = "hard_any"
name = "Hard Any%"
difficulty = "Hard"
category = "Any%"
end = { trigger = "enter_room", room = "ending" }   # timing keys left out come from [timing]
stripped_start = { globals = { difficulty = 2 } }   # optional; overrides [stripped].start key by key

[stripped]                       # optional; ranked (stripped) mode, see Stripped mode
start = { room = "stage1_01", globals = { difficulty = 1 } }   # where a ranked run starts
cutscenes = [                    # the ranked timer is frozen while one holds
  { id = "boss_intro", kind = "@boss_intro" },
  { id = "ending", room = "ending" },
]
dialogues = [                    # text that waits for a press: frozen, and advances on its own
  { id = "shopkeeper", kind = "@textbox", advance = "shoot", timeout_ticks = 150 },
]

[stripped.cut]                   # what stripped mode leaves out
rooms = [
  { room = "intro", to = "stage1_01" },
]
kinds = ["@tutorial_sign"]
instances = [
  { room = "stage1_01", name = "save_hint" },
]

[tricks]                         # ids from the research trick inventory
vine_check = "on"                # on | off | required

[[third_party]]
path = "music/stage1.ogg"
what = "Stage 1 music"
owner = "<rights holder>"
license = "unknown"              # SPDX id, or "unknown"
status = "to-clear"              # cleared | to-clear | excluded-from-public

[music.stage1]                   # optional per-track settings; may move to music/<id>.toml
volume = 1.0

[key_art]                        # optional; see Key art
image = "art/key.png"            # the game's art, 1920 x 1080 recommended
maps = { hard = "art/key_hard.png" }   # optional per-map override, keyed by map id
```

### Timing triggers

The triggers form one chain, evaluated at the end of every tick: `start`, then each stage in order, then `end`.

- Vocabulary: `run_start` (true at once: the run starts on its first tick), `run_end` (true in the tick `game_clear` ends the run) and `enter_room` with `room = "<id>"` (true while the kid's world is in that room).
- Each trigger fires at most once. Nothing fires before `start`. A stage is looked at only after the stage before it fired, so stages never fire out of order. Several triggers can fire in one tick. `end` can fire with stages still unreached. After `end` nothing fires.
- A split is its chain index (0 start, then the stages, then the end) and the tick it fired at. The tick is the number of ticks run so far, so `run_start` is tick 1 and a run's time is `end - start` in ticks.
- `iwbtg replay run` prints the splits as `<index>@<tick>`.
- A `.iwbr` replay (stored in `replays/` or submitted) uses replay format 2: its header carries the run's mods as a bit set (Sudden Death, visual mods, practice assists; [replay format, Mods](../architecture/replay.md#mods)). Format 1 files, which had no mods field, are no longer read. None were ever stored. Under Sudden Death a run ends on the tick of its first death, so its `end` trigger can only fire in a deathless run.

### Maps

A package holds every map of its game: each built-in difficulty, each category (Any%, 100%, True Ending) and each version, like the beatmaps of an osu! set ([content](../content.md#package-file)). Game select lists the game once and expands it into its maps. Each map has its own timing chain and its own leaderboard.

- `id` is the map's snake_case id, unique within the package. Stable forever: leaderboards key on (package id, map id, `gameplay_hash`).
- `name` is shown in game select. `difficulty` names the original's built-in difficulty, `category` the run category; both are display text and optional. `version` is the original's version the map plays, default `source_version`.
- `start`, `end` and `stages` work as in `[timing]` ([Timing triggers](#timing-triggers)); each key a map leaves out comes from `[timing]`. `stages = []` is a map with no splits. The stage rules hold per map: stage ids unique, no two stages on one trigger, no stage on the start trigger.
- Without `[[maps]]` the package has one map, id `main`, named after the game and timed by `[timing]`.
- The loader resolves each map's triggers like `[timing]`'s (the vocabulary, and `enter_room` rooms must exist) and returns every map's chain (`LoadReport::maps`). OPEN (#504): a static check that each `enter_room` room can be reached from the start room through warps and room order.
- `name`, `difficulty` and `category` are left out of the `gameplay_hash`, so renaming a map keeps its board; the timing keys count.
- `stripped_start` is the map's ranked start point (`{ room, globals }`, [Stripped mode](#stripped-mode)): how the map selects the original's difficulty or version once the menus are cut. Keys it leaves out come from `[stripped].start`; `globals` merge by name, the map's value winning. A Play original run picks the difficulty in the game's own menu, as the original does.
- OPEN (#505): running a map's chain. Until then the sim runs `[timing]`'s chain from the package's start.

### Stripped mode

Ranked (stripped) mode plays the game without its frame: no title screen, menus, file select or difficulty select ([product](../product.md#two-ways-to-play-each-game)). `[stripped]` says how, per package. What a given game cuts, where its ranked run starts and which parts are cutscenes is decided per game in `docs/games/<game-id>.md`, never guessed by a porter or agent. Play original ignores `[stripped]`. All of it counts for the `gameplay_hash`. Without `[stripped]` a ranked run starts in `[engine].new_game_room` and nothing is cut or frozen.

- **`start`**, the ranked start point: `room` is the room a ranked run starts in (default `[engine].new_game_room`, else `start_room`). `globals` are set before that room's creation, in place of what the skipped menus set (`difficulty`, a save slot, a version flag). Names are GML variable names; values are a number (or `{ bits }`), a string, or a boolean (true is 1), as in `set_global`. A map's `stripped_start` overrides it key by key ([Maps](#maps)). The ranked timer starts on the first input after the start ([product](../product.md#two-ways-to-play-each-game)); the run ends at the map's `end` trigger.
- **`[stripped.cut]`**, what is left out:
  - `rooms`: `{ room, to }`. Any room change to `room` (warp, `room_goto`, `room_goto_next`, a save load) goes to `to` instead. A `to` room cannot be cut itself, and the ranked start room cannot be cut.
  - `kinds`: placed instances of these kinds are not created when a room loads, and room `spawn` actions of them do nothing. Scripts are not affected: a script that creates a cut kind still creates it.
  - `instances`: `{ room, name }`, one placed instance by its `name` in that room.
- **`cutscenes`**: regions that freeze the ranked timer. Each has an `id` (unique among cutscenes and dialogues) and exactly one condition: `kind` (holds while any instance of that kind exists) or `room` (holds while the kid's world is in that room). Ranked time is the run's ticks outside every region. The player can always skip one: the client runs the region's ticks at once without drawing them, so the replay and the sim do not change.
- **`dialogues`**: cutscene regions for text that waits for a press. Besides `id` and the condition they name `advance`, the action the original reads to go on (an action name: `jump`, `shoot`, `accept`, ...), and `timeout_ticks` (at least 1). While a dialogue region holds, the sim counts the ticks since the region began or since the last press of `advance`; when the count reaches `timeout_ticks`, the sim presses `advance` itself in that tick (held and pressed for one tick). The press is derived, so replays never store it, and nobody gets free rest time in a text box.
- The loader checks that every room, kind and instance name resolves, that nothing is cut twice, that region ids are unique and that the ranked start room is not cut. A start global named `difficulty` also sets the engine's difficulty (what built-ins such as the bow read), so it must be a whole number from 0 to 255.
- **In the sim** (#561). A run has a play mode, `original` or `stripped` (`SimOptions::mode`, recorded in the replay header and hashed with the world). A stripped new game creates the boot instances, sets the start's `globals` (and the engine difficulty from `difficulty`), then enters the start room. Every room entry goes through the cut rooms: a request (`room_goto`, `room_goto_next`, a warp), `game_restart`'s first room, a start point and a save load. Until #505 picks a map, the sim starts at `[stripped].start`; the loader already resolves every map's merged start (`StrippedDef::map_starts`). The client buttons are #43.
- **Regions in the sim** (#34). `stripped::begin_tick` runs at tick row 0, before the input is latched, on the world as the previous tick left it. A tick that starts with any region holding is frozen; the timer's other ticks are ranked time (`TimingState::ranked_ticks`, `Sim::ranked_ticks`, the replay trailer's `ranked_ticks`). The tick the start trigger fires in is not the timer's, the tick the end fires in is, so ranked plus frozen ticks is `end.tick - start.tick`. A dialogue's count goes up once per tick it holds, goes to 0 on a real press of `advance` (holding is no press) or when the region stops holding, and in the tick it reaches `timeout_ticks` the frame gets `advance` held and pressed and the count goes back to 0: with `timeout_ticks = 150` the first derived press is the region's 150th tick. Play original has no regions.
- **The derived press is press-only** (#574). It sets `advance` held and pressed for its one tick and adds no `released` edge on the next tick: the next tick runs exactly as the player's frame says. The reason is what the 20 games' text reads. Their text is shown by the runner's modal `show_message` box (13 pause boxes, signs, endings, RBF's quiz), which the runner's own dialog closes rather than game input, or opened by a press: signs use a "Key up pressed" event or an Up press check. No game has a Key Release event, and the only `keyboard_check_released` reads in the input survey are the kid's jump cut (research `specs/engines/gm8/CLONE_SPEC.md`, events used by the 20 games and How the 20 games read input; `specs/mechanics.md`, builtin.sign and Client features implied). So no text box waits for a release. If a port ever adds one, `advance` gets a `released` edge then, decided in that port's issue.
- **No stripped-mode query for scripts** (decided in #561, `revisit`). Scripts behave the same in both modes; everything stripped mode changes is data in `[stripped]`, so a port's two modes cannot drift apart in code and a reviewer sees every ranked difference in `game.toml`. If a game needs a script to know (for example a menu object that also runs in play rooms), a query can be added later without breaking any package.

### Key art

Key art is the picture behind every screen of the background system (game select, loading, gameplay, pause, results; [product](../product.md)) and on the game's panel in the game select list. It never changes the sim, so `[key_art]` and the image files are outside the `gameplay_hash`.

- `image` and each `maps` value are paths inside the package to a PNG (the usual place is `art/`). They follow the image rules in [Assets](#assets): at most 4096 px on a side.
- Recommended: **1920 x 1080 (16:9)**, the size the M4 mockups are drawn at (`docs/design/mockups/m4/`). The client scales it to cover the window, crops what does not fit, blurs it with the player's blur slider and dims it, so keep the subject near the centre and avoid small text. A picture that is not 16:9 (within 1%) or smaller than 1280 x 720 gets a warning.
- `maps` keys are map ids. A map with an entry shows that picture; every other map and the game itself show `image`. The loader rejects a key that is not a map id of the package (`main` when there is no `[[maps]]`).
- **Fallback** when there is no key art for the game or map: the background of the first ranked room. That room is the `[timing].start` room when the start trigger is `enter_room`, else `[engine].new_game_room`, else `start_room`. Its `background` image (`backgrounds/<id>.png`) is used if it has one, else its `background_color`, else the client's own default backdrop. `iwbtg_format::key_art::resolve` gives the client this choice.
- `iwbtg pkg check` checks each path (inside the package, not under `tests/`, ends in `.png`, present), decodes the image, and checks its size.

## Physics profile: `physics.toml`

The kid is one built-in. The profile is a preset (the engine family whose defaults fill every missing key) plus overrides, and its event lists name the actions the kid runs. The full page, with every section, action and collision run, is [physics.md](physics.md); the complete example of rely-the-needle-4-2 is [examples/rely-physics.toml](examples/rely-physics.toml). Minimal form:

```toml
#:schema ../../client/docs/format/schema/v0/physics.schema.json
preset = "A1"                # A1 | A2 | A3 | A4 | A5 | B | C: the defaults

[numbers]
run_speed = 3.0              # any key overrides the preset's value
jumps = [8.5, 7.0]           # ground jump, then each air jump

[sprites]
idle = "kid_idle"            # sprite names from the package
running = "kid_run"
```

An empty file is `preset = "A1"`. Unknown keys, actions, classes and values are load errors.

## Objects: `objects/<id>.toml`

Built-in kinds need no file. A package object file defines one of two things.

A **preset**: a built-in with fixed parameters. This is how near-duplicate original objects collapse into one (principle 9). The "hide spikes" triggers in Fed up become one preset:

```toml
#:schema ../../../client/docs/format/schema/v0/object.schema.json
# objects/hide_spikes.toml defines @hide_spikes
base = "trigger"
on = "kid_touch"             # kid_touch | shot | room_tick | flag
once = true
actions = [ { do = "hide", target = "group:{group}" } ]   # {group} comes from the instance
```

A **scripted object**: a script, with an optional built-in base for native behavior and roles.

```toml
#:schema ../../../client/docs/format/schema/v0/object.schema.json
# objects/boss1.toml defines @boss1
sprite = "boss1"
script = "boss1"             # scripts/boss1.rhai
solid = false
counts_as = ["bullet_blocker"]
collides_with = ["kid_bullet"]   # collide(other) runs only for these kinds
params = { hp = 20 }             # defaults; instances may override
timeline = "boss1_phases"        # optional; started at create
```

```toml
# objects/orb.toml defines @orb: a native projectile that kills on touch
base = "projectile"
sprite = "orb"
counts_as = ["killer"]
```

**OPEN:** whether presets may also override built-in parameters per instance beyond `params`.

Object keys: `base`, `script`, `sprite`, `mask` (an object-level collision mask sprite, GM object `mask`), `solid` (default false), `visible` (default true), `depth` (default 0), `persistent` (default false; true for the `kid` built-in, which is persistent in all 20 games, so a restart that creates the kid and changes room keeps it), `counts_as` (extra collision classes: named classes such as `block` or `killer`, or package class names; sim plan 1.1), `params`. Every other key is a param. The legacy converter key `roles` is read only by trace builds (`LoadMode::Trace`, CR11); write `counts_as` instead.

Object files (presets and scripted objects) may set `depth` (default 0) and `visible` (default true); instance keys of the same name override them. A preset may set `sprite`, which also gives it that sprite's collision mask instead of the built-in's default. Decided on the user's behalf, 2026-10-24 (research/converter/FORMAT_NOTES.md, OPEN 18 and 19).

## Rooms: `rooms/<room_id>.toml`

```toml
#:schema ../../../client/docs/format/schema/v0/room.schema.json
size = [800, 608]
file_speed = 50              # room_speed on entry (R14); default is game.toml tick_rate
role = "play"                # boot | title | menu | select | play; default play
no_restart = false           # true: R does nothing in this room (animus room52); default false
music = "stage1"             # optional; "keep" keeps the current track
background_color = "#000000"
backgrounds = [
  { image = "sky", speed = [1, 0] },
  { image = "fog", foreground = true, offset = [0, 512], tile = [true, false] },
]
persistent = false
views_enabled = true
views = [
  { visible = true, view = [0, 0, 800, 608], port = [0, 0, 800, 608], follow = "kid", border = [32, 32], speed = [-1, -1] },
]
on_create = [                # room creation code, as data (sim plan 4.2 step 6)
  { do = "set_global", var = "difficulty", value = 1 },
  { do = "spawn", kind = "@intro", x = 0, y = 0, params = { lines = 3 } },
]
instances = [
  { kind = "kid_start", x = 48, y = 552 },
  { kind = "block", x = 0, y = 576, run = [25, 1] },
  { kind = "spike", x = 320, y = 544, dir = "up" },
  { kind = "spike", x = 352, y = 544, dir = "up", group = "trap1" },
  { kind = "@hide_spikes", x = 288, y = 448, w = 32, h = 96, group = "trap1" },
  { kind = "water", x = 480, y = 384, variant = 2, run = [4, 6] },
  { kind = "vine", x = 640, y = 256, side = "left" },
  { kind = "save", x = 64, y = 512, name = "save_a" },
  { kind = "trigger", x = 600, y = 0, w = 32, h = 608, on = "kid_touch", emits = "stage1_clear" },
  { kind = "warp", x = 768, y = 512, to = { room = "stage1_04", at = "spawn_left" } },
  { kind = "@boss1", x = 400, y = 200, hp = 30 },
]
```

- **Order is creation order.** The list order is the GM creation order, which decides event and collision order within a kind. Tools never sort it.
- **Common instance keys:** `kind`, `x`, `y`, `name`, `group`, `xscale`, `yscale`, `angle`, `visible`, `depth`, `run`, `step`. Any other key is a parameter of the kind and is checked against its schema.
- **`run = [columns, rows]`** expands into a grid of identical instances in row-major order. Spacing is `step = [dx, dy]`, default `[32, 32]`. It expands into separate instances at load and is never merged into one rectangle.
- **Warps** point at `{ room, at = <instance name> }` or `{ room, x, y }`.
- **Room creation code** is `on_create`, a list of actions run in step 6 of the room start sequence: `set_global` (`var`, `value`; a global named `difficulty` also sets the engine difficulty that built-ins such as the bow read, like a ranked start's, so the loader requires a whole number from 0 to 255), `spawn` (`kind`, `x`, `y`, optional `params`) and `load_game`. `destroy_self` parses but is `Unsupported` until the spec says which instance is self (R24).
- **Instance creation code** is instance params: whatever the original's creation code set (`roomTo`, `depth`, `visible`) is written as keys on the instance.
- **Views:** `views_enabled` and up to 8 `views` (`visible`, `view = [x, y, w, h]`, `port` default the view's size at (0, 0), `follow` a kind, `border` default `[32, 32]`, `speed` default `[-1, -1]` for no limit). The built-in `camera` kind stays for games that move the view themselves (Fairy tale places 32 camera instances).
- **Backgrounds:** `background_color = "#rrggbb"` fills the room behind everything; without it the room clears to nothing of its own (GM "draw background color" off). `backgrounds` lists up to 8 layers in drawing order (GM's background slots 0 to 7, visible ones only): `image` (a `backgrounds/<id>` id), `foreground` (default false: drawn after every instance and tile instead of before them), `offset = [x, y]` (where the image's top-left corner sits in the room, default `[0, 0]`), `speed = [x, y]` (scroll in pixels per tick, default `[0, 0]`), `tile = [horizontal, vertical]` (repeat the image along that axis, default `[true, true]`) and `stretch` (scale the image to the room's size, default false; with `tile` the stretched image repeats). `background = "<id>"` is short for `backgrounds = [{ image = "<id>" }]`; a room sets one or the other. A missing image is a load error.
- **Roles** (`role`) mark boot, title, menu, select and play rooms. Restart and reset read them (`excluded_roles`). A room without `role` is a play room. `no_restart = true` turns R off in that one room (a play room where the original disables the key); F2 is not affected.

Decorative tiles go in `rooms/<room_id>.tiles.toml`:

```toml
#:schema ../../../client/docs/format/schema/v0/tiles.schema.json
layers = [
  { depth = 1000000, tileset = "stage1_tiles", tiles = [
    { x = 0, y = 576, src = [0, 0], run = [25, 1] },
    { x = 64, y = 64, src = [32, 0, 16, 16], run = [3, 1], step = [24, 0] },
  ] },
]
```

Tiles never affect the sim. A layer has a `depth` and a `tileset` (a `backgrounds/<id>` id; a missing image is a load error). A tile is the rectangle of the tileset image at `src`: `[x, y]` for a tile of the tileset's `tile_size`, or `[x, y, w, h]` for a tile of its own size (GM 8 stores a size per tile, and 1 in 60 converted tiles differs from its tileset's usual size). It is drawn at `x, y` (top-left) at its own size; `run = [columns, rows]` repeats it in a grid with spacing `step = [dx, dy]`, default the tile's size.

A tileset may have a sidecar `backgrounds/<id>.toml`:

```toml
#:schema ../../../client/docs/format/schema/v0/background.schema.json
tile_size = [32, 32]   # default [32, 32]: the size of a tile written as src = [x, y]
separation = [0, 0]    # default [0, 0]: pixels between tiles in the image
```

`separation` is for editors that cut the image into a tile palette; drawing never uses it, since every tile names its own source. GM 8 marks no background of the 20 games as a tileset, so the converter derives `tile_size` from the tiles that use the image (the most common size).

**How room art is drawn** (`iwbtg_format::art` reads it, `crates/client/src/art.rs` draws it; order from the GM8 CLONE_SPEC, Rooms). First `background_color`, then the layers that are not foregrounds in list order, then instances and tile layers by `depth` (a larger depth is farther back; tiles share the order with instances), then the foreground layers in list order. A layer's image starts at `offset` plus `speed` times the ticks since the room started, repeats along each tiled axis and is cut at the room's edge. OPEN: whether GM 8 moves a scrolling background before the room's first frame and keeps fractions (CLONE_SPEC, Rooms OPEN); the client draws the first frame at `offset` and keeps fractions. A game's code that changes `background_x` or `background_hspeed` at run time (animus) is not modelled.

## Timelines: `timelines/<id>.toml`

```toml
#:schema ../../../client/docs/format/schema/v0/timeline.schema.json
loop = false
moments = [
  { t = 0, call = "intro" },     # runs moment_intro() on the instance running the timeline
  { t = 150, call = "wave1" },
  { t = 312, call = "wave2" },
]
```

`t` counts ticks from the timeline's start. Moments must ascend strictly; `call` is a function name. `loop = true` sets `TimelineDef::looping`: a run started through `timeline::start_with_def` begins with `timeline_loop` set. The `call` names are kept in `TimelineDef::calls` for the script host. Avoidance patterns are synced to music by these tick counts, as in the originals.

## Paths: `paths/<id>.toml`

```toml
#:schema ../../../client/docs/format/schema/v0/path.schema.json
points = [[0, 0], [32, 0, 50], [32, 32]]   # [x, y] or [x, y, speed factor]; the factor defaults to 100
closed = false                             # the last point connects to the first
smooth = false                             # curved path: not supported by the sim yet (a warning)
precision = 4                              # smoothing precision
```

At least two points. The path id is the file stem; params name a path by index (the loader orders paths by file path).

## Sounds and music sidecars

```toml
#:schema ../../../client/docs/format/schema/v0/sound.schema.json
length_ticks = 9792   # song length in seconds times the tick rate
volume = 1
pan = 0
```

`sounds/<id>.ogg` is a normal sound; `music/<id>.ogg` is MULTIMEDIA (at most one copy plays). A sound id and a music id may not be the same. The optional sidecar `<folder>/<id>.toml` holds `length_ticks` (the song length in ticks, which `sound_isplaying` needs; converter request CR9), `volume` (default 1), `pan` (default 0) and `kind` (`normal` or `multimedia`, to override the folder). Without `length_ticks` the length is 0 and the load warns (CR9). Sound ids are numbered sounds first, then music, each in file path order.

**Files a game loads through a DLL** (SuperSound `SS_LoadSound`, GMFMODSimple `FMODSoundAdd`: kaenbyou, eat-the-lemon, go-the-spook-house, xia) get their length from the same sidecars. The DLLs never report a length, so when the script host calls an adapter's load function it passes `GameDef::dll_sound_length(file)`: the file name's stem (after the last `/` or `\`, without the extension, case ignored) names a `sounds/` or `music/` id, and that id's `length_ticks` is the length. A file that names no package sound gets 0, "unknown": a one-shot DLL sound then plays until stopped, which differs from the original for `SS_IsSoundPlaying` and for FMOD instance validity. So a converter puts every file a game loads by path into `sounds/` or `music/` (as Ogg) with a `length_ticks` sidecar, and the game's DLL calls name it by that stem (converter request CR9, which now covers DLL-loaded loose files too).

## Scripts: `scripts/<id>.rhai`

Scripts are Rhai under the IWS profile ([0001](../decisions/0001-script-language.md)). One file per scripted object (or shared by several objects of one game). Only `fn` and `const` items at top level. A `const` whose value is a literal (a number, a string, `true` or `false`, a number with a minus sign) is visible inside every function below it, as if the literal were written there; a const whose value is an expression works at the top level only, a const must be declared above the function that uses it, and its name cannot be reused for a variable or a parameter. The API is in [architecture](../architecture/sim.md#script-api-first-version); the generated reference will be `docs/format/script-api.md`.

```rhai
// scripts/boss1.rhai
const SHOT_EVERY = 25;

fn create() {
    this.hp = 20.0;
    this.set_alarm(0, 50);
}

fn alarm(n) {
    if n == 0 {
        for i in 0..12 {
            instance_create("@orb", this.x, this.y, #{ speed: 4.0, direction: i * 30.0 });
        }
        this.set_alarm(0, SHOT_EVERY);
    }
}

fn collide(other) {
    if other.kind == "kid_bullet" {
        this.hp -= 1.0;
        destroy(other);
        if gm_le(this.hp, 0.0) {
            emit("boss1_dead");
            destroy(this);
        }
    }
}
```

`draw(d)` is a valid event function (client only), but the draw builder `d` has no methods yet, so the example does not use it.

Limits: at most 256 KB per script file.

## Assets

- **Images:** PNG only, straight alpha, at most 4096 px on a side (a sprite wraps its frames into rows with `columns`).
- **Sprites:** `sprites/<id>.png` is a horizontal strip, or a grid of rows when the sidecar sets `columns`. Its sidecar:

  ```toml
  #:schema ../../../client/docs/format/schema/v0/sprite.schema.json
  frames = 4
  frame_size = [64, 64]
  columns = 4                # optional; frames per row of the image, default all frames in one row
  origin = [32, 32]
  collision = "precise"      # precise | rect | disk | diamond | none, as in GM8 sprite settings
  bbox = [0, 0, 63, 63]      # optional; computed from alpha if absent
  alpha_tolerance = 0
  separate_masks = false     # GM "separate collision masks": one mask per frame
  mask = "boss1_mask"        # optional separate mask sprite
  ```

  `columns` wraps the frames into a grid read row by row: frame `i` is at column `i % columns`, row `i / columns`, so the image is `columns * frame_width` by `ceil(frames / columns) * frame_height` px (the last row may be partly empty). It is at least 1 and at most `frames`. A sprite whose strip would pass 4096 px sets it (converter request CR15); both image sides stay at most 4096.

  `disk` and `diamond` are rasterized inside the box at load. `none` is GM's empty mask (an inverted box or a fully transparent sprite). `frames = 0` is a sprite without images: it needs no PNG and has an empty mask.

  Collision masks are built from PNG alpha at load, so masks never drift from the art.
- **Backgrounds and tilesets:** `backgrounds/<id>.png`, with a sidecar for tile size and separation when used as a tileset (see Rooms).
- **Audio:** Ogg Vorbis. Sound effects in `sounds/`, music in `music/`. Loop points and preview start in `music/<id>.toml`. FMOD and SuperSound calls in originals become plain sound and music ids. Audio never affects the sim.
- **Fonts:** bitmap PNG plus sidecar.
- **Package size:** at most 512 MB. At most 50,000 instances per room.
- Every file that is not the creator's own work or ours is listed in `[[third_party]]`.

## Validation

`iwbtg pkg check <dir>` runs these steps in order. The client and the server run the same checks on load and refuse a package that fails. Output is either OK or a list of readable errors with file, line and column.

1. Every data file parses, with no unknown keys.
2. Every reference resolves: rooms, kinds, sprites, sounds, music, timelines, scripts, trigger names, warp targets, engine pack assets.
3. Numbers are in range, and limits hold (image size, instances per room, script size).
4. Masks build from every sprite; frame counts match the image width.
5. Every script compiles under the IWS profile with strict variables. Event names and arities are valid. Every called function exists. String literals passed to the API resolve. Lints run: RNG draws or state changes in a right operand of `&&`/`||`, float `switch`, a real value as a condition (errors), and raw float `==`/`!=` (a warning). Details: [architecture](../architecture/sim.md#scripts).
6. `object_order` lists every kind used in the package.
7. The timing triggers of `[timing]` and of every map exist; `enter_room` rooms exist. `[stripped]` and every `stripped_start` resolve: rooms, kinds and instance names exist, and the ranked start room is not cut.
8. Manifest fields are present: creators, source URL, permission status, and a `[[third_party]]` entry for every file that needs one.

## Versioning

- `format` is an integer major version. Format 0 is this draft.
- From format 1 on, `crates/format` keeps a loader or an in-memory migrator for every older version (principle 7). `iwbtg pkg upgrade` rewrites files on disk with `toml_edit`.
- Because unknown keys are errors, an older client refuses a newer package with a clear message.
- `engine_rev` pins built-in behavior ([architecture](../architecture/replay.md#versions)).
- Two hashes, computed by `iwbtg pkg hash` and stored in the catalog, never inside the package:
  - `gameplay_hash`: BLAKE3 over the canonical parsed form of everything that can change the sim: `game.toml` gameplay fields, physics, objects, rooms, timelines, scripts, sprite sidecars, mask bits and `engine_rev`. Comments, formatting, art pixels outside masks, music, backgrounds, tiles, key art and credits are excluded. Leaderboards key on (package id, `gameplay_hash`), so cosmetic fixes keep the leaderboard.
  - `content_hash`: SHA-256 over all shipped file bytes (`tests/` excluded), for downloads (`/files/<sha256>` in [server](../server.md)). The input is the prefix `iwbtg-content-hash v0` and a zero byte, then for each file in path order the path and the bytes, each as an 8-byte little-endian length and the content. Text files (`.toml`, `.rhai`, `.md`, `.txt`, `.json`) have CRLF turned into LF first; PNG and Ogg are hashed as they are (`PackageFiles::content_hash`).
  - `iwbtg pkg hash <dir>` prints both (`gameplay_hash: <hex>`, `content_hash: <hex>`); a package with errors has no gameplay hash, so the errors are printed and the exit code is 1.
