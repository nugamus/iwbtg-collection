# Game package format v0 (draft)

Status: draft for roadmap Phase 3. Accepted by Claude on the user's behalf, 2026-10-24 (user may revisit).

This page defines the files in a game package. It follows the [format principles](README.md), the [script language decision](../decisions/0001-script-language.md) and the [data syntax decision](../decisions/0002-data-syntax.md). How the simulation runs a package is in [architecture](../architecture.md).

Version 0 is a draft. It may change without migrators until format 1, the first stable version. From format 1 on, every change follows [versioning](#versioning).

Items marked **OPEN** are not decided yet. Each names where the answer will come from.

## Package layout

One package is one folder in the games repo, `games/<game_id>/`. For download it is zipped and served by content hash.

```
games/rely_the_needle/
  game.toml                  manifest
  physics.toml               kid physics profile
  objects/<id>.toml          package objects: presets of built-ins and scripted objects
  scripts/<id>.rhai          scripts, only for behavior built-ins cannot express
  timelines/<id>.toml        tick-indexed moments (avoidance, boss phases)
  paths/<id>.toml            movement paths (`path_start`)
  rooms/<room_id>.toml       gameplay instances of one room
  rooms/<room_id>.tiles.toml optional decorative tiles of that room
  sprites/<id>.png           horizontal strip of frames
  sprites/<id>.toml          sprite sidecar: frames, origin, collision mask
  backgrounds/<id>.png       backgrounds and tilesets
  backgrounds/<id>.toml      optional sidecar for tilesets (tile size, separation)
  sounds/<id>.ogg            sound effects
  sounds/<id>.toml           optional sidecar: length_ticks, volume, pan
  music/<id>.ogg             music
  music/<id>.toml            optional sidecar: length_ticks, volume, pan (loop points and preview start are `[music]` in game.toml)
  fonts/<id>.png             bitmap fonts
  fonts/<id>.toml            font sidecar: glyph size, character map
  engine/<pack>/            bundled engine pack (engine.toml and the pack files used), see engine.md
  CREDITS.md                 human-readable credits (game.toml is the machine source)
  tests/                     not shipped, not hashed
    replays/full_clear.iwbr  a verified full clear
    inputs/<case>.inputs     trace and test inputs
    trace-map.toml           maps original rooms, objects, sprites and variables to ours
```

Shared engine assets (kid sprites, blood, default save and sounds of an engine family) live once in `games/_engines/<pack>/`, with their own `engine.toml` and credits. Packages reference them as `engine:<pack>/<id>`; the full page is [engine.md](engine.md). A built package carries the pack files it uses under `engine/<pack>/`. An engine pack can also provide a default `object_order` and default physics values. **Decided: bundled.** The package builder copies the pack assets a game uses into its package, so a built package is self-contained. Reasons: a download works offline and alone; the content hash covers every byte the game shows, so a later pack fix cannot change a game silently; the gameplay hash never depends on a pack version. The cost is the same kid sprites stored once per game, which is small next to music. The pack stays the single source in `games/_engines/`; only the built package carries copies.

## Ids and references

- Ids are lowercase snake_case ASCII: `[a-z][a-z0-9_]*`, at most 48 characters.
- An asset id is its file stem: `sprites/boss1.png` is the sprite `boss1`. Ids are unique within their namespace (rooms, objects, sprites, backgrounds, sounds, music, fonts, timelines, scripts).
- A field's type says what it points to. `sprite = "boss1"` always means a sprite. References carry no prefix, with two exceptions:
  - Package objects are written with `@`: `@boss1` is defined in `objects/boss1.toml`. Built-in kinds are bare (`spike`). A built-in name can never be shadowed.
  - Engine pack assets are written `engine:<pack>/<id>`.
- An instance that something points to gets `name = "..."`, unique within its room.
- Trigger names are global to the package.
- `group = "..."` tags instances for triggers and scripts.
- Original GM ids never appear in a package. `tests/trace-map.toml` holds the mapping.
- Every reference is resolved at load. An unknown id is an error with file, line and column.

## Common rules for data files

- TOML 1.1. Unknown keys are errors.
- The first line is a `#:schema` comment that points at the generated JSON Schema, for example `#:schema ../../client/docs/format/schema/v0/game.schema.json`. The schemas (`game`, `engine`, `object`, `room`, `tiles`, `sprite`, `timeline`, `path`, `sound`, `physics`) live in `docs/format/schema/v0/`. They are generated from the types in `crates/format` (and, for `physics`, `PhysicsProfileDraft` in `crates/sim` through its `schema` feature, which the format crate's `schema` feature turns on), never edited by hand: `UPDATE_SCHEMAS=1 cargo test -p iwbtg-format --test schemas` rewrites them, and the plain test fails when one is stale or an example in this page stops validating. They check the shape of a file (keys, types, ranges of the fixed keys); the loader still checks references and param values. Params of a built-in or a kind are open in the schema until the built-in param lists are generated too.
- Numbers are TOML integers or decimals. Any number may instead be written `{ bits = "3FDCCCCCCCCCCCCD" }` (16 hex digits of an IEEE double) when a trace shows it must match a GM8 constant bit for bit.
- `iwbtg pkg fmt <dir> [--check]` is the canonical formatter (`iwbtg_format::fmt::format_toml`). The level editor writes through the same rules. It keeps comments and the order of keys, tables and lists, and sets:
  - LF line ends, no byte order mark, one newline at the end of the file; `key = value` spacing; inline tables as `{ key = value }`; short arrays on one line as `[1, 2]` (an array already spread over several lines, or with a comment inside, is left as written).
  - Floats in their shortest form that reads back to the same bits; integers and strings as written.
  - Lists of rows (`instances`, `views`, `on_create`, tile `layers` and `tiles`, `moments`, `object_order`, `stages`) with one inline table per line, two spaces of indent, a trailing comma, so a one-instance edit is a one-line diff. In a row the keys the format names come first in a fixed order (an instance: `kind, x, y, name, group, xscale, yscale, angle, visible, depth, run, step`; then its params as written). It never reorders a list.
  - Running it twice changes nothing. `--check` writes nothing, lists the files that would change and exits 1 if there are any.

## Manifest: `game.toml`

```toml
#:schema ../../client/docs/format/schema/v0/game.schema.json
format = 0                       # format major version (integer)
id = "rely_the_needle"
title = "I Wanna Rely The Needle"
version = "1.0.0"                # version of our port (semver)
source_version = "4.2"           # version of the original we ported
engine_pack = "yuuutu"           # engine pack in games/_engines/, optional
engine_rev = 1                   # built-in behavior revision this package was verified against
runner = "gm80"                  # gm80 | gm81: original runner, selects event-order differences
physics = "physics.toml"
start_room = "title"
tick_rate = 50                   # default room speed; rooms may override
max_ticks = 1_080_000            # the server rejects longer replays (6 hours at 50)
object_order = [                 # event and collision order; every kind used must be listed
  "kid", "block", { kind = "spike", dir = "up" }, { kind = "spike", dir = "down" },
  "save", "warp", "platform", "trigger", "@boss1",
]
room_order = ["title", "room_1", "room_2"]   # optional; GM room order for room_goto_next/previous

[engine]                         # optional; engine settings
new_game_room = "room_1"         # where a new game starts; default start_room (with a warning)
boot = ["@world"]                # persistent kinds created before the first room; default the world kind
uninit_reads_zero = true         # GM "treat uninitialized variables as 0"; default true
float_model = "f64"              # runner number model; only f64 so far
roles = { kid_bullet = "@bullet", bow = "none" }   # which kind the sim spawns for an engine role

[engine.restart]                 # the retry key (R)
kind = "room_goto_saved"         # game_restart_via_boot | room_goto_saved | showdown_load | recreate_in_place
trigger = "step_pressed"         # key_press_event | step_held | step_pressed | step_pressed_unless_paused
excluded_roles = ["title", "menu"]
# death_on_restart = "nothing" | "save_counters" | "save_counters_per_kid"   # per kid: one death for each live kid, none with no kid (showdown)
kid_steps = { add_time = 2, save_death_time = true, clear_frozen = true }   # kid-side steps, all off by default: add_time (ticks added to the play timer first), save_death_time, clear_frozen (frozen and frozen2, globals and every kid), reset_jump_values (showdown; the new kid's jump values, speeds and jump flags), clear_triggers (showdown; the trigger arrays and `global.triggered` after the load)

[engine.reset]                   # the reset key (F2)
kind = "game_reset"              # delete_temp_and_restart | game_reset
trigger = "key_press_event"

[defaults.spike]                 # default sprite and mask of a bare built-in, per variant
sprite = "spike_up"
variants = [{ dir = "down", sprite = "spike_down" }]

[[creators]]
name = "<creator>"
role = "author"                  # author | co-author | music | art | tester | other

[source]
url = "https://delicious-fruit.com/game/19483"
permission = "community-assumed" # granted | community-assumed | pending | revoked
permission_date = 2026-10-24     # when the status was last set
permission_note = ""             # where the permission came from, or why it is pending

[budget]
ops_per_tick = 1_000_000         # script budget units per tick; hard cap 2_000_000

[timing]
start = { trigger = "run_start" }
end = { trigger = "run_end" }
stages = [
  { id = "stage1", name = "Stage 1", trigger = "stage1_clear" },
  { id = "boss", name = "Boss", trigger = "boss1_dead" },
]

[tricks]                         # ids from the research trick inventory
vine_check = "on"                # on | off | required

[[third_party]]
path = "music/stage1.ogg"
what = "Stage 1 music"
owner = "<rights holder>"
license = "unknown"              # SPDX id, or "unknown"
status = "to-clear"              # cleared | to-clear | excluded-from-public

[music.stage1]                   # optional per-track settings; may move to music/<id>.toml
volume = 1.0
```

| `id` | yes | Package id, snake_case. Stable forever; leaderboards key on it. |
| `title` | yes | Display title. |
| `version` | yes | Semver of our port. For humans. |
| `source_version` | no | Version of the original. |
| `engine_pack` | no | Engine pack id ([engine packs](engine.md)); the pack must be bundled. |
| `engine_rev` | yes | Built-in behavior revision ([architecture](../architecture.md#versions)). |
| `runner` | yes | `gm80` or `gm81`. **OPEN:** which differences it switches, from the CLONE_SPEC. |
| `physics` | yes | Path to the physics profile. |
| `start_room` | yes | First room. |
| `tick_rate` | no | Default room speed, 50 if absent. |
| `max_ticks` | yes | Upper bound for a replay. |
| `object_order` | yes | Rank order of every kind placed or spawnable. An entry is a kind name or a selector `{ kind = "spike", dir = "up" }` that matches instances by their params, so originals that collapsed into one kind keep their original order (R2). An instance takes the first matching selector of its kind, else the plain entry. The research converter emits it from the original's object order. |
| `room_order` | no | GM room order for `room_goto_next` and `room_goto_previous`. Rooms not listed follow in path order. |
| `[engine]` | no | `new_game_room`, `boot`, `uninit_reads_zero`, `float_model`, `roles` (engine role to kind: `world`, `kid`, `kid_flipped`, `kid_bullet`, `bow`, `blood`, `blood_emitter`, `game_over`, `playerface`; `"none"` when the game never spawns one), `[engine.restart]` and `[engine.reset]` (restart and reset models, sim plan 4.3). |
| `[defaults.<kind>]` | no | Default `sprite` and `mask` of a bare built-in kind, plus `variants` tables that match param values (`dir = "down"`) and give their own `sprite` or `mask`. |
| `[[creators]]` | yes, at least one | Name and role. |
| `[source].url` | yes | Original game page. |
| `[source].permission` | yes | `granted`, `community-assumed`, `pending` or `revoked`. A `revoked` package is never loaded, built or served. |
| `[source].permission_date`, `permission_note` | no | Audit trail. |
| `[budget].ops_per_tick` | no | Default 1,000,000, hard cap 2,000,000 ([0001](../decisions/0001-script-language.md#step-budget)). |
| `[timing]` | yes | `start` and `end` triggers, and `stages` in order. Each stage ends at its trigger. |
| `[tricks]` | no | Switches for tricks that are engine behaviors. **OPEN:** trick ids, from the research trick inventory. A trick key is the id of `research/specs/tricks.md` without its `trick.`, `input.` or `bug.` prefix (`restart_glitch`, `ad_align`). A trick marked `required` needs its switch on in the physics profile (the loader checks `dual_shift`, `restart_glitch`; the switches of `ad_align`, `disable_cancels`, `sub_frame_tap` are not in the profile yet, and `vdiet`, `coyote_time`, `jump_buffer`, `numpad_cancel`, `cactus_phantom_release` are never on). |
| `[[third_party]]` | yes, one per file that is not the creator's own work or ours | `path`, `what`, `owner`, `license`, `status`. Commercial music, Kayin's sprites and engine assets all go here. |

### Timing triggers

The triggers form one chain, evaluated at the end of every tick: `start`, then each stage in order, then `end`.

- Vocabulary: `run_start` (true at once: the run starts on its first tick), `run_end` (true in the tick `game_clear` ends the run) and `enter_room` with `room = "<id>"` (true while the kid's world is in that room).
- Each trigger fires at most once. Nothing fires before `start`. A stage is looked at only after the stage before it fired, so stages never fire out of order. Several triggers can fire in one tick. `end` can fire with stages still unreached. After `end` nothing fires.
- A split is its chain index (0 start, then the stages, then the end) and the tick it fired at. The tick is the number of ticks run so far, so `run_start` is tick 1 and a run's time is `end - start` in ticks.
- `iwbtg replay run` prints the splits as `<index>@<tick>`.

## Physics profile: `physics.toml`

The kid is one built-in. The profile is a preset (the engine family whose defaults fill every missing key) plus overrides, and its event lists name the actions the kid runs. The full page, with every section, action and collision run, is [physics.md](physics.md); the complete example of rely-the-needle-4-2 is [examples/rely-physics.toml](examples/rely-physics.toml). Minimal form:

```toml
#:schema ../../client/docs/format/schema/v0/physics.schema.json
preset = "A1"                # A1 | A2 | A3 | A4 | A5 | B | C: the defaults

[numbers]
run_speed = 3.0              # any key overrides the preset's value
jumps = [8.5, 7.0]           # ground jump, then each air jump

[sprites]
idle = "kid_idle"            # sprite names from the package
running = "kid_run"
```

An empty file is `preset = "A1"`. Unknown keys, actions, classes and values are load errors.

## Objects: `objects/<id>.toml`

Built-in kinds need no file. A package object file defines one of two things.

A **preset**: a built-in with fixed parameters. This is how near-duplicate original objects collapse into one (principle 9). The "hide spikes" triggers in Fed up become one preset:

```toml
#:schema ../../../client/docs/format/schema/v0/object.schema.json
# objects/hide_spikes.toml defines @hide_spikes
base = "trigger"
on = "kid_touch"             # kid_touch | shot | room_tick | flag
once = true
actions = [ { do = "hide", target = "group:{group}" } ]   # {group} comes from the instance
```

A **scripted object**: a script, with an optional built-in base for native behavior and roles.

```toml
#:schema ../../../client/docs/format/schema/v0/object.schema.json
# objects/boss1.toml defines @boss1
sprite = "boss1"
script = "boss1"             # scripts/boss1.rhai
solid = false
counts_as = ["bullet_blocker"]
collides_with = ["kid_bullet"]   # collide(other) runs only for these kinds
params = { hp = 20 }             # defaults; instances may override
timeline = "boss1_phases"        # optional; started at create
```

```toml
# objects/orb.toml defines @orb: a native projectile that kills on touch
base = "projectile"
sprite = "orb"
counts_as = ["killer"]
```

**OPEN:** whether presets may also override built-in parameters per instance beyond `params`.

Object keys: `base`, `script`, `sprite`, `mask` (an object-level collision mask sprite, GM object `mask`), `solid` (default false), `visible` (default true), `depth` (default 0), `persistent` (default false), `counts_as` (extra collision classes: named classes such as `block` or `killer`, or package class names; sim plan 1.1), `params`. Every other key is a param. The legacy converter key `roles` is read only by trace builds (`LoadMode::Trace`, CR11); write `counts_as` instead.

Object files (presets and scripted objects) may set `depth` (default 0) and `visible` (default true); instance keys of the same name override them. A preset may set `sprite`, which also gives it that sprite's collision mask instead of the built-in's default. Decided on the user's behalf, 2026-10-24 (research/converter/FORMAT_NOTES.md, OPEN 18 and 19).

## Rooms: `rooms/<room_id>.toml`

```toml
#:schema ../../../client/docs/format/schema/v0/room.schema.json
size = [800, 608]
file_speed = 50              # room_speed on entry (R14); default is game.toml tick_rate
role = "play"                # boot | title | menu | select | play; default play
music = "stage1"             # optional; "keep" keeps the current track
background = "sky"
background_color = "#000000"
persistent = false
views_enabled = true
views = [
  { visible = true, view = [0, 0, 800, 608], port = [0, 0, 800, 608], follow = "kid", border = [32, 32], speed = [-1, -1] },
]
on_create = [                # room creation code, as data (sim plan 4.2 step 6)
  { do = "set_global", var = "difficulty", value = 1 },
  { do = "spawn", kind = "@intro", x = 0, y = 0, params = { lines = 3 } },
]
instances = [
  { kind = "kid_start", x = 48, y = 552 },
  { kind = "block", x = 0, y = 576, run = [25, 1] },
  { kind = "spike", x = 320, y = 544, dir = "up" },
  { kind = "spike", x = 352, y = 544, dir = "up", group = "trap1" },
  { kind = "@hide_spikes", x = 288, y = 448, w = 32, h = 96, group = "trap1" },
  { kind = "water", x = 480, y = 384, variant = 2, run = [4, 6] },
  { kind = "vine", x = 640, y = 256, side = "left" },
  { kind = "save", x = 64, y = 512, name = "save_a" },
  { kind = "trigger", x = 600, y = 0, w = 32, h = 608, on = "kid_touch", emits = "stage1_clear" },
  { kind = "warp", x = 768, y = 512, to = { room = "stage1_04", at = "spawn_left" } },
  { kind = "@boss1", x = 400, y = 200, hp = 30 },
]
```

- **Order is creation order.** The list order is the GM creation order, which decides event and collision order within a kind. Tools never sort it.
- **Common instance keys:** `kind`, `x`, `y`, `name`, `group`, `xscale`, `yscale`, `angle`, `visible`, `depth`, `run`, `step`. Any other key is a parameter of the kind and is checked against its schema.
- **`run = [columns, rows]`** expands into a grid of identical instances in row-major order. Spacing is `step = [dx, dy]`, default `[32, 32]`. It expands into separate instances at load and is never merged into one rectangle.
- **Warps** point at `{ room, at = <instance name> }` or `{ room, x, y }`.
- **Room creation code** is `on_create`, a list of actions run in step 6 of the room start sequence: `set_global` (`var`, `value`), `spawn` (`kind`, `x`, `y`, optional `params`) and `load_game`. `destroy_self` parses but is `Unsupported` until the spec says which instance is self (R24).
- **Instance creation code** is instance params: whatever the original's creation code set (`roomTo`, `depth`, `visible`) is written as keys on the instance.
- **Views:** `views_enabled` and up to 8 `views` (`visible`, `view = [x, y, w, h]`, `port` default the view's size at (0, 0), `follow` a kind, `border` default `[32, 32]`, `speed` default `[-1, -1]` for no limit). The built-in `camera` kind stays for games that move the view themselves (Fairy tale places 32 camera instances).
- **Roles** (`role`) mark boot, title, menu, select and play rooms. Restart and reset read them (`excluded_roles`). A room without `role` is a play room.

Decorative tiles go in `rooms/<room_id>.tiles.toml`:

```toml
#:schema ../../../client/docs/format/schema/v0/tiles.schema.json
layers = [
  { depth = 1000000, tileset = "stage1_tiles", tiles = [
    { x = 0, y = 576, src = [0, 0], run = [25, 1] },
  ] },
]
```

Tiles never affect the sim.

## Timelines: `timelines/<id>.toml`

```toml
#:schema ../../../client/docs/format/schema/v0/timeline.schema.json
loop = false
moments = [
  { t = 0, call = "intro" },     # runs moment_intro() on the instance running the timeline
  { t = 150, call = "wave1" },
  { t = 312, call = "wave2" },
]
```

`t` counts ticks from the timeline's start. Moments must ascend strictly; `call` is a function name. `loop = true` sets `TimelineDef::looping`: a run started through `timeline::start_with_def` begins with `timeline_loop` set. The `call` names are kept in `TimelineDef::calls` for the script host. Avoidance patterns are synced to music by these tick counts, as in the originals.

## Paths: `paths/<id>.toml`

```toml
#:schema ../../../client/docs/format/schema/v0/path.schema.json
points = [[0, 0], [32, 0, 50], [32, 32]]   # [x, y] or [x, y, speed factor]; the factor defaults to 100
closed = false                             # the last point connects to the first
smooth = false                             # curved path: not supported by the sim yet (a warning)
precision = 4                              # smoothing precision
```

At least two points. The path id is the file stem; params name a path by index (the loader orders paths by file path).

## Sounds and music sidecars

```toml
#:schema ../../../client/docs/format/schema/v0/sound.schema.json
length_ticks = 9792   # song length in seconds times the tick rate
volume = 1
pan = 0
```

`sounds/<id>.ogg` is a normal sound; `music/<id>.ogg` is MULTIMEDIA (at most one copy plays). A sound id and a music id may not be the same. The optional sidecar `<folder>/<id>.toml` holds `length_ticks` (the song length in ticks, which `sound_isplaying` needs; converter request CR9), `volume` (default 1), `pan` (default 0) and `kind` (`normal` or `multimedia`, to override the folder). Without `length_ticks` the length is 0 and the load warns (CR9). Sound ids are numbered sounds first, then music, each in file path order.

**Files a game loads through a DLL** (SuperSound `SS_LoadSound`, GMFMODSimple `FMODSoundAdd`: kaenbyou, eat-the-lemon, go-the-spook-house, xia) get their length from the same sidecars. The DLLs never report a length, so when the script host calls an adapter's load function it passes `GameDef::dll_sound_length(file)`: the file name's stem (after the last `/` or `\`, without the extension, case ignored) names a `sounds/` or `music/` id, and that id's `length_ticks` is the length. A file that names no package sound gets 0, "unknown": a one-shot DLL sound then plays until stopped, which differs from the original for `SS_IsSoundPlaying` and for FMOD instance validity. So a converter puts every file a game loads by path into `sounds/` or `music/` (as Ogg) with a `length_ticks` sidecar, and the game's DLL calls name it by that stem (converter request CR9, which now covers DLL-loaded loose files too).

## Scripts: `scripts/<id>.rhai`

Scripts are Rhai under the IWS profile ([0001](../decisions/0001-script-language.md)). One file per scripted object (or shared by several objects of one game). Only `fn` and `const` items at top level. The API is in [architecture](../architecture.md#script-api-first-version); the generated reference will be `docs/format/script-api.md`.

```rhai
// scripts/boss1.rhai
const SHOT_EVERY = 25;

fn create() {
    this.hp = this.param("hp");
    set_alarm(0, 50);
}

fn alarm(n) {
    if n == 0 {
        for i in 0..12 {
            spawn("@orb", this.x, this.y, #{ speed: 4.0, direction: i * 30.0 });
        }
        set_alarm(0, SHOT_EVERY);
    }
}

fn collide(other) {
    if other.kind == "kid_bullet" {
        this.hp -= 1.0;
        destroy(other);
        if gm_le(this.hp, 0.0) {
            emit("boss1_dead");
            destroy(this);
        }
    }
}

fn draw(d) {
    d.bar(16.0, 16.0, 200.0, 8.0, this.hp / this.param("hp"));
}
```

Limits: at most 256 KB per script file.

## Assets

- **Images:** PNG only, straight alpha, at most 4096 px on a side.
- **Sprites:** `sprites/<id>.png` is a horizontal strip. Its sidecar:

  ```toml
  #:schema ../../../client/docs/format/schema/v0/sprite.schema.json
  frames = 4
  frame_size = [64, 64]
  origin = [32, 32]
  collision = "precise"      # precise | rect | disk | diamond | none, as in GM8 sprite settings
  bbox = [0, 0, 63, 63]      # optional; computed from alpha if absent
  alpha_tolerance = 0
  separate_masks = false     # GM "separate collision masks": one mask per frame
  mask = "boss1_mask"        # optional separate mask sprite
  ```

  `disk` and `diamond` are rasterized inside the box at load. `none` is GM's empty mask (an inverted box or a fully transparent sprite). `frames = 0` is a sprite without images: it needs no PNG and has an empty mask.

  Collision masks are built from PNG alpha at load, so masks never drift from the art.
- **Backgrounds and tilesets:** `backgrounds/<id>.png`, with a sidecar for tile size and separation when used as a tileset.
- **Audio:** Ogg Vorbis. Sound effects in `sounds/`, music in `music/`. Loop points and preview start in `music/<id>.toml`. FMOD and SuperSound calls in originals become plain sound and music ids. Audio never affects the sim.
- **Fonts:** bitmap PNG plus sidecar.
- **Package size:** at most 512 MB. At most 50,000 instances per room.
- Every file that is not the creator's own work or ours is listed in `[[third_party]]`.

## Validation

`iwbtg pkg check <dir>` runs these steps in order. The client and the server run the same checks on load and refuse a package that fails. Output is either OK or a list of readable errors with file, line and column.

1. Every data file parses, with no unknown keys.
2. Every reference resolves: rooms, kinds, sprites, sounds, music, timelines, scripts, trigger names, warp targets, engine pack assets.
3. Numbers are in range, and limits hold (image size, instances per room, script size).
4. Masks build from every sprite; frame counts match the image width.
5. Every script compiles under the IWS profile with strict variables. Event names and arities are valid. Every called function exists. String literals passed to the API resolve. Lints run: RNG draws or state changes in a right operand of `&&`/`||`, float `switch`, a real value as a condition (errors), and raw float `==`/`!=` (a warning). Details: [architecture](../architecture.md#scripts).
6. `object_order` lists every kind used in the package.
7. The timing triggers exist and can be reached from `start_room`.
8. Manifest fields are present: creators, source URL, permission status, and a `[[third_party]]` entry for every file that needs one.

## Versioning

- `format` is an integer major version. Format 0 is this draft.
- From format 1 on, `crates/format` keeps a loader or an in-memory migrator for every older version (principle 7). `iwbtg pkg upgrade` rewrites files on disk with `toml_edit`.
- Because unknown keys are errors, an older client refuses a newer package with a clear message.
- `engine_rev` pins built-in behavior ([architecture](../architecture.md#versions)).
- Two hashes, computed by `iwbtg pkg hash` and stored in the catalog, never inside the package:
  - `gameplay_hash`: BLAKE3 over the canonical parsed form of everything that can change the sim: `game.toml` gameplay fields, physics, objects, rooms, timelines, scripts, sprite sidecars, mask bits and `engine_rev`. Comments, formatting, art pixels outside masks, music, backgrounds, tiles and credits are excluded. Leaderboards key on (package id, `gameplay_hash`), so cosmetic fixes keep the leaderboard.
  - `content_hash`: SHA-256 over all shipped file bytes (`tests/` excluded), for downloads (`/files/<sha256>` in [server](../server.md)). The input is the prefix `iwbtg-content-hash v0` and a zero byte, then for each file in path order the path and the bytes, each as an 8-byte little-endian length and the content. Text files (`.toml`, `.rhai`, `.md`, `.txt`, `.json`) have CRLF turned into LF first; PNG and Ogg are hashed as they are (`PackageFiles::content_hash`).
  - `iwbtg pkg hash <dir>` prints both (`gameplay_hash: <hex>`, `content_hash: <hex>`); a package with errors has no gameplay hash, so the errors are printed and the exit code is 1.
