# `blood_emitter`

Made by the kid's death. **Alarm plus Step**: Create sets alarm 0 to `life`, Alarm 0 destroys it (or, with `outlives_stream`, only ends its stream), each Step makes the blood. The Step count follows from the tick order: made in a collision event its first Step is the next tick and it gets 19 Steps; made in a Key press event it also Steps on the creation tick and gets 20 (Confirmed (recorder), rely `num-rng-a.csv`, `t6-input-key-event-order-b.csv`). Source: `crates/sim/src/builtins/blood_emitter.rs`.

| Param | Type | Default | Meaning |
|---|---|---|---|
| `mode` | `random_dir`, `angle_sweep`, `particles` | `random_dir` | How it makes blood (below). |
| `life` | real | 20 | Alarm 0 at Create (A3: 10). A negative whole value (GameMaker's -1) sets no alarm: the instance and its stream never end by themselves. Allowed, but not what family B does (use `outlives_stream`). |
| `per_step` | whole | 40 (15 in `particles`) | Drops per Step; in `particles`, the stream per tick (1 or more). |
| `speed_max` | real | 6 | Speed is `random(speed_max)`. OPEN: the original also has a `random(8)` branch the spec does not name. |
| `chance` | real | 0.2 | `angle_sweep`: chance per angle. |
| `per_angle` | whole | 8 | `angle_sweep`: drops per chosen angle (A3 uses 10). |
| `flipped` | bool | false | The kid was flipped; passed to the blood. |
| `destroyed_by_restart` | bool | false | A Restart key press destroys it (kaenbyou, eat-the-lemon). |
| `outlives_stream` | bool | false | `particles` only (refused in the other modes): Alarm 0 ends the stream, not the instance (family B, below). |

- `random_dir`: per drop, the blood's Create (frame, gravity), then the emitter draws the direction `irandom(35) * 10` and the speed. Rely: 160 draws a Step.
- `angle_sweep` (A2, A3): for each angle 0, 10, ..., 360, with `chance` (one draw), `per_angle` drops with speed `random(speed_max)`. OPEN: the draw order is not in the spec.
- `particles` (family B): the client draws the particles (`BuiltinOutput::DeathParticles` each Step); the Step draws nothing. With `NumRules::particles_draw_rng` (N10, on in engine_rev 0) Create also builds the emitter's particle system in the sim (#766), as the original's Create does (kid/B.md Death): one type with size, speed (1 to 5) and direction (0 to 360) ranges and life 50 (4 draws), one emitter on a linear rectangle (2 draws) streaming `per_step`. Each tick's particle update then draws `per_step` x 6 (90), from the creation tick until alarm 0 (CLONE_SPEC numbers "Particle draw rules"; Confirmed (recorder): kaenbyou `num-part-rng-3-k1.csv` frames 45-50 replay bit for bit, test `particles_rng::blood_emitter::k1_seed_column_replays_bit_for_bit`). The original removes the emitter at alarm 0 and destroys the system on Restart and Room End; here alarm 0 destroys the instance and its Destroy destroys the system, which draws the same (the type has no step or death particles, so the particles left over draw nothing). Room End destroys the system too. A death in a collision or Key press event streams in 20 updates (the alarm phase comes first). `per_step` 0 is refused in this mode (a stream of 0 is not traced).
- `outlives_stream` (family B: kaenbyou, eat-the-lemon): the original's Alarm 0 only destroys the particle emitter (`part_emitter_destroy`); the instance lives until Restart, Escape, F2 or room end (kid/B.md Death step 2; trace famb-death-timing-b: `instance_number(bloodEmitter)` is 1 from frame 12 to 80). With this param Alarm 0 destroys the emitter in the sim's system, so the stream and its 90 draws a tick stop after the same updates as without it; the system and its live particles stay (they age out with no draws) until a Restart press (`destroyed_by_restart`), Room End or Destroy destroys the system. The Step stops sending `DeathParticles`. The ended stream is kept as `per_step` 0 in the state (refused at load in this mode, so 0 only means ended). It is read from the instance's own params, so a placed or spawned instance can set it. Tests: `particles_rng::blood_emitter::outlives_stream_*`, `k1_replays_with_outlives_stream` (k1's seed and emitter count columns to frame 90), `k2_replays_with_outlives_stream` (kaenbyou `num-part-rng-3-k2.csv`, no R press, Confirmed (recorder): the seed matches on every frame to 120 with 19 drawing updates, frames 45-63, then constant; `instance_number(bloodEmitter)` stays 1, emitters go to 0 on frame 64 and the system stays; research#214, #907), `a_placed_instance_param_outlives_its_stream`.
