# Versioning

Part of [format v0](v0.md).

- `format` is an integer major version. Format 0 is the v0 draft; format 1 ([v1](v1.md)) is the current format (`FORMAT_VERSION`), whose schemas are in `schema/v1/` (`schema/v0/` is the frozen format-0 copy).
- `crates/format` loads every older format directly into the same `GameDef` (principle 7); a format-0 package loads unchanged. `iwbtg pkg upgrade` rewrites a package folder to the current format with `toml_edit`, one step per format in `crates/format/src/migrate.rs`, and writes nothing unless the result loads into an equal `GameDef` ([v1](v1.md#upgrading-a-format-0-package)). The freeze criteria and the migration rule are in [versioning](../architecture/versioning.md#format-1-freeze); the freeze guard is #1395.
- Because unknown keys are errors, an older client refuses a newer package with a clear message.
- The built-in revision pins built-in behavior ([architecture](../architecture/replay.md#versions)): `engine_rev` in format 0, the `<rev>` of `ruleset = "gm8@<rev>"` in format 1.
- `ruleset` and `[compat]` (decision 0005) are declarations in format 0. Their values must resolve to what the package already does (the profile to the physics preset's family, a deviation to the physics value), so they are removed before `gameplay_hash` is computed and writing them keeps the hash of the package without them. **The normalization is format-0 and resolution-equality only:** a ruleset or `[compat]` profile that changes behavior must enter `gameplay_hash` (user decision 2). Format 0 rejects such a declaration before hashing. Format 1 requires both and hashes them as written, so an upgraded package's hash differs from its format-0 hash until #928 makes the hash stable across migrations.
- Two hashes, computed by `iwbtg pkg hash` and stored in the catalog, never inside the package:
  - `gameplay_hash`: BLAKE3 over the canonical parsed form of everything that can change the sim: `game.toml` gameplay fields, physics (`physics.toml` and `physics/`), objects, rooms, timelines, scripts, sprite sidecars, mask bits and `engine_rev`. Comments, formatting, art pixels outside masks, music, backgrounds, tiles, key art, `[controls]` labels and credits are excluded. Leaderboards key on (package id, `gameplay_hash`), so cosmetic fixes keep the leaderboard.
  - `content_hash`: SHA-256 over all shipped file bytes (`tests/` excluded), for downloads (`/files/<sha256>` in [server](../server.md)). The input is the prefix `iwbtg-content-hash v0` and a zero byte, then for each file in path order the path and the bytes, each as an 8-byte little-endian length and the content. Text files (`.toml`, `.rhai`, `.md`, `.txt`, `.json`) have CRLF turned into LF first; PNG and Ogg are hashed as they are (`PackageFiles::content_hash`).
  - `iwbtg pkg hash <dir>` prints both (`gameplay_hash: <hex>`, `content_hash: <hex>`); a package with errors has no gameplay hash, so the errors are printed and the exit code is 1.
