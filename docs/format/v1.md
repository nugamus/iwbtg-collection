# Game package format 1

Status: current format (`FORMAT_VERSION = 1`, #795). Format 1 is the [format 0 draft](v0.md) with one change to `game.toml`: the package names its ruleset and its compatibility profile instead of `engine_rev`. The shape is decision 3 of [0005](../decisions/0005-standard-mechanics.md#decision-log), accepted by the user on 2026-11-21. Every other file, key and rule is the format-0 one, so the v0 pages ([manifest](game.md), [rooms](rooms.md), [physics](physics.md) and the rest) describe format 1 too. Schemas: `docs/format/schema/v1/`; `docs/format/schema/v0/` is the frozen format-0 copy.

## What changes from format 0

| `game.toml` | Format 0 | Format 1 |
|---|---|---|
| `format` | `0` | `1` |
| `engine_rev` | required: the built-in revision | refused: the revision is in `ruleset` |
| `ruleset` | optional; absent = `gm8@<engine_rev>`, written = must equal it | required: `"gm8@<rev>"` |
| `[compat] profile` | optional; absent = the physics preset's family bundle | required: `"gm8/<family>@1"` |
| `[[compat.deviation]]` | optional | optional, unchanged |
| `gameplay_hash` | `ruleset` and `[compat]` removed before hashing | `ruleset` and `[compat]` hashed as written |

```toml
format = 1
id = "keep_celebrating_for_xia"
title = "I wanna Keep Celebrating for Xia"
version = "0.1.0"
ruleset = "gm8@0"                # was engine_rev = 0
runner = "gm81"
physics = "physics.toml"
# ... every other key as in format 0 ...

[compat]
profile = "gm8/c@1"              # the physics preset's family bundle
```

`gm8` is the only ruleset this build implements; `standard` comes with the sim work of 0005 (#1149 and the other workstreams). In both formats a declared profile must be the physics preset's family and a deviation must name the value the package already resolves to, until the profile layer can apply a value (#1160). Those are loader rules, not schema: relaxing them changes no file.

## Loading format 0

The loader reads format 0 and format 1 directly into the same `GameDef` (principle 7, [versioning](versioning.md)); there is no on-load rewrite. A format-0 package loads unchanged and keeps its `gameplay_hash`. The client refuses a format above 1 with "update the client".

## Upgrading a format-0 package

`iwbtg pkg upgrade <dir> [--check] [--trace-mode]` ([cli](../architecture/cli.md)) rewrites a package folder in place:

1. The package must load (strictly, or with `--trace-mode` for converter output); otherwise it prints the errors and changes nothing.
2. `game.toml`: `format = 1`; `engine_rev` becomes `ruleset = "gm8@<rev>"` in the same place, with its comments; `[compat] profile` is added with the resolved bundle. A `ruleset`, profile or deviation the package already wrote is kept. The values come from what the loader resolved, so the upgrade writes down what the package already plays under and never chooses a behavior.
3. Every `.toml` file outside the bundled `engine/` folder: the `#:schema` line points at `schema/v1/`.
4. The rewritten package is loaded again; it must give an equal `GameDef`, or nothing is written.

It prints the changed files, `format 0 -> 1` and the `gameplay_hash` before and after; `--check` writes nothing and exits 1 when the package is not current. Running it on a current package prints `already current, no changes`. Editing is done with `toml_edit` (`crates/format/src/migrate.rs`, one step function per format), so comments, key order and layout stay; `pkg fmt` is not run.

**The gameplay hash moves on upgrade** until #928: format 1 hashes `format = 1`, `ruleset` and `[compat]`, which format 0 does not. Nothing plays differently. Until #928 lands, do not upgrade a package whose board or replays matter; the interim server rule is in [versioning](../architecture/versioning.md#format-1-freeze). The in-repo packages (`showcase.pkg`, the golden and test packages) and the research converter stay on format 0 for now.

## What format 1 does not contain

The [Format changes needed](../content.md#format-changes-needed) list is closed for format 1. Done in format 0 and carried: maps, stripped mode, physics per room, `[controls]`, the `.iwbz` container. Deferred, each with its reason:

| Item | Issue | Why it does not block format 1 |
|---|---|---|
| Language packs | #45 | Translatable text is new optional files and keys; no format-1 package needs editing for them and they are outside `gameplay_hash` (text is not gameplay). The extraction pipeline that decides their shape is phase 9 work. |
| Creator locks (asset reuse, skins) | #796 | Optional cosmetic flags read by the asset library and the skin system, neither of which exists yet (skins are **OPEN** in [content](../content.md#assets)). |
| Script library references (`lib:<name>@<version>`) | #797 | Needs the shared script library and its versioning rule (0004); a new reference form is additive. |
| `standard` new-game shape (no `runner`, `object_order`, `room_order`) | #1149, #1153 | Needs the `standard` ruleset in the sim (engine-owned lifecycle, stable room identity). Until then every package is `gm8` and keeps these keys. |
| `[tricks]` removal | #1160 | User decision (#1160); format 1 keeps `[tricks]` as the compatibility table it is. |

Each deferred item is additive: an optional key, table or folder. Before the format freeze point it may join format 1 with no package edit and no hash move; after it, it is format 2 with an identity migration step.

## The freeze point

`FORMAT_VERSION = 1` makes format 1 the format the tools write; it does not yet forbid schema changes. The freeze, after which every schema change bumps `format` and gets a migration step, follows the default in [versioning](../architecture/versioning.md#format-1-freeze): no later than the `SIM_VERSION` freeze point, the first public nightly of phase 7. Enacting it (a guard that fails when a frozen format's schema changes) is #1395.
